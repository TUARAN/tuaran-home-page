本记录保存 2026-09-08 的代码与线上抽样观察，不代表全站实时状态。路线图是建议执行顺序，不代表所有设计、平台设置或发布动作已获实施授权，也不承诺收录时间或流量增幅。

### 线上爬虫规则的解释

线上 robots.txt 在仓库规则之外包含 Cloudflare Managed Content，观测到 `search=yes,ai-train=no,use=reference`，以及 GPTBot、ClaudeBot、Google-Extended 等具体 agent 的禁止规则。未看到针对 OAI-SearchBot 的专门禁止项。

这不等于“禁止所有 AI 搜索”。OpenAI 的搜索爬虫与训练爬虫分开控制；robots 放行也不能证明 WAF 放行。后续应按目标平台的官方 agent 和 IP 验证规则检查真实请求，不以伪造 User-Agent 的成功请求作为充分证据，不为追求收录直接关闭全站防护。

## 4. 改造原则

1. 优先保证公开正文、链接、日期和结构化数据可直接读取。
2. 沿用统一内容标识与注册表；数据库与构建期内容去重，不另造平行内容系统。
3. 真实实质更新才修改日期，不以每日刷新日期制造新鲜度。
4. 重点主题页提供整理与阅读顺序，参数筛选页维持合理去重；不批量制造薄页面。
5. 主题推荐、资源动作与订阅围绕读者当前问题展开。
6. 搜索发现、AI 引用、真人访问、有效阅读和回访分别衡量。
7. llms.txt、特殊标记和关键词堆积不能替代原创价值与可抓取性。

## 5. 建议内容与板块方向

以下为待验证的编辑方向，不是新增分类契约。优先使用现有 subjects、series 和内容管线，是否新增主题按既有供给门槛判断。

| 主线 | 读者任务 | 内容资产 |
|---|---|---|
| AI 编程与 Agent 实践 | 安装、配置、排错、完成实际任务 | Codex / WorkBuddy、记忆、Skills、MCP、工程案例 |
| 前端与部署工程 | 做出可运行、可维护的项目 | Next.js、Cloudflare、发布、性能、故障复盘 |
| 技术创作者工作流 | 整理、发布和复用内容 | 写作工具、浏览器扩展、分发实践与效果记录 |

其他内容可继续保留，首页主要推荐位置先验证上述主线的效果。首个试点建议选择 Codex / Agent，整理已有 8–12 篇内容；具体清单在实施前按质量与相关性筛选。

### 内容资产

- 实践文章补充环境、版本、前提、验证步骤、结果与失败条件。
- 工具比较尽量使用同一任务和明确评价标准，区分实测与文档整理。
- 原始记录、可下载脚本、模板、检查表和持续更新的兼容性记录，提供访问与收藏理由。
- 长文可按“简短结论 → 适用条件 → 操作或比较 → 证据与限制”组织，不强制固定字数或 FAQ。
- 保留来源与核验日期，明确作者判断、产品事实与未验证事项。

### 页面组织

首页试验顺序：清晰定位 → 三条主题入口 → 精选入门 → 最近实质更新 → 工具与模板 → 订阅。最终布局需结合移动端检查和实际入口数据确定。

主题页包含：适用读者、入门顺序、常见任务、排错入口、可复用资源与最近更新；拥有独立标题、canonical、可读正文和可抓取内链。

文章末尾优先呈现：解决下一步问题的一篇内容、当前主题的实用资源、主题更新订阅。复用现有组件，避免把全部动作并列堆满页面。

### 宣传与回站

重点文章配套站内完整原文、平台短内容、可复用资料。先使用已有渠道小范围验证；外部分发链接指向对应文章或章节，必要时带统一来源参数，canonical 保持干净 URL。

平台短内容展示一个实际发现或结果；回站理由具体到配置、数据、模板、工具或后续更新。宣传发布由站长选择具体渠道与内容，不因本路线图自动发送外部消息。

## 6. 执行清单与验收

状态约定：下列未勾选任务均为未完成。阶段表示依赖顺序，不是承诺工期。

### A：先修发现链路

- [ ] **A1｜高：真实修改日期。** 明确 frontmatter 日期契约，在 loader、详情 metadata / JSON-LD 与 sitemap 一致使用；非法日期安全处理，无修改日期时保留合理回退。验收：构造有更新、无更新、非法日期样本；核对发布与修改时间，避免每次构建改变日期。
- [ ] **A2｜高：发现入口内容覆盖。** 盘点数据库公开文章与静态内容，复用现有数据访问封装，选择符合 Edge / Pages 的合并和缓存策略。验收：抽样公开动态文章进入 sitemap / RSS，重复 slug 去重，草稿和私域不会新增泄露；发布后无需依赖目录客户端 JS 才获得发现链接。
- [ ] **A3｜高：直接输出结构化数据。** 调整抽检问题涉及的输出方式，正确转义 JSON，避免重复 Schema。验收：不执行 JS 的 HTML 解析可以读取合法 JSON-LD；内容与页面一致；再做浏览器及官方验证工具检查。
- [ ] **A4｜中：首页基础元信息。** 增加适当 H1 和首页 canonical。验收：初始 HTML 可见语义主标题、canonical 正确，视觉和标题层级正常。
- [ ] **A5｜高：真实爬虫访问核验。** 核对目标平台、robots、Cloudflare 拦截与真实日志。验收：记录验证身份、时间、URL、状态及挑战情况；不足以确认的项目继续标为待验证。
- [ ] **A6｜中：IndexNow 增量通知。** 先核对外部是否已接入；仅在内容发布成功且 URL 可访问后通知实质变更。验收：密钥文件验证成功，去重、重试、响应记录齐全；提交成功与收录成功分开显示。

### B：先做一条连续阅读路径

- [ ] **B1｜高：Codex / Agent 主题试点。** 整理 8–12 篇现有内容并设计独立主题页，具体 URL 在实现时确定。验收：有独立编辑价值，关键内容通过普通链接可达；遵守既有分类契约，不生成批量重复页。
- [ ] **B2｜高：相关推荐。** 复核并复用 `getRelatedContent()` 等已有能力，支持编辑精选或阅读顺序。验收：排除当前页、不可访问内容和重复项；抽查试点文章推荐能延续问题，记录推荐点击与后续阅读。
- [ ] **B3｜中：主题化订阅与资源动作。** 复用现有 CTA、订阅和资源组件。验收：入口清晰、操作可用，来源与主题可区分，移动端不阻挡正文。
- [ ] **B4｜高：邮件运营核验。** 核对配置、同步失败、本地保存、发送、送达和退订。验收：获授权的测试收件人走通链路；页面承诺符合实际能力，不能把本地入库误报成已完成发送能力。

### C：建立衡量与迭代

- [ ] **C1｜高：数据基线。** 核对 Search Console、Bing、已有 Umami / D1 数据与权限，能导出则先复用导出，无需先做大后台。验收：来源、时间窗口、分母和缺失值明确，至少按来源和落地内容拆分。
- [ ] **C2｜中：扩展 SEO 审计。** 增加代表路由的 HTTP / canonical / robots / 初始正文 / JSON-LD / sitemap 覆盖检查。验收：针对本次发现设置有意义的失败样本，保留线上检查时间与结果；通过不能解释为排名保证。
- [ ] **C3｜中：宣传试点。** 为试点文章准备短内容与资源，在选定渠道发布后比较有效访问和回访。验收：保留发布记录、来源参数、落地 URL 和实际转化，不以平台曝光替代站内效果。
- [ ] **C4｜低：llms.txt 整理。** 依据访问需求决定精简导航或补充入口。验收：链接有效、公开范围正确、维护成本可控；不把存在该文件当成收录成果。

第一批建议范围：A1–A4、C1。抓取与邮件核验可在取得相应数据后推进；B1–B4 构成首个内容增长试点。先完成有限范围验证，再决定扩大到更多主题或重排首页。

## 7. 指标与效果判定

继续沿用[内容信息架构](content-information-architecture.md)的有效起点、新访客、事件和评审口径；不在此复制另一套事件契约。

| 目标 | 观察指标 | 限制 |
|---|---|---|
| 内容发现 | 发布到首次已验证爬虫访问的时差 | 没有日志不能用提交时间代替 |
| 搜索效果 | 索引状态、曝光、点击、CTR | sitemap 数不是索引数，索引不保证曝光 |
| AI 可见性 | 支持平台的引用报告、被引用 URL、可识别来源访问 | 引用报告覆盖有限，不能将一次人工问答外推为全平台引用率 |
| 阅读与使用 | 既有有效起点率、有效阅读、资源动作 | 8 秒可见上报与 30 秒加滚动的有效起点不是同一指标；均不等于读完 |
| 连续阅读 | 推荐点击率、第二篇有效阅读会话占比 | 统一分母，排除自身测试和可识别自动流量 |
| 留存 | 订阅完成、邮件回访、7 / 30 日回访 | 匿名识别受清理存储和跨设备影响；等待观察窗成熟 |

先收集 2–4 周同口径基线。低流量按四周滚动窗口判断，记录样本量；足够流量时再采用随机实验。前后比较要标注内容更新和宣传渠道变化，不直接把所有增长归因于改版。不在缺少基线时设承诺型增长百分比。
