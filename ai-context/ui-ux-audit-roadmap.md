## 3. 已有优点与需要保留的能力

- 首页已形成纸张感、编辑排版、低饱和色的整体风格，不需要先更换全站视觉方向。
- 目录已具备搜索、主题和类型筛选、URL 参数、空结果文案和加载更多。
- 摘要已截断：列表默认一行，桌面两行。可访问性树包含完整文本，不代表屏幕显示全部摘要。
- 移动端顶部 `SiteHeader` 已有搜索表单，不能因为目录的桌面搜索框隐藏就判断“移动端无搜索”。
- 移动端已有底部导航及随滚动收起逻辑；应测试可发现性和遮挡，不先叠加另一套导航。
- 长文已有桌面章节目录、朗读和文章末尾订阅 / 推荐能力，后续优先完善复用。

## 4. 发现与建议

### UI-01｜高｜首页新读者入口的位置

证据：桌面截图中，文章、灵感、站长三栏并列；顶部另有多个站内外入口。可访问性树中的“从这里开始”位于站长介绍、舆情、成就与平台信息之后，截图首屏没有显示这一组主题路径。

判断：内容选择与站长信息同时争取注意力，新读者寻找合适主题的路径可以更直接。这是设计假设，不能据此断言三栏一定降低留存。

建议：先把现有主题路径提到主要内容附近，突出 2–3 个稳定起点；保留文章为主、灵感为辅的结构；外站入口标清去向。与 SEO 路线图 B1 联动，先试点再决定大规模重排首页。

验收：桌面和手机无需先浏览站长履历就能选主题；外站跳转可预期；按既有有效起点率和首次价值耗时比较。

### UI-02｜中｜目录选择与结果反馈

证据：目录可访问性树列出搜索、两类筛选、24/256 条结果；代码中的“已显示”位于列表底部，已选筛选条在手机隐藏。摘要已有行数限制。

建议：在结果开始处呈现简短的已选条件与结果数量，手机可直接移除条件；保留现有主题 / 类型模型。对标题、日期、类型、摘要的阅读顺序做视觉抽检后再调整密度。

验收：无需滚到 24 条结果末尾即可知道筛选结果数量；清除主题与清除关键词的含义一致；200% 缩放下文本和操作可达。不要把“继续压缩摘要”作为默认解决方案。

### UI-03｜高｜手机长文章节定位

证据：`ArticleToc.jsx` 使用 `hidden … md:block`；调研 `ResearchBody.jsx` 与普通文章页复用该组件，检查路径未发现等价的手机目录。

建议：复用同一份 toc 数据提供手机折叠目录，或可关闭的章节面板。先补可靠的章节跳转，再考虑当前章节高亮和阅读进度。

验收：在至少一篇长调研和普通长文章中，通过目录到达中间章节；标题不被固定页头遮挡；键盘可展开、跳转、关闭；多版本正文切换后目录仍对应当前版本。

### UI-04｜高｜动态目录失败提示

证据：`ArticlesIndexClient.jsx` 请求数据库文章与手工内容时将失败转换为 `null`，最终仍设置 `catalogReady`；现有静态内容保留，但没有区分“最新内容加载失败”和“确实没有动态内容”。

建议：保留可用内容，加克制的失败说明与重试动作；不把局部错误升级成全页阻塞，也不把失败展示成空目录。

验收：分别模拟一项失败、两项失败和成功空结果；静态内容继续可读，重试不重复条目，成功后提示消失，反馈可被辅助技术感知。

### UI-05｜中｜手机筛选可发现性与点击区域

证据：`.h5-chip-row` 横向滚动且隐藏滚动条；筛选按钮声明最小高度 28px。实际点击区域和设备表现未测量，不能直接认定不符合无障碍标准。

建议：提供剩余选项的可发现线索，选中项在视区内可定位；实测后增大过小的触控区域，避免同时新增复杂筛选抽屉和多排固定栏。

验收：360 / 390 / 430 宽度下能找到最后一项、辨认当前选择；长标签和放大字体不遮挡；横向手势不造成整页横向溢出。

### UI-06｜中｜连续阅读动作

证据：已有相关推荐和底部通用订阅 / 联系 / 目录 / 关于等入口；普通调研推荐按大类取前三篇，与当前问题的相关性有限。

建议：明确一个首要的“下一篇”，其次是当前主题资源与订阅。复用统一推荐能力，不堆叠新卡片。与 SEO 路线图 B2、B3 共用一个实施任务。

验收：抽查主题试点内容，推荐能延续读者问题；记录推荐点击和第二篇有效阅读，而不只观察按钮点击。

### UI-07｜高｜后台 SEO 概览与路线图顺序

证据：本地新增 `SeoGrowthRoadmap` 位于四个 StatCard 之前，默认展开第 6 节完整执行清单。该实现未部署，本轮没有后台视觉截图。

建议：恢复概览优先；路线图先展示精简摘要、下一批任务和阅读入口，完整审计按需展开。顶部锚点应能直接定位，不需要先扫过所有条目。

验收：桌面首屏可读关键概览；手机能迅速找到路线图与下一批任务；展开 / 折叠不导致焦点丢失。待浏览器验证实际首屏后确认布局。

### UI-08｜中｜后台设计令牌一致性

证据：新路线图组件写入了硬编码文字、边框颜色；现有设计总纲要求后台使用 `--admin-*`。`app/globals.css` 已有 `--admin-ink`、`--admin-muted`、`--admin-line` 等令牌。

建议：先修新增组件的偏离，再按页面逐步治理旧组件，不全库批量替换。正文表格、链接、焦点和深色状态一起验证。

验收：新组件使用既有语义令牌；浅色 / 深色 / 墨水屏下文字、表格边框与焦点清楚；不引入第二套调色板。

### UI-09｜中｜审计记录与执行待办的连接

证据：后台路线图显示禁用勾选框，进度来自 Markdown；尚未与 `/admin/planning` 关联。这是当前只读设计，不是保存故障。

建议：保留“归档状态”的准确含义，并提供明确的“去规划与待办”入口。需要任务同步时使用稳定 ID、来源引用和幂等导入，先定义进度正本与回写机制。

验收：用户能区分归档记录和可编辑任务；重复导入不生成重复待办；勾选后的持久化、失败反馈和审计记录一致。不要先把禁用框变成无持久化的可点击框。

### UI-10｜中｜移动端全路径复测

当前状态：待验证。已有底部导航随滚动隐藏，顶部搜索和两排横向筛选；多个固定 / 滚动区域需要实机确认。

验收：软键盘出现时搜索可提交、可退出；底部安全区不遮挡内容 / 订阅按钮；返回列表保留预期筛选与位置；长文上滑能发现导航；切主题、减少动态和放大字体均可用。

## 5. 执行顺序与复测矩阵

首批建议先完成 UI-03、UI-04，改善明确的阅读和错误恢复问题；同时完成 UI-07、UI-08，修正当前未发布后台组件。UI-01 / UI-02 在完成视觉基线后做小范围试点。UI-06 / UI-09 与现有 SEO / 规划任务合并，避免重复开发。

| 样本 | 任务 | 覆盖状态 |
|---|---|---|
| 首页 `/` | 选择 AI / 工程内容，辨认站外入口 | 桌面观察完成；手机、深色待测 |
| 目录 `/articles` | 搜索、组合筛选、零结果、清除、加载更多、返回 | 入口观察与代码检查完成；端到端操作待测 |
| 长调研 `agent-memory-mechanisms` | 切正文版本、找章节、继续阅读 | 代码检查；交互待测 |
| 普通长文章 | 找章节、分享、返回目录 | 需实施时选代表样本并记录 URL |
| 后台 `/admin/seo` | 看概览、找下一步、读验收、去待办 | 本地代码 / HTML 检查；视觉待测 |

建议视口：桌面 1280 / 1440，移动 360 / 390 / 430；浅色、深色、减少动态、键盘、200% 缩放。只对实际测过的组合标记通过。稳定后记录关键流程的截图和前后对比，截图需标明时间、视口、主题和登录状态。

衡量复用既有有效起点、首次价值耗时、搜索结果点击、第二篇阅读与回访定义。小流量使用四周滚动窗口；不以主观“更好看”代替流程是否可完成。
