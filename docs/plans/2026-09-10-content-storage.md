# 内容存储与发布改造计划

日期：2026-09-10。状态：本地代码实现与验收完成，待按上线手册执行远程迁移/部署。未提交、推送、部署或上传 R2。

## 目标

每天新增 10 篇文章时，正文和新增目录记录进入 D1，不随文章数量扩大 Worker 代码包，也不要求重建全站。复用现有 article_posts、content_index、Owner 鉴权和 MEDIA 图片上传。保留历史 URL、research:{category}:{slug} / article:{slug}、评论与燃币权益。

上线和恢复的完整步骤见 [内容存储上线手册](../content-storage-rollout.md)。该手册明确区分本次已完成的本地实现与尚未执行的远程操作。

## A：普通文章解耦（已实现）

- 原有富文本与 `{type:"markdown",markdown:"..."}` 共存于 article_posts.content_json；Markdown 最大 256 KiB，检索文本由正文派生。
- 后台创建、导入 .md、编辑、预览、发布、撤回，继续使用既有鉴权与 R2 图片上传。含 frontmatter 的调研文件不能误导入普通文章。
- 七篇内置文章逐篇导出为历史静态 JSON，Worker 按需读取 ASSETS，运行时代码只引用元数据。
- 正文和目录写入同一 D1 batch；CAS 冲突整批回滚。发布过的 slug 不可修改，撤回也保留首次发布日期，避免断开评论与权益关联。
- middleware 在开始流式输出前查询发布状态：草稿/不存在为 404，读取失败为 503，不暴露草稿标题或正文。

## B：Git 调研与目录解耦（已实现）

- 新增 0089_content_documents.sql：metadata_json / body_json 分列、源路径与 SHA-256、修订号、状态、持久别名。content_index 保持公共元数据投影。
- 调研详情使用单个 Edge 动态路由，D1 优先于历史归档。草稿/撤回 tombstone 禁止归档回落；只有新增 schema 缺失允许历史兼容读取，数据库连接错误不回落。
- 保留短 URL、带日期旧 URL、canonical、多版本 ?v=、密文解锁、测评、A 股清单、评论及权益 key。PPT 下载保留在浏览器执行，避免 Node 依赖进入 Edge。
- Owner 导入入口 `/admin/articles/research-import` 展示源路径、哈希、版本和正文，显式发布/撤回。Git Markdown 为创作正本；导入包来自可信 Owner，源哈希用于追踪，并非服务器验签。
- A 股/加密资产旧发布器改为：预检 D1 → 保存 Git 正本 → 发布 D1 快照 → 标记草稿发布成功。失败可重试，相同已发布源哈希不重复增加修订号。纯内容提交使用 Cloudflare 支持的 `[CF-Pages-Skip]` 前缀。
- 主目录、A 股/加密系列页、推荐、MCP、PV 白名单、RSS/sitemap、后台统一列表/周报和权益标题使用运行时数据。公开缓存采用 no-store，避免撤回后继续推荐旧条目。
- 目录按稳定顺序分页，不截断第 1,000 条之后的记录。旧 sync 同步不能覆盖 manual/git 状态；普通索引编辑不能修改 Git 文档的发布状态。
- `data/content-archive.json` 固定迁移当日 249 篇调研和 7 篇内置文章；日常新增不扩充它。静态目录代码、正文资产、旧 RSS/sitemap 与构建候选均受归档范围约束。

## C：媒体迁移工具（已实现，远程执行待上线阶段）

- 清点脚本输出文件字节数、SHA-256、重复文件组和字面引用。实测四个媒体目录共 96 个文件、128,000,997 字节（122.07 MiB），没有相同 SHA-256 的重复文件组。
- 迁移按 prepare / upload / verify / activate / prune / rollback 分步执行。只有审阅为 public + approved 的条目可进入计划；上传限定当前 MEDIA 桶，不写两个私有媒体桶。
- R2 对象使用内容哈希路径；校验完整字节、MIME、CORS 和音视频 Range。先添加旧 URL 的 302，再在实际线上旧 URL 已切换后允许清理源文件。清理前备份全部文件，恢复时不覆盖他人改动。
- 旧 URL 通过 Pages 静态重定向保持兼容，构建工具排除相应 Functions 路由；动态 /feed/<id> 继续进入 Worker。媒体迁移不必批量改写文章正文中的 URL。
- 本次只生成了一个真实文件的本地准备计划，未上传、激活或清理项目媒体。上传过程使用假的 R2/CLI 做本地集成测试；线上 CORS、权限和可访问性由执行时再次校验。

## 构建体积与边界

- 初始公开 Worker gzip 2.743 MiB，原门槛 2.750 MiB。
- 最终公开 Worker gzip **2.731 MiB** / raw **10.883 MiB**，余量 **0.019 MiB**；104 个 Edge 路由。
- 最终后台 Worker gzip **1.961 MiB** / raw **6.800 MiB**，余量 **0.539 MiB**；原门槛 2.500 MiB。
- 公开静态产物（排除 Worker）为 **1,084 个文件、210,604,396 字节**，初始为 1,821 个文件。媒体尚未实际迁移，不能把未来的 R2 节省记作已实现的体积下降。
- 静态最大项：feed 视频 23.67 MiB、ONNX WebAssembly 运行库 21.76 MiB、另一段 feed 视频 12.03 MiB。WASM 不属于正文或媒体迁移范围。
- 公开 Worker 余量仍小，后续功能代码变动需要继续检查。已隔离的是内容增长，不承诺代码包有很大剩余空间。
- 历史归档/目录文件仍是固定范围的兼容层；新内容必须通过 D1 发布。新发布内容的生效依赖新版代码和 D1 schema 已上线。

内容风格审计命令 exit 0，仍报告已有语料的 48 项风格建议和 17 项人工复核；本任务未批量改写作者正文，不将这些既有待审项计为本次已修复。
