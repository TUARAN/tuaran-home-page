# 2aran.com 站点设计语言

状态：生效中  
建立日期：2026-08-27  
适用范围：主站、后台、专题页面与站内工具。

## 设计目标

2aran.com 是内容与工程并重的个人站。界面需要先保证长文可读、路径清楚、状态可信，再表达克制的个人气质。视觉以纸张感、编辑排版和低饱和强调色为基础；交互反馈短促、明确，不用装饰性动画干扰阅读。

## 权威来源

- 全站颜色、表面、间距与壳层令牌：`app/globals.css`。
- 主站与后台页面壳：`app/(site)/layout.jsx`、`app/(admin)/layout.jsx` 及相关共享组件。
- 站点导航与公开信息架构：`lib/siteNav.js`。
- 后台可复用组件：`app/(admin)/components/ui/`。
- 加载与等待反馈：[加载动效设计规范](./loading-motion-system.md)。
- 调研内容风格不属于界面设计语言，继续以 `lib/researchStyleTemplates.js` 的 active 版本为准。

代码与文档冲突时，以当前组件和设计令牌为准，并在同一次修改中更新对应文档。

## 视觉基础

### 页面壳

- 主站内容宽度默认不超过 1120px，使用统一页头、页脚、背景和移动端底部导航。
- 后台使用 `admin-shell` 与 1180px 内容宽度，数据密集页面可以使用紧凑模式。
- 沉浸式专题只能使用已登记的 `feature` 壳，不在路由内创造第三套全站壳层。

### 颜色与表面

- 使用 `--page-bg`、`--site-ink`、`--site-muted`、`--site-line`、`--site-panel` 与 `--site-accent` 等语义令牌。
- 后台使用 `--admin-*` 令牌，不把主站硬编码颜色复制进后台控件。
- 深色模式需要单独验证层级、边界和对比度，不依靠透明度自动推导全部颜色。

### 排版

- 长文标题与编辑性标题优先使用站点衬线字体；控件、导航和数据使用无衬线字体；编号、时间与短标签可使用等宽字体。
- 正文靠字号、行高和段落节奏建立层级，避免用大量彩色卡片切碎阅读。
- 界面文案直接描述动作与结果，如“保存”“复制”“正在加载通知”，不暴露站长工作流。

## 组件与布局

- 同类功能复用同一组件；新增变体优先扩展语义属性，避免复制一份只有颜色不同的组件。
- 列表和台账优先行式分隔，卡片只用于确有独立对象边界的内容。
- 空状态、错误状态、加载状态和成功反馈属于组件完整状态，不能只实现理想数据状态。
- 页面骨架应接近最终内容尺寸，避免加载完成时产生明显布局跳动。

## 动效

- 动效用于解释状态变化、保持空间连续性和确认用户操作。
- 页面进入与普通悬停保持克制；循环动效仅用于尚未完成的等待或真实持续状态。
- 加载统一使用结构骨架、平滑圆环、三点节奏和按钮小圆环四级语言，详见专项规范。
- 支持 `prefers-reduced-motion`；循环动画优先使用 `transform`、`opacity` 或遮罩位置。

## 可访问性

- 交互控件必须具备键盘焦点样式、明确标签和足够点击区域。
- 状态不能只依赖颜色表达；异步反馈使用 `role="status"`、`aria-live` 或 `aria-busy`。
- 装饰图形对辅助技术隐藏，重要文本不能只存在于伪元素或动画帧。

## 变更流程

1. 先确认新需求能否由现有令牌、壳层和组件表达。
2. 需要新增模式时，先写清适用范围、状态和无障碍行为。
3. 修改共享组件与令牌后，复核主站、后台、深色模式、移动端和减少动态模式。
4. 同步更新本总纲、对应专项规范和 `/help` 的公开说明。
