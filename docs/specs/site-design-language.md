# 2aran.com 站点设计语言

状态：生效中  
建立日期：2026-08-27  
适用范围：主站、后台、专题页面与站内工具。

## 设计目标

2aran.com 是内容与工程并重的个人站。界面需要先保证长文可读、路径清楚、状态可信，再表达克制的个人气质。视觉以纸张感、编辑排版和低饱和强调色为基础；交互反馈短促、明确，不用装饰性动画干扰阅读。

## 权威来源

站长阅读入口：后台 `/admin/design`（UI 设计）；页面随部署读取文档正本。

- 全站颜色、表面、间距与壳层令牌：`app/globals.css`。
- 主站与后台页面壳：`app/(site)/layout.jsx`、`app/(admin)/layout.jsx` 及相关共享组件。
- 站点导航与公开信息架构：`lib/site/siteNav.js`。
- 后台可复用组件：`app/(admin)/components/ui/`。
- 加载与等待反馈：[加载动效设计规范](./loading-motion-system.md)。
- 资源书籍与手册正文：[资源书籍阅读模板](./resource-book-reader.md)。
- 页面问题与改造进度：[UI / 交互审计路线图](../context/ui-ux-audit-roadmap.md)（2026-09-08，GPT6-Astra 记录；视觉复测范围与待验证项见文内）。
- 调研内容风格不属于界面设计语言，继续以 `lib/research/researchStyleTemplates.js` 的 active 版本为准。

代码与文档冲突时，以当前组件和设计令牌为准，并在同一次修改中更新对应文档。

## 视觉基础

### 页面壳

- 主站内容宽度默认不超过 1120px，使用统一页头、页脚、背景和移动端底部导航。
- 后台使用 `admin-shell` 与 1180px 内容宽度，数据密集页面可以使用紧凑模式。
- 沉浸式专题只能使用已登记的 `feature` 壳，不在路由内创造第三套全站壳层。

### 颜色与表面

- 使用 `--page-bg`、`--site-ink`、`--site-muted`、`--site-line`、`--site-panel` 与 `--site-accent` 等语义令牌。
- 后台使用 `--admin-*` 令牌，不把主站硬编码颜色复制进后台控件。
- 深色模式需要单独验证层级、边界和对比度，不依靠透明度自动推导全部颜色。

### 内容图表与彩色契约

生效版本：2026-11-18。适用于 `/articles` 下的调研文章与普通文章正文里的内嵌 SVG 图、Mermaid 图和表格。写作约定见 `research/README.md`；实现见 `lib/research/markdown.js`、`app/globals.css`；方案来龙去脉见 `docs/context/content-visualization-alignment.md`。

**色板令牌**：`--sem-*` 系列，浅色定义在 `:root`，深色在 `.dark` 单独定义，不从浅色靠透明度推导。每类三个值——`*-bg`（形状浅填充 / 标签底）、`*-ink`（文字）、`*-line`（描边 / 标签边 / 色条）。另有 `--sem-surface`（中性面）与 `--sem-edge`（连线）。全部低饱和，取自站点纸张感与冷灰基调。装饰性强调色在同一张图内不超过一主一辅；确需按类别区分时走下面这张语义色板，并在文字或图例里写明类别，不靠颜色单独表意。

| 语义类 | 用途 | 令牌组 |
|---|---|---|
| `sem-core` | 核心判断、主节点 | `--sem-core-*` |
| `sem-good` | 正向 / 已核验 | `--sem-good-*` |
| `sem-warn` | 提示 / 待核 | `--sem-warn-*` |
| `sem-risk` | 风险 / 否定 | `--sem-risk-*` |
| `sem-mute` | 次要 / 中性 | `--sem-mute-*` |

**内嵌 SVG 图**：作者在 `research-inline-diagram` 的 `figure` 内写语义类，形状用 `sem-core` 等，文字用对应的 `sem-*-ink`，中性底板用 `sem-surface`，连线与箭头用 `sem-edge`。配色由 CSS 统一维护，SVG 的 `fill`/`stroke` 属性优先级低于类规则，因此类会覆盖内联配色。渐变、多边形、多行文字可用，但标签与属性必须过 `SAFE_DIAGRAM_TAGS` / `SAFE_DIAGRAM_ATTRS` 白名单；`style`、`href`、`src`、`on*`、`<foreignObject>`、`<filter>`、`<script>` 一律拒绝。

**彩色表格**：单元格与正文用 `[!core]…[/!core]` 这类成对语义标签，渲染成 `sem-tag--*` 胶囊。`.table-scroll` 里带标签的单元格补一条左侧色条。颜色只作辅助，状态词必须直接写在标签文字里（如「已核验」「待核」「高风险」），保证读屏、灰度打印和深色模式下判断仍成立。一表一类语义，避免同一张表既标状态又标量级。

**硬性要求**：

- 每幅图配 `figcaption` 讲清判断，`svg` 带 `aria-label` 给读屏与放大视图；装饰图形对辅助技术隐藏。
- 明暗两套主题都要复核文字与填充的对比度，浅填充配深文字；不能只靠颜色表达状态。
- 图、表与正文共用同一套事实口径，图里的数字、日期、名称与信息来源一致。
- 一图一结论；汇总大图只表达同一层关系下的完整清单，跨层派生、时间线、流程拆成各自的图。
- 正文有内嵌图时 frontmatter 设 `auto_images: false`，避免氛围图与图表重复。
- 两条渲染链路共用 `.prose-tuaran` 容器：调研正文走 `renderMarkdown`，普通文章走 Tiptap JSON（`ArticlePostBody.jsx`）。语义色类在 CSS 层对两条链路生效，但语义标签与内嵌 SVG 图只在 markdown 链路可用；改渲染链路时两条一起核。

### 排版

- 长文标题与编辑性标题优先使用站点衬线字体；控件、导航和数据使用无衬线字体；编号、时间与短标签可使用等宽字体。
- 正文靠字号、行高和段落节奏建立层级，避免用大量彩色卡片切碎阅读。
- 界面文案直接描述动作与结果，如“保存”“复制”“正在加载通知”，不暴露站长工作流。

## 组件与布局

- 同类功能复用同一组件；新增变体优先扩展语义属性，避免复制一份只有颜色不同的组件。
- 列表和台账优先行式分隔，卡片只用于确有独立对象边界的内容。
- 空状态、错误状态、加载状态和成功反馈属于组件完整状态，不能只实现理想数据状态。
- 页面骨架应接近最终内容尺寸，避免加载完成时产生明显布局跳动。

## 动效

- 动效用于解释状态变化、保持空间连续性和确认用户操作。
- 页面进入与普通悬停保持克制；循环动效仅用于尚未完成的等待或真实持续状态。
- 加载统一使用结构骨架、平滑圆环、三点节奏和按钮小圆环四级语言，详见专项规范。
- 支持 `prefers-reduced-motion`；循环动画优先使用 `transform`、`opacity` 或遮罩位置。

## 可访问性

- 交互控件必须具备键盘焦点样式、明确标签和足够点击区域。
- 状态不能只依赖颜色表达；异步反馈使用 `role="status"`、`aria-live` 或 `aria-busy`。
- 装饰图形对辅助技术隐藏，重要文本不能只存在于伪元素或动画帧。

### 首页第一次进入

记录日期：2026-09-20。

第一次打开首页时，先给一扇全屏入口，像屏风挡住后面的园子；上面只放几句核心主张，点小入口后再揭开现在的三栏首页。第二次起直接进内容，不要每次刷新都演一遍。同一浏览器身份一次即可，可复用现有游客身份。

文案要对仗、有冲击。不要用「前端 · AI 工程 · 一个奶爸」这类履历句。现成可用的是站内已有对联「输入决定输出 / 输出暴露输入」，横批用「选一件值得投入二十年的事」。界面上不要写「大观园」「屏风」「本文」这类自我指涉。

已试过并撤回：左右平移的对开屏风太呆；GSAP 月洞门扩开加竖排楹联更接近设想，但完成度不够，2026-09-20 已全部撤销。

以后若再做，必须同时满足：首页仍是 force-static；搜索引擎看到的仍是现有首页 HTML；游客 cookie 是 HttpOnly，入园标记要另用可读存储；`prefers-reduced-motion` 下直接揭开；回访零成本，不为全站用户打包动画库。这套进入动画也要能说服当前「页面进入保持克制」的原则，否则继续搁置。

## 变更流程

1. 先确认新需求能否由现有令牌、壳层和组件表达。
2. 需要新增模式时，先写清适用范围、状态和无障碍行为。
3. 修改共享组件与令牌后，复核主站、后台、深色模式、移动端和减少动态模式。
4. 同步更新本总纲、对应专项规范和 `/help` 的公开说明。
