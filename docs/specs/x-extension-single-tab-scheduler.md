# X 扩展单页签排班（设计与验收）

日期：2026-10-28。目标版本：4.0.10。本地源码已实现，尚未打包或在用户浏览器完成实测；以下是源码行为与验收边界。

## 目标

- 每个 Chrome 配置文件中的一个 X 账号只保留一个长期执行页签。评论、点赞、关注、发帖八项任务轮流占用它；临时读取回复上下文的页签在读取后立即关闭。
- 扩展后台保存排班意图、每项任务的等待截止时间、冷却原因、手动停止标记和轮换位置。页签关闭、导航或后台重启后，仍能从这些记录继续安排任务。
- 任务实际等待时释放执行页签。到期后才唤醒；同一账号最多一项任务执行动作。不同 Chrome 配置文件各自排班。
- 保留现有任务的成功确认、去重、冷却和停止语义。精品发帖仍按五个北京时间档位执行，错过档位不集中补发。
- 面板总开关下方展示排班台：上一任务（已结束轮班）、当前任务（正在执行）、下一任务（预计可运行时间）。“排班”及“详情”弹窗展示轮班历史、预计顺序、倒计时、时段、手动停止和受限原因，均读取同一份后台调度状态。点击任务只查看详情；另设「打开当前执行页签」，查看不改变队列。

## 边界

- 排班不提高各任务的操作频率，也不缩短 X 限制后的冷却。一个任务受限只延后该任务；明确的账号级限制才影响该账号全部任务。
- 切换前必须让当前点击或发送动作结束，保存任务进度及下一次执行时间。保存或停止未确认时，保持当前页签，不启动下一项。
- 同一 Chrome 配置文件只绑定一个 X 账号。若检测到账号切换，暂停自动调度并提示重新确认，避免把上一账号的去重记录用于新账号。
- 管理设置包含任务参与、优先级、可运行时段和单次最长占用（默认 30 秒，可选 20 / 45 秒）。确认完成一次动作后立即让出页签并进入等待；超时硬顶也会轮换。优先级不能让低优先级任务永久饥饿；任务本身的冷却、普通发帖间隔和精品发帖档位优先于管理设置。
- 清理未回关默认约每周一次：上次结束后间隔 7 天才再进队；到点后占用约 10 分钟做一轮清理，不按短切片「完成一次动作就让出」。
- 当前多窗口排班是旧模式。迁移时先保存并安全结束旧窗口，再启用单页签；失败时不关闭仍在执行动作的窗口。

## 界面状态

对外只保留四类：运行中、等待中、需处理、已停止。冷却、队列、自动恢复与正在停止都归入等待中；连续受限、失联超窗、停止超时归入需处理；空闲与手动停止归入已停止。主按钮上的「启动中 / 停止中」仅作短暂过渡文案。

排班台任务卡：运行中绿边跑马灯，等待中黄边跑马灯，已停止 / 需处理红边呼吸。点任务卡进入子页，只显示该单项内容；顶部「← 排班台」旁用文字标题标记当前任务，不再展示评论 / 点赞 / 关注 / 发帖下的 01/02 分组页签。排队等待默认是查看，不在排班台上误写成手动停止。

## 验收

1. 全流程启动后，同一配置文件最多一个长期 X 执行页签；八项任务都能轮到。`strategyVersion ≥ 4` 后即使暂停排班，也不回退到按任务开窗。启动与轮班默认不抢焦点；优先复用点启动的那一页，同路径任务页内交接。排队中的任务点击默认只查看，不会写成手动停止。等待期间可以无执行页签。
2. 评论任务完成一轮或进入倒计时后，后台在不提前唤醒它的情况下安排其他到期任务。
3. 任一任务在发送、点赞或关注动作中切换失败时，不会开启下一项，也不会把未确认操作计为成功。
4. 浏览器重启、扩展后台重启、手动停止、单项冷却、普通发帖待发列表和精品发帖档位均能恢复到正确状态。
5. 面板中每项状态和后台一致，且只以四类状态呈现；管理设置真实影响排班，页面预览明确标为模拟。

## 迁移顺序

1. 将评论运行快照按账号和任务分开持久化；补齐其他任务的保存检查。
2. 将调度器改成八项统一轮换，并复用一个执行页签；加入安全切换和旧窗口收敛。
3. 接入排班设置与状态显示，验证异常、重启和手动操作后，再升级主版本。

## 当前验证范围

- 扩展自动化测试覆盖优先级、时段、八项轮班、旧窗口迁移、安全切换和本地更新恢复；源码与文档通过静态检查。
- 实际 X 页面上的长时间轮班、跨浏览器重启后的恢复、不同账号隔离及受限倒计时仍需在加载 v4 扩展后观察。安装前不把本地开发结果当作线上已生效。
