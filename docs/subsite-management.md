# 二级站管理中心

入口：后台 → 项目与工程 → 二级站点（`/admin/subsites`）。

## 管理范围

- 登记、编辑、搜索二级站点与内部服务；记录域名、部署平台和项目、代码仓库、分类及运维备注。范围包括 Ollama、站长后台与历史 Ops 入口，不以公开目录为限。
- 访问范围分为公开访问、内部 / 受控，可筛选和编辑。它只标记台账，不会修改真实访问权限或向公开目录添加站点。
- 运营状态为待上线、运营中、暂停、兼容保留、已归档。历史 Ops 入口保持“兼容保留”，不误标为待上线。归档保留站点资料和关系，恢复时重新调整状态。
- 关系方向为来源站点 → 归属方／服务提供方，类型包括归属、账号、燃币、复用部署、内容来源和服务依赖。
- 关系可新增、编辑状态和说明、停用、移除；详情同时显示出站与入站关系。
- 主站为只读关系锚点。归档前必须停用涉及该站点的所有已接入关系。

这是站长维护的管理台账。保存不会修改公开 `/sites` 目录、DNS、Cloudflare 项目、账号 Origin 白名单、实际账户关联或燃币计费。台账的“已接入”由站长登记，不是实时探测结果。

## 数据与权限

- 初次读取从 `lib/secondarySites.js`、`lib/domainRegistry.js` 和账号来源配置生成初始资料，也纳入域名台账中尚未公开的站点；账号白名单中的子站保守地以“待接入”登记，由站长核验后更新，避免把配置存在当成验收完成。
- 首次保存后，管理台账持久化到现有 D1 `site_settings` 表的 `subsites.registry.v1` 键。读取旧台账时自动补齐完整域名目录中缺失的站点与其初始关系，下次明确保存时写入数据库。不会覆盖已有资料或恢复已移除的关系；标识或域名冲突时保留现有记录。旧资料的访问范围按相同标识及域名补齐，无法确认的自定义站点默认内部 / 受控。
- 不新增数据库或迁移；环境需已应用 `migrations/0040_site_settings.sql`。
- `GET /api/admin/subsites` 读取台账；`POST` 接收 `{ revision, action }`，动作有 `save-site`、`save-relation`、`delete-relation`。
- API 每次独立验证站长身份，写请求要求同源 Origin 和 JSON。响应均禁止缓存，不放宽子站登录信任边界。
- 使用版本检查和数据库条件写入防止覆盖他人修改。发生冲突返回 409，刷新后重新编辑。
- 无 D1 绑定时只提供只读初始资料；表缺失、数据损坏或读写失败返回 503，不降级为成功保存。
- 资料只允许 `2aran.com` 子域，拒绝重复和已有内部域名；归属唯一，归属、依赖和复用部署分别禁止循环。
- 备注不能存储密钥，凭证继续使用后台集成密钥管理入口。
