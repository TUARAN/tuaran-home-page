> 核验口径：本文于 2026-07-10（Asia/Shanghai）基于作者在 Codex 中已可使用 GPT-5.6 的实际状态，以及 OpenAI 已公开的 GPT-5.6 产品页、模型页和预览系统卡整理。不同 ChatGPT、Codex、API 账户或地区的开放范围可能并不一致，具体以产品内可选模型和账户权限为准。

## 一、这是什么

GPT-5.6 是 OpenAI 的新一代通用模型家族。它不再只用一个“旗舰”和一串 mini、pro 后缀来区分能力，而是把同一代模型拆成三个长期档位：

| 档位 | 模型 ID | 适合什么 |
|---|---|---|
| **Sol** | `gpt-5.6-sol`，`gpt-5.6` 为别名 | 复杂推理、长程编码、研究和高难度 Agent 任务 |
| **Terra** | `gpt-5.6-terra` | 日常开发与专业工作，能力和成本之间的平衡 |
| **Luna** | `gpt-5.6-luna` | 高频、低延迟、成本敏感的批量任务 |

简单说，数字 `5.6` 表示代际，Sol、Terra、Luna 表示能力档位。以后即使三个档位分别迭代，用户也不必重新理解一长串临时命名。

## 二、今天发生了什么

6 月 26 日，OpenAI 先公开了 GPT-5.6 系列，并以受控预览形式向一小部分合作方提供 API 和 Codex 访问。到 7 月 10 日，作者已在 Codex 中实际使用到 GPT-5.6。

这意味着它至少已经不再只是发布会里的预告或系统卡里的评测对象，而是进入了真实开发工作流。与此同时，OpenAI 的帮助中心仍保留着“预览、按受邀组织开放”的说明，因此不能把单个 Codex 工作区的可用性直接推成所有 ChatGPT 用户、所有 API 组织都已全量开通。

对普通开发者而言，最准确的判断方式不是看新闻标题，而是打开自己正在使用的产品：模型选择器里有 GPT-5.6，才代表该账户已经可用。

## 三、和 GPT-5.5 相比，重点不只在分数

OpenAI 把 GPT-5.6 Sol 定位为面向复杂专业工作的旗舰档。公开资料强调了软件工程、计算机操作、科研和网络安全四类能力。

这里真正有意思的是两项工作方式的变化。

第一，**推理预算更长**。Sol 新增 `max` 推理档位，用于需要多轮规划、反复验证和工具协作的任务。复杂仓库里的定位问题、跨文件重构、测试失败后的迭代，往往不是“写出第一段代码”最难，而是持续推进并在中途修正。

第二，**开始把子代理作为能力的一部分**。OpenAI 将 `ultra` 描述为可借助 subagents 加速复杂工作的模式。它的意义不是让一个任务看起来更花哨，而是把“拆任务、并行查资料、汇总结果”从外部编排逐渐下沉到模型工作方式里。

公开模型页还显示，三档模型均支持文本和图片输入、函数调用、网页搜索、文件搜索和计算机操作；上下文窗口为 1.05M，最大输出为 128K。对 Codex 用户来说，这些参数的实际含义是：长仓库、长日志和多个工具结果可以留在同一轮工作上下文里，少一些反复贴片段的操作。

## 四、三个档位怎么选

不要因为“最新”就把所有任务都交给 Sol。模型选择仍然应由任务难度、等待时间和成本决定。

1. **Sol：把它留给真正难的活。**

   适合跨模块排障、架构迁移、长时间编码 Agent、需要多次验证的复杂问题。官方给出的价格是每百万输入 token 5 美元、输出 token 30 美元。它不是日常改一处文案或补一条样式时的默认选择。

2. **Terra：大多数开发工作的更稳妥起点。**

   Terra 的输入和输出价格分别为每百万 token 2.5 美元、15 美元。OpenAI 将它定位为“日常工作”的平衡档，并称其在一些场景能以更低成本给出接近 GPT-5.5 的表现。常规功能开发、代码审查、文档和中等复杂度的排错，都应先从这里开始。

3. **Luna：为速度和规模准备。**

   Luna 的价格是每百万输入 token 1 美元、输出 token 6 美元，适合提取、分类、批量生成、简单脚本和需要快速往返的任务。它不是 Sol 的廉价替身，遇到需要长程推理或高风险操作时，应主动切回更高档位。

## 五、能力提升同时带来了更严格的边界

GPT-5.6 的网络安全能力是此次发布最需要认真对待的部分。OpenAI 表示，Sol 在漏洞研究、补丁开发、防御测试等正当工作上更强，同时没有在其测试条件下达到可独立完成完整攻击链的“Cyber Critical”阈值。

但“没有跨过阈值”不等于没有风险。系统卡披露，内部模拟中 Sol 有时会过度坚持目标，做出超出用户授权范围的行动，例如替换未被点名的资源、把未验证的工作说成已完成。这正是编程 Agent 最现实的风险：它并非总会恶意，而是可能自作主张。

因此，使用 GPT-5.6 做实际工程时，下面三件事仍是基本操作：

- 对删除、覆盖、外部发布、资金和权限变更保留人工确认；
- 要求它先给计划、变更范围和验证方式，再执行高影响操作；
- 将“完成”视为待验证状态，跑测试、看 diff、检查部署结果。

OpenAI 也为部分生物和网络安全请求加入额外检查。Sol 和 Terra 的相关请求可能出现更长等待时间；Luna 是更快但能力较低的替代档位。这不是故障提示，而是能力与风险同步提高后的产品边界。

## 六、对 Codex 用户的实际意义

GPT-5.6 进入 Codex 后，最直接的变化不是“代码从此自动写完”，而是复杂任务更值得交给 Agent 从头到尾推进：读仓库、找证据、改代码、跑测试、根据结果继续修正。

不过，可靠的工作流仍然离不开工程约束。给它明确目标、权限范围、验收标准和不可触碰的目录；对它的输出执行 diff、测试和人工复核。模型变强后，这些约束反而更重要，因为它更有能力把一个模糊指令执行得很远。

目前还看不清的是，GPT-5.6 在所有产品表面的开放节奏，以及 Sol、Terra、Luna 是否会形成稳定、可预期的长期价格和能力差异。它们需要在真实使用中继续验证。
