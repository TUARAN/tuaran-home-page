> **合规提示：** 中国人民银行等八部门发布的银发〔2026〕42号通知明确，境内代币发行融资等虚拟货币相关业务属于非法金融活动；未经相关部门依法依规同意，境内主体及其控制的境外主体不得在境外发行虚拟货币。以下内容用于理解技术架构、安全审计和测试网实验，不构成主网发行、融资或投资建议。

## 一、先给结论

“发币”在技术上包含四个连续阶段：

1. **定义资产**：选择区块链和代币标准，确定名称、符号、总量、精度、增发规则和管理权限。
2. **创建与分配**：部署合约，把初始供应量分配给流动性、社区、团队、金库或锁仓合约。
3. **建立价格发现**：通过联合曲线发行，或者将代币与 BNB、USDT 等资产注入 DEX 流动性池。
4. **约束发行者权力**：公开源码和部署参数，管理增发、升级、撤池、锁仓、多签和时间锁。

一个最小 ERC-20 合约可能不到 20 行。决定资产性质和市场风险的是完整发行结构：谁持有管理权限、总量能否继续增发、初始筹码如何分配、价格如何形成、流动性能否被撤走，以及发行行为在哪个司法辖区面向哪些用户。

用户提供的“小龙虾”项目可以作为核验案例。公开网络上同时存在多个使用“币安小龙虾”“First Agent 全自动小龙虾”等近似名称的 BNB Chain 代币，合约地址包括 `0x9458...3935c2`、`0xed9d...4444`、`0x3dca...7777` 等。它们是不同资产，不能因为名称、图片或中文简称相同就视为同一个项目。

参考项目具体使用哪条链、哪一个合约、哪种发行平台，仍需完整合约地址或部署交易才能核验。链 ID 与合约地址是分析起点，网站采用什么托管技术不影响代币的链上规则。

## 二、完整架构：从资产定义到二级市场

一套常见的 Meme 币或社区代币系统，可以拆成以下链路：

```text
发行规则
  ├── 链与标准：EVM / Solana；ERC-20 / SPL Token
  ├── 供应规则：固定总量 / 可增发 / 销毁
  └── 权限规则：管理员 / 多签 / 时间锁 / 不可升级
          │
          ▼
代币合约部署
  ├── 创建初始供应量
  ├── 分配到团队、社区、金库和锁仓合约
  └── 验证源码与部署参数
          │
          ▼
首次价格发现
  ├── Launchpad 联合曲线
  └── 直接创建 DEX 交易池
          │
          ▼
二级市场
  ├── Router：寻找交换路径并执行交易
  ├── Pair / Pool：持有两侧资产并形成价格
  └── LP 头寸：决定谁能增加或撤出流动性
          │
          ▼
链上观察
  ├── 区块浏览器：合约、权限、持仓、交易
  └── 行情索引器：价格、成交量、流动性、K 线
```

### 1. 链与资产标准

首先要决定代币部署在哪条链。链的执行环境决定合约语言、账户模型、手续费资产、钱包生态和可用的交易市场。以 BNB Smart Chain 为例，它兼容 EVM，主网 Chain ID 为 `56`，燃料资产是 BNB，常见 BEP-20 代币沿用 ERC-20 接口。Solana 的 SPL Token、Sui 的 Coin 等资产采用不同模型，不能直接套用 Solidity 合约。

任何代币都至少需要以下唯一标识：

```js
const token = {
  chainId: 56,
  address: '0x完整的40位十六进制地址',
  symbol: 'CRAW',
  decimals: 18,
}
```

`symbol` 可以重复，`address + chainId` 才能唯一指向一份链上资产。名称和图标属于辅助信息。

钱包保存私钥并签名，RPC 节点把读取请求和已签名交易转发到区块链。这些组件负责访问基础设施，不参与决定供应量和价格。

### 2. 代币合约层

ERC-20 定义了 `totalSupply`、`balanceOf`、`transfer`、`approve`、`transferFrom` 等通用接口。BNB Smart Chain 与 EVM 兼容，常见 BEP-20 代币沿用这套接口，因此钱包和 DEX 可以直接识别。

最小固定总量版本可以直接复用 OpenZeppelin：

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import {ERC20} from "@openzeppelin/contracts/token/ERC20/ERC20.sol";

contract CrawfishToken is ERC20 {
    constructor(address recipient)
        ERC20("Crawfish", "CRAW")
    {
        _mint(recipient, 1_000_000_000 * 10 ** decimals());
    }
}
```

部署完成后，总量一次性进入 `recipient`。合约没有额外的 `mint`、税费、黑名单、暂停或代理升级能力，外部审计相对容易。`decimals = 18` 只影响钱包显示，链上仍用整数记账。

一旦加入以下功能，审计范围会明显扩大：

| 功能 | 可能用途 | 主要风险 |
|---|---|---|
| `mint` | 持续发奖励、生态激励 | 管理员可以稀释所有持有人 |
| 转账税 | 营销、回购、自动加池 | 买卖实际到账不透明，可能造成高税或无法卖出 |
| 黑名单 | 合规冻结、阻止攻击地址 | 管理员可以冻结普通用户 |
| `pause` | 紧急停止 | 管理员可以让全市场停止转账 |
| 可升级代理 | 修复缺陷、增加功能 | 现有规则可被更换，审计结论可能失效 |
| 最大持仓/最大交易 | 限制机器人和巨鲸 | 参数设置不当会形成隐性交易限制 |

公开社区币若没有明确业务需要，固定总量、无税、无黑名单、不可升级的合约最容易解释。需要管理权限时，应把权限交给多签钱包，并配合时间锁和公开变更记录。

### 3. 初始分配与权限层

合约创建出总量后，代币仍集中在一个或少数地址。发行结构需要回答每一部分代币归谁、何时可以转出：

| 分配方向 | 常见承载方式 | 需要公开的约束 |
|---|---|---|
| 流动性 | 创建 DEX 池 | 初始数量、配对资产、LP 控制人 |
| 社区 | 空投或领取合约 | 资格、领取窗口、防女巫规则 |
| 团队 | 线性释放合约 | cliff、释放周期、受益地址 |
| 金库 | 多签钱包 | 签名阈值、成员、资金用途 |
| 生态激励 | 奖励合约 | 发放上限、速度、停止条件 |

团队声称“只占 5%”时，需要继续检查关联地址、创建者首批转账、金库签名人和未标记钱包。初始分配决定筹码集中度，管理员权限决定未来能否改变供应和转账规则，两者应分开核验。

### 4. 发行平台层：联合曲线先交易

很多新代币没有单独部署一套定制业务合约，而是调用 Launchpad 的工厂合约：

```text
创建者填写名称、符号、图片
        │
        ▼
Launchpad Factory 创建代币
        │
        ▼
用户在联合曲线上买卖
        │
   达到募集或市值阈值
        ▼
自动向 PancakeSwap 等 DEX 建池并注入流动性
```

这种路线把合约模板、初始交易、手续费和 DEX 迁移打包在一起，买卖可以全部发生在 Launchpad。链上核验时要同时检查：

- 代币是谁创建的；
- 是否由已知工厂合约产生；
- 买卖发生在联合曲线合约还是普通 DEX 池；
- 达到什么条件后迁移；
- 迁移后 LP 头寸归谁；
- 平台和创建者分别收取哪些费用。

同名“小龙虾”资产里出现以 `7777`、`4444` 结尾的地址，只能作为发行平台生成模式的线索。地址尾缀不能证明安全，也不能单独证明来自某个平台。

### 5. DEX 与流动性层

直接部署路线通常要自行创建交易池。创建者把两种资产按设定比例放入池中，例如：

```text
100,000,000 CRAW + 10 BNB
```

忽略手续费时，初始价格约为：

```text
1 CRAW = 10 / 100,000,000 BNB
```

V2 自动做市池常用 `x × y = k` 维持储备关系。用户买入 CRAW 后，池中的 CRAW 减少、BNB 增加，价格随之上升。池子越浅，同样大小的交易造成的滑点越高。

PancakeSwap V3 使用集中流动性。流动性提供者需要选择价格区间，头寸以 NFT 表示；价格离开区间后，头寸会变成单边资产并停止赚取手续费。新项目需要持续管理区间，操作复杂度高于 V2。PancakeSwap 当前文档建议优先使用 V3，只有代币不兼容或主要流动性仍在 V2 等场景才考虑 V2。

能交易还不等于市场健康。至少要同时观察：

- 池内两侧资产的实际价值；
- 大额买卖的预估滑点；
- LP Token 或 V3 头寸由谁控制；
- 流动性是否锁定，锁定多久；
- 前十地址是否包含池、销毁地址和交易所；
- 创建者是否能撤池、增发或修改税费。

“烧毁 LP”可以降低创建者直接撤走该头寸的能力，但也会失去迁移、调整和应急能力。时间锁、多签和公开计划提供了更灵活的约束，代价是仍需信任治理流程。

### 6. 索引与信息层

区块链节点提供原始状态，用户看到的 K 线、持币人数、美元价格和安全评分通常来自第三方索引器。常见数据路径是：

```text
链上区块与事件
   ├── BscScan：合约源码、创建交易、持币地址
   ├── DEX 索引器：池储备、成交量、价格
   ├── 钱包：余额和代币图标
   └── 行情网站：供应量、市值、社交资料
```

第三方页面可能延迟、映射错误或把同名代币合并。核验顺序应以区块浏览器中的合约、创建交易和池地址为主，行情网站只用于辅助观察。

### 7. 链下信息入口

项目介绍页、社区账号和钱包连接界面负责传播信息、展示合约地址或帮助用户构造交易。它们可以随时更换，不参与区块链共识，也不决定供应量、权限和池内价格。

安全的交互界面不会索取助记词或私钥。签名应发生在钱包内，用户仍需核对目标合约、调用方法和授权额度。链下入口被篡改时，攻击者可能替换合约地址或诱导无限授权，因此公开页面只能作为发现入口，不能作为资产真实性证明。

## 三、两条实现路线怎么选

| 维度 | Launchpad 模板发行 | 自行部署合约与建池 |
|---|---|---|
| 开发量 | 低 | 中到高 |
| 上线速度 | 快 | 需要测试、验证、建池 |
| 合约自由度 | 受平台模板限制 | 可自定义 |
| 初始定价 | 联合曲线决定 | 创建者用入池比例决定 |
| 流动性 | 达到条件后自动迁移 | 创建者自行准备 |
| 平台依赖 | 高 | 较低 |
| 审计重点 | 平台工厂、曲线、迁移规则 | 代币权限、分配、DEX 头寸 |
| 适合场景 | 无复杂功能的公开实验 | 有长期产品和明确治理需求的项目 |

对于纯 Meme 币，定制“税费 + 自动回购 + 防机器人 + 动态黑名单”往往增加攻击面和信任成本。对于积分、会员权益等产品内代币，先确认是否真的需要自由转让和公开市场；许多业务用中心化积分账本或不可转让凭证更合适。

## 四、从测试网到上线的工程流程

一条可审计的开发流程可以分成九步。

### 第一步：定义法律与产品边界

先明确发行主体、用户所在地、代币是否可转让、是否承诺收益、是否接受法币或稳定币、是否代表股权债权或现实资产权益。涉及公开融资、收益权、稳定币或 RWA 时，应在写合约前取得对应司法辖区的专业法律意见。

对境内主体，银发〔2026〕42号已经把公开发行路径严格收口。合规的技术研究应使用本地开发链、BNB Chain Testnet、Sepolia 等测试环境，测试资产不得宣传为可投资资产。

### 第二步：冻结代币规格

至少写清：

- 名称和符号；
- 总量与小数位；
- 固定总量还是可增发；
- 初始分配地址和比例；
- 团队、社区、流动性和金库份额；
- 锁仓与释放计划；
- 是否存在暂停、销毁、投票或升级功能。

规格需要直接映射到合约和链上地址，不能只写在白皮书里。

### 第三步：使用成熟标准库

基于 OpenZeppelin ERC-20 实现组合必要扩展，锁定明确的依赖版本。不要从陌生项目复制含税费、反机器人或路由器特判的合约。

### 第四步：自动化测试

最低测试集合包括：

- 初始总量和接收地址正确；
- 转账、授权和代扣符合 ERC-20；
- 未授权地址不能增发、暂停或升级；
- 锁仓不能提前释放；
- 税费上限和豁免名单符合规格；
- 与预定 DEX Router 的买卖、加池和撤池流程兼容；
- 极端数值、零地址和重复初始化不会破坏状态。

如果合约包含联合曲线、分红、回购、代理升级或跨链桥，应增加不变量测试、模糊测试和独立安全审计。

### 第五步：测试网完整演练

测试网演练不能只验证“部署成功”。还要模拟分配、建池、买入、卖出、撤池、管理权转移、前端切链、错误 RPC 和区块浏览器验证。

### 第六步：部署与源码验证

部署交易应保存以下证据：

- 编译器版本和优化参数；
- Git commit；
- 构造参数；
- 部署者地址；
- 合约地址和交易哈希；
- 区块浏览器源码验证结果。

源码验证让外部用户确认链上字节码与公开代码一致。验证本身不代表代码安全。

### 第七步：分配与权限托管

团队和金库份额应进入公开的多签、时间锁或线性释放合约。部署者的临时权限需要按计划移交。单纯调用 `renounceOwnership` 也不一定足够，因为代理管理员、其他角色或外部控制合约可能仍有权限。

### 第八步：创建流动性

选择交易对、DEX 版本、费率档位、初始价格和资金规模。公开记录 LP 或 V3 头寸的持有人、锁定安排和解锁时间。创建池之前还要评估抢跑与夹子交易风险，避免公开待执行参数后被机器人利用。

### 第九步：公开链上信息并持续监控

发行方应公开链名、Chain ID、完整合约地址、部署交易、区块浏览器、池地址和权限说明。项目介绍页只是承载这些信息的一种渠道。上线后持续监控大额转账、权限变更、增发、流动性变化、异常税费和公开入口劫持。

## 五、如何判断参考币的真实架构

拿到完整合约地址或任意一笔该币的链上交易后，可以按下列顺序还原：

### 1. 确定链与完整合约地址

不要用中文名称代替地址。先从钱包资产详情、区块浏览器、交易记录或项目公开渠道取得完整地址，再确认 Chain ID。同一个地址字符串在不同 EVM 网络上也可能对应不同合约。

### 2. 在区块浏览器检查创建交易

记录：

- 创建时间和区块；
- 创建者地址；
- 是否由 Launchpad 工厂创建；
- 源码是否验证；
- 合约是否为代理；
- 所有者、管理员、铸币和暂停角色。

### 3. 读取合约功能

重点搜索 `mint`、`setTax`、`blacklist`、`excludeFromFee`、`pause`、`upgradeTo`、`setRouter`、`setPair`、`maxTx` 等接口。还要看管理员能把参数改到多大，不能只看当前值。

### 4. 定位真实交易池

通过创建交易、工厂合约、Router 调用和交易记录，确认交易发生在联合曲线、PancakeSwap V2、PancakeSwap V3，还是聚合器。代币地址和池地址是两个不同概念。查询池中两种资产的储备、LP 持有人和最近交易。

### 5. 复核筹码与流动性

把销毁地址、池地址、交易所地址从普通持币者中区分出来，再计算创建者关联地址和前十持仓。持币人数多也可能来自空投或批量小额转账。

### 6. 对照公开入口

项目介绍页、社交账号和交易入口应使用同一个 `chainId`、代币地址和池地址。页面配置只能说明它准备调用谁，最终仍以钱包弹窗和链上交易为准。

目前缺少参考币的完整合约地址或创建交易哈希，以上六步无法形成闭环。补充其中任意一项后，可以继续完成逐项核验。

## 六、最容易被忽略的风险

### 合约地址冒充

同名币可以无限创建。搜索结果、社交账号和代币图片都可以复制，完整合约地址才是识别入口。

### 流动性撤出

代币合约完全正常，创建者仍可能控制全部 LP 并撤走 BNB 或 USDT。用户手里的代币还在，市场却失去退出流动性。

### 隐藏增发和代理升级

`owner` 已销毁不代表所有权限消失。角色控制、代理管理员、外部铸币合约和跨链桥都可能改变有效供应。

### 高税与卖出限制

转账税、交易开关、最大交易额、黑名单和只允许特定 Pair 的逻辑都可能造成“能买不能卖”。应在分叉环境模拟真实 Router 买卖。

### 信息入口与签名风险

域名、社交账号或前端依赖被入侵后，攻击者可以替换合约地址或诱导无限授权。用户应核对钱包显示的目标合约和授权额度。

### 价格幻觉

极小流动性池里的一笔交易就能制造很高的最后成交价和“市值”。市值通常是最后价格乘以供应量，不能代表池里存在同等规模的可兑现资金。

### 监管风险

技术服务、商业展示、营销宣传和付费导流也可能被纳入监管范围。银发〔2026〕42号同时限制境内互联网企业和信息技术服务机构为相关非法活动提供服务，境内团队不能因合约和服务部署在境外就推定业务合规。

## 七、工程上的建议方案

若目标是学习 EVM 与代币机制，可以采用以下最小测试方案：

1. 使用 BNB Chain Testnet 或本地 Anvil 网络；
2. 部署固定总量、无税、无黑名单、不可升级的 OpenZeppelin ERC-20；
3. 把初始总量发送到测试多签；
4. 在测试环境创建小额流动性池；
5. 验证源码，记录部署交易和构造参数；
6. 用区块浏览器或只读工具核对余额、合约地址和测试网交易；
7. 完成买入、卖出、撤池和权限检查；
8. 不面向公众募资，不承诺收益，不把测试资产包装成投资品。

若目标是正式商业发行，需要先完成司法辖区、发行主体、牌照、用户范围、KYC/AML、税务、证券属性和营销规则评估。法律路径确定后，再决定技术路线。合约开发只是整个项目的一小部分。

## 八、未能验证

- 参考币的完整合约地址、Chain ID 和部署交易；
- 它是否通过 Four.meme、Flap 或其他 Launchpad 创建；
- 它是否已经迁移到 PancakeSwap；
- 代币权限、筹码分布、LP 控制人和锁定安排；
- 用户提供的项目链接与任何公开同名“小龙虾”代币之间的归属关系。

继续查证至少需要一个材料：完整合约地址、区块浏览器链接、买入交易哈希或钱包中的资产详情页。
