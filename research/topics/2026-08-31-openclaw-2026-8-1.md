## 一、先给结论

1. **`v2026.8.1` 是 2026-08-31 的稳定发布节点**，不是 2026-11 的 tip。GitHub tag `v2026.8.1` 于 **2026-08-31 03:30 UTC**（北京时间约 11:30）发布；同日前后公开 Release 说明仍是核对该节点行为的一手来源。[Release](https://github.com/openclaw/openclaw/releases/tag/v2026.8.1)
2. **该节点最值得核的两件事**：OpenProse 内置移除 + OpenAI 模型路由迁移；官方指向 `openclaw doctor --fix`。
3. **记忆侧有四类默认行为**（Active Memory 召回、Grounded Dreaming、自动学习、会话跨空闲/日界保留）——个人安装升级后应按使用边界逐项核对，而不是默认「全开最好」。
4. **现行 Releases（复核 2026-11-04）**：最新稳定 tag 为 **`v2026.10.10`**（published **2026-11-03 03:22 UTC**）；同一时间窗还有 `v2026.10.9`、`v2026.9.x` 等更近补丁。8.1 之后的安全补丁、工具权限与依赖修复以现行 notes 为准，勿沿用本稿作安装手册。
5. **仓库规模是当日快照，不是采用证明**：`openclaw/openclaw` GitHub API 于 **2026-11-04** 读到 stars ≈ **393,871**、forks ≈ **82,780**。这只说明可见度，不能换算安装量或 MAU。

### 2.2 两项破坏性迁移（发布说明原文级）

发布说明 Changes 写明：

- **OpenProse migration (breaking)**：移除内置 OpenProse 插件与 `/prose`；运行 `openclaw doctor --fix` 清理遗留配置；保留既有 `.prose` 源文件，并指向上游 Agent Skill 迁移文档。
- **OpenAI route migration (breaking)**：`doctor --fix` 迁移已发布的 `codex/*`、`openai-codex/*` 模型引用、provider 配置、已存会话与自动化路由到 `openai/*`；冲突留给操作者修复。

稳妥顺序（工程建议，非厂商 SLA）：备份配置与状态 → `doctor --fix` → 读冲突输出 → 重启 Gateway → 验证常用模型 / Skill / 自动化。

同期预告：外部插件需在 **2026-09-01** SDK 移除门槛前迁移若干宽泛 `plugin-sdk` 子路径。是否已在你安装的 tip 完成，以现行 docs / doctor 为准。

### 2.3 会话与执行位置

Highlights 可核对的能力包括：

- 按精确词检索可见历史，并打开命中附近上下文；
- 从某条用户消息回退或分叉（改聊天上下文，**不**撤销已发生的文件/工具副作用）；
- 配对设备与云端 Worker 承接工作，会话工作区可随之移动；
- 刷新后仍可见进度卡（计划、子 Agent、累计修改）；
- 结构化提问卡片（点选 / 按钮 / 文本 / Skip）。

这些属于「长期运行会话」方向的产品事实，细节以该 tag notes 与当时客户端为准。

### 2.4 记忆：四类默认（需人工核对）

发布说明对个人安装默认记忆行为的表述可压缩为：

| 默认项 | 发布说明要点 |
|---|---|
| Active Memory | 启用且未配置私聊隔离时，默认可检索有限范围内同一 Agent 的私人会话上下文；群组/频道不参与；可显式关闭 |
| Grounded Dreaming | 默认开启模型驱动的后台记忆整理，带出处的材料进入长期记忆，并保留 Dream Diary；可关闭 |
| Automatic self-learning | 默认捕获可复用经验，并自动应用 scanner 通过的新 Skill / Workshop 管理的 Skill；用户自写 Skill 改动仍待确认 |
| Session reset | 未配置重置策略时，会话默认跨空闲与日期边界保留；显式 daily/idle 与手动 `/new`、`/reset` 仍有效 |

另有 **Incognito threads**：Control UI 对话记录与压缩状态留在 Gateway 内存，重启消失；模型服务商处理、诊断日志与显式工具写入仍按各自规则保留。它不能当成完整无痕。

### 2.5 权限、自动化与并发

- 会话可选权限模式，受限文件系统可钉在记录的工作区 / worktree；团队角色限制他人会话与操作范围——发布说明同时标明这些是**协作控制**，不用于隔离恶意租户。
- 自动化可对精确操作申请持续授权，可查看/撤销；任务或操作变化需重新确认。
- 凭据请求走遮罩输入，值不进聊天或模型上下文；可选代理仅向批准目标替换受保护 secret。
- 无显式上限时，默认顶层并发按 CPU 并行度落在 **8–16**；已有显式限制保留。

## 三、结构：为什么这个节点仍值得单独留档

卡住判断的一层是：**默认记忆与权限比新 UI 更影响既有安装的风险面**。

跨设备会话、进度卡、widget 是可见能力；真正会在升级后「悄悄改变系统记住什么」的是 Active Memory / Dreaming / 自动学习 / 会话重置四项。多人共用 Gateway、处理客户材料或需要项目隔离时，缺的是一张升级后的核对表；功能清单本身不够。

与现行 tip 的关系也属于结构问题：若把 8.1 当安装指南，会漏掉 8.1→10.10 之间的安全依赖与工具边界修复。节点文应回答「当时改了什么、升级要核什么」；版本选择应回到 [Releases](https://github.com/openclaw/openclaw/releases) 与 `docs.openclaw.ai/releases/...`。

## 四、外部研判

一种外部解读是：到 2026.8.1，OpenClaw 的主矛盾已从「能不能调工具」转向「多会话、多设备、长期运行时状态与权限能否被操作者看懂」。Fixes 长于 Highlights 的发布形态，也符合这一判断——但 Fixes 条目本身未在本篇逐条复述，以免把未实测的 bug 叙述写成结论。

对仍停在 8.1 附近的自托管实例：优先用 doctor 与现行 release notes 做差分，而不是假设 10.x 只是「同款加功能」。
