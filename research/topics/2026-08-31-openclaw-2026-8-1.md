OpenClaw 在 2026 年 8 月 31 日发布 `v2026.8.1`，tag 对应已验证提交 `ea80657`。

发布说明很长。值得优先看的内容可以压缩成一句话：OpenClaw 正在把会话、记忆、权限和执行位置做成一套长期运行的系统能力。功能更多了，升级时需要核对的默认行为也更多了。

## 1、升级前先处理两项迁移

第一项是 OpenProse。内置的 OpenProse 插件和 `/prose` 命令已经移除，官方建议运行：

```bash
openclaw doctor --fix
```

这个命令会清理遗留配置。已有的 `.prose` 源文件会保留，后续要迁移到上游的 Agent Skill。

第二项是 OpenAI 模型路由。原来的 `codex/*` 和 `openai-codex/*` 引用会迁移到 `openai/*`。`doctor --fix` 会处理官方提供的模型引用、provider 配置、已有会话和自动化路由；遇到冲突时会留给操作者修复。

这两项都可能影响现有工作流。稳妥的顺序是先备份配置和数据库，再运行 doctor，阅读输出中的冲突提示，然后重启 Gateway 验证常用模型、Skill、插件和自动化。

外部插件作者还要留意 2026 年 9 月 1 日开始执行的 SDK 移除门槛。多个宽泛的 `plugin-sdk` 子路径将迁移到更聚焦的配置、消息通道和运行时入口。当前版本给出的是预告，插件最好在门槛生效前完成修改。

## 2、会话开始跨越一台 Gateway

这次最容易感知的变化，是会话不再紧贴当前设备和当前页面。

OpenClaw 新增了历史对话搜索，可以按精确词语找到过去的可见消息，再打开命中位置附近的上下文。会话还支持从某条用户消息回退或分叉，保留此前的对话分支。回退只改变聊天上下文，不会撤销已经发生的文件修改和工具操作。

配对设备和云端 Worker 可以承接工作，会话工作区也能随之移动。云机器可以保留预热状态和项目种子，供后续会话复用。页面刷新后，进度卡会继续显示任务计划、子 Agent 活动和累计修改。

结构化提问也进入了 Web 和原生客户端。Agent 等待选择时，用户可以点选卡片、使用消息按钮、直接输入文字，或者明确跳过。这个变化看似只是界面优化，实际解决的是长任务中的人机交接：任务可以暂停等待授权，得到回答后继续执行。

## 3、记忆有四个默认行为需要核对

`v2026.8.1` 对个人安装的默认记忆行为改动较大。

启用 Active Memory 后，如果没有配置私聊隔离，同一个 Agent 会默认检索有限范围内的私人会话上下文。群组和频道不参与这项召回，配置中也可以关闭。

后台记忆整理默认启用。官方称为 Grounded Dreaming，它会把带来源的信息整理进长期记忆，并保留 Dream Diary。自动学习也默认启用：系统会捕获可复用经验，自动应用通过扫描的新 Skill 或由 Workshop 管理的 Skill；用户自己编写的 Skill 修改仍保持待确认状态。

没有配置重置策略时，会话默认跨越空闲期和日期边界继续保留。手动 `/new`、`/reset` 以及显式配置的 daily、idle 策略仍然有效。

这四项设置会直接改变“系统记住什么”和“下一次对话从哪里继续”。多人共用 Gateway、处理客户材料或需要严格项目隔离时，升级后应该逐项检查：

- Active Memory 的召回范围；
- 后台记忆整理是否开启；
- 自动学习对新 Skill 的应用规则；
- 会话按日期或空闲时间重置的策略。

发布说明还加入了 Incognito 会话。它会把 Control UI 的对话记录和压缩状态留在 Gateway 内存中，重启后消失。但是，模型服务商的处理、诊断日志和显式工具写入仍按各自规则保留。Incognito 不能当作完整的无痕模式。

## 4、权限从一次确认变成可管理的范围

长期运行的 Agent 需要更细的权限边界，这一版集中补上了几块。

会话可以选择明确的权限模式，并把受限文件系统访问固定在记录下来的工作区或 worktree。团队管理员可以给已验证用户分配角色，限制他们可访问的 Agent、他人会话和操作范围，还可以要求新会话在沙箱中执行。官方同时说明，这些机制属于协作控制，不能用于隔离恶意租户。

自动化可以为一项精确操作申请持续授权。授权可以查看和撤销；任务或操作变化后需要重新确认。这比“以后都允许”更容易审计，也减少了定时任务在提示词变化后继续沿用旧权限的风险。

凭据请求会使用遮罩输入，值不会进入聊天或模型上下文。可选代理只向批准的目标替换受保护的 secret。团队凭据存储把 secret 与普通环境值分开：secret 只写，受保护的出站请求绑定声明过的主机。

外部插件的安装和更新也增加了来源、版本、能力和制品检查。任意可执行来源需要显式 `--force`；受信任的官方目录和已跟踪来源可以跳过来源警告，但仍要完成能力确认。

## 5、自动化开始围绕会话组织

新建的 Agent-turn 自动化会默认绑定发起它的会话。`/loop` 可以按固定间隔或自定节奏反复检查，且仅限 owner 使用。没有会话上下文的 CLI 或 API 自动化仍保持隔离。

Goals 可以直接在 Control UI 创建和管理。Workboard 可以绑定自动化，在关联会话结束后继续调度，并把完整看板放到会话仪表盘。邮件触发器则可以从指定 IMAP 邮箱启动 Agent 工作。

这套组合的实际意义是，自动化开始拥有明确的对话来源、工作状态和后续动作。操作者可以追溯“哪段对话创建了任务”“任务目前做到哪里”“完成后触发了什么”。

默认顶层并发也会根据 CPU 并行度调整到 8 至 16 个任务，已有显式限制会保留。小内存设备、本地模型或同时运行多个浏览器 Worker 的机器，升级后应观察资源占用，必要时继续使用自己的并发上限。

## 6、聊天结果可以变成可交互界面

Agent 现在可以在聊天中返回交互式 widget，把它固定到会话仪表盘，并导出为 PNG。每个 widget 可以获得精确的操作授权和网络来源许可。MCP App 的视图也能固定到仪表盘，重新打开时恢复此前界面。

音频和视频会跟随会话跨上传、回复、播放和刷新保留。Apple 和 Android 客户端获得原生播放与视频上传；浏览器 Talk 可以向兼容模型发送有限频率的摄像头画面。

这些能力扩大了 Agent 的输出形式。表单、仪表盘和媒体不再只是聊天附件，它们开始成为会话状态的一部分。涉及网络访问、摄像头、麦克风或可执行操作时，权限范围仍应按最小需要授予。

## 7、修复清单透露了工程重点

发布说明的 Fixes 部分比功能清单更长，主要集中在四类问题。

第一类是 SQLite 和状态恢复，包括 WAL 损坏防护、共享文件系统上的日志模式、快照验证、数据库隔离恢复和新旧 schema 冲突。第二类是配置完整性，包括长数字标识符、并发写入、无法解析配置和 SecretRef 的保留。

第三类是会话与子 Agent 收尾，包括重启后恢复长会话、压缩边界、分支重写、跨会话消息和子 Agent 完成通知。第四类是权限与凭据，包括受保护出站连接、私密提示词、会话权限继承和插件授权。

这些修复说明，项目当前的难点已经从“Agent 能否调用工具”转向“长时间、多会话、多设备运行时能否保持状态一致”。这也是升级后需要做回归验证的原因。

## 8、升级后检查什么

可以按下面的顺序做一次小范围验收：

1. 备份配置、全局数据库和 Agent 数据；
2. 运行 `openclaw doctor --fix`，处理 OpenProse 与 OpenAI 路由迁移提示；
3. 重启 Gateway，验证常用模型、插件和 provider；
4. 创建一段测试会话，刷新页面并重启 Gateway，确认历史、进度和工作区恢复；
5. 检查 Active Memory、Grounded Dreaming、自动学习和会话重置策略；
6. 检查自动化的来源会话、持续授权和通知目标；
7. 用一个无敏感数据的测试 secret 验证遮罩输入与目标主机限制；
8. 观察 CPU、内存和本地模型占用，确认 8 至 16 的自动并发是否合适。

这份清单只能覆盖发布说明中最影响既有安装的部分。插件开发者、团队 Gateway、云端 Worker 和移动客户端还需要按自己的部署方式补充验证。
