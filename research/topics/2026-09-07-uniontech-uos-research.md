## 一、先给结论

统信 UOS 已经是产品线完整、商业交付体系成熟的国产 Linux 发行版家族。它继承了 deepin 二十余年的桌面技术积累，又围绕政企信创补上了多 CPU 架构、集中管控、应用分发、迁移工具、安全认证和现场服务。

对准备选型或从 Windows 迁移的单位，结论可以压缩为五点：

1. **桌面是统信最鲜明的长板。** DDE 的交互积累、deepin 社区、应用商店、玲珑包和 Deepin-Wine 形成了连续的桌面技术路线。V25 又加入 Linux 6.6、磐石系统 2.0、USEC 2.0 和 UOS AI 3.0。
2. **“支持国产 CPU”只能作为入场条件。** 飞腾、鲲鹏、龙芯、海光、兆芯、申威及 Intel、AMD 都在官方适配范围内，但 AMD64、ARM64、LoongArch64、MIPS64、SW64 的软件包和驱动并不通用。项目必须核对具体 CPU、整机、固件、UOS 小版本、内核、应用和驱动的组合。
3. **生态数字很大，关键业务仍需逐项验收。** 官方适配目录已超过千万条记录；这类数字按产品版本、CPU 平台和系统版本累计。V25 发布时披露的“应用商店 1 万余款、玲珑 6000 余款、Windows 兼容引擎 4000 余款”也属于不同集合，不能相加，更不能换算成单位内部应用的可用率。[统信 UOS V25 发布说明](https://www.uniontech.com/news-info/2877.html)
4. **Windows 迁移的主要成本在操作系统之外。** IE/ActiveX、COM/OLE、VBA 宏、字体与分页、UKey、电子签章、打印扫描、加密狗、专用驱动、AD/GPO 和安全客户端，任何一项都可能阻断岗位迁移。
5. **与银河麒麟的胜负只能由真实业务 PoC 决定。** 两家新一代桌面系统都采用 Linux 6.6、不可变系统、原子更新、新包格式和 AI 子系统。UOS 的 Windows 过渡工具链公开得更完整；银河麒麟的政企积累、安全体系和服务器长期支持同样有竞争力。生态总量和市场口号无法替代同机、同应用、同外设测试。

## 二、从 Hiweed、deepin 到统信 UOS

### 1. 历史脉络

deepin 的源头可追溯到 2004 年 7 月发布的 Hiweed Linux。项目在 2009 年更名为 Linux deepin；武汉深之度科技有限公司于 2011 年成立；2012—2013 年间，自研 Deepin Desktop Environment（DDE）随 deepin 12.12 进入产品。团队在 2013 年前后开始建设 Deepin-Wine 兼容路线。[deepin 二十年回顾](https://www.deepin.org/zh/write-in-20-years-of-deepin/)

统信软件成立于 2019 年。公司官网把自己的前身概括为“自 2004 年组建的深度操作系统团队”。这段血缘解释了 UOS 的桌面设计、DDE、自研应用和 Wine 兼容能力从何而来。[统信企业介绍](https://www.uniontech.com/About.html)

deepin 与商业 UOS 需要分开理解：

- deepin 是社区发行版和桌面技术上游，面向全球开源用户；
- 统信 UOS 是商业产品家族，面向政企、教育、个人和专用终端，增加商业授权、认证、服务、集中管控和行业交付；
- 两条线持续并行。统信官网当前直接把 deepin 列为“统信桌面操作系统社区版”，同时保留专业版、教育版和家庭版。[统信产品树](https://www.uniontech.com/OS.html)

因此，把 UOS 简化成“deepin 改名版”会漏掉商业交付层；把两者说成完全无关，也不符合其社区和技术演进关系。

### 2. 版本迭代

| 时间 | 版本与事件 | 主要变化 |
|---|---|---|
| 2004 | Hiweed Linux | 基于 Debian 的中文本地化发行版起点 |
| 2009—2013 | Linux deepin、DDE 1.0 | 更名并转向自研桌面环境与桌面应用 |
| 2019 | 统信软件成立 | deepin 技术积累进入商业 UOS 产品与信创交付体系 |
| 2020 | 统信 UOS V20 | 商业主线发布，随后经历 1010、1020 等小版本 |
| 2021—2024 | V20 1030—1070 | 多架构、兼容、AI、运维和质量更新；1070 于 2024 年发布，之后继续推出 u1、u2 |
| 2024-08-15 | deepin 23 | 重建仓库，强化 ARM64、RISC-V、LoongArch64 等架构支持，[发布记录](https://www.deepin.org/en/deepin-23-is-officially-released/) |
| 2025-06-26 | deepin 25 | DDE、磐石系统、玲珑和 UOS AI 继续演进，[发布记录](https://www.deepin.org/zh/deepin-25-release/) |
| 2026-04-15 | 统信桌面 UOS V25 | Linux 6.6、磐石系统 2.0、USEC 2.0、UOS AI 3.0、应用和迁移生态升级 |

统信总裁刘闻欢在 2024 年的公开演讲中回顾，V20 早期迭代过快，第一次大规模升级约有 10% 用户出现升级故障，客户和伙伴反映强烈，后来主要版本节奏调整为每年一版。这个历史数据不能代表 V25 当前故障率，但它说明大型组织应当把升级回归、灰度和回退当成长期工程。[统信版本与生态回顾](https://uniontech.com/news-info/2351.html)

截至 2026 年 9 月，官网已经确认统信桌面 UOS V25 正式发布；服务器官网的主产品资料仍以 V20 为主，公开材料曾披露服务器 V25 规划，缺少与桌面 V25 同等清晰的正式发布证据。服务器项目不应仅凭桌面版本号推定产品状态。

#### 公司是怎样组建起来的

统信成立时由诚迈科技、北京世界星辉、北京一路创科、宁波深度汭溥、刘闻欢和北京神州绿盟等共同出资。随后，诚迈科技把武汉诚迈 100% 股权作价 2.04 亿元注入，武汉深之度原股东把武汉深之度 100% 股权作价 2.55 亿元注入；两家公司成为统信旗下业务主体。诚迈科技当时持股 44.44%，是第一大股东，但统信一直按联营企业而非诚迈控股子公司核算。[诚迈科技 2019 年年报](https://vip.stock.finance.sina.com.cn/corp/view/vCB_AllBulletinDetail.php?id=6037385&stockid=300598)

2020 年末的 11 亿元 A 轮融资引入 18 家投资方。融资后的公开股东表中，诚迈科技持股 32.5423%，北京世界星辉持股 10.7390%，北京一路创科、宁波深度汭溥、北京深度创科和员工持股平台南京友联信创也是重要股东；其余股东包括北京亦庄、南京软件谷、武汉光谷、山西信创等地方产业资本，以及深创投、高榕、国和、力合等市场化机构。[2021 年监管问询回复及完整股东表](https://static.cninfo.com.cn/finalpage/2021-01-06/1209057082.PDF)

这套股东结构可以概括为四类：

- 诚迈科技及其注入的操作系统团队；
- deepin 创始团队、管理层相关主体与员工持股平台；
- 三六零旗下北京世界星辉、北京神州绿盟等产业资本；[三六零 2025 年年报](https://dataclouds.cninfo.com.cn/shgonggao/hsomarket/2026/20260514/2b28035833674b5f8c91dda2c2a3e912.PDF)

公开股东名册不支持把统信直接归为某一家央企的控股子公司或地方国企。公司具有明显的信创产业资本和地方国资背景，同时保留创始团队、上市公司和市场化基金共同持股的混合所有制特征。现有公开文件没有给出一份仍然有效的“一致行动协议 + 表决权安排 + 最新完整持股比例表”，因此无法仅按第一大股东、法定代表人或董事长判断最终实际控制人。

## 三、产品谱系与授权模式

### 1. 产品线

| 产品线 | 公开产品 | 典型对象与场景 |
|---|---|---|
| 桌面操作系统 | V25/V20 专业版 | 党政、国企、金融、能源等办公终端，配套域管、企业应用商店和私有更新 |
| 桌面操作系统 | V20 教育版 | 电子教室、教学办公、机房还原、考试与教育应用 |
| 桌面操作系统 | deepin 社区版 | 开源社区、开发者和个人体验 |
| 桌面操作系统 | 家庭版 | AMD64 个人消费市场，强调易用与多生态兼容 |
| 服务器与云 | 服务器 V20、云原生操作系统、容器镜像平台 | 数据库、中间件、云平台、容器、高可用和行业数据中心 |
| 智能终端 | 专业版、云终端专用版 | 平板、手持终端、智慧大屏、自助终端和云终端 |
| 专用设备 | 专用设备操作系统 V20 | 金融自助设备、医疗终端、网安设备、军工装备等固定用途设备 |

“行业定制版”不是一个统一 SKU。教育版有明确产品名称；金融、政务、电力等更多采用专业版或服务器版，加行业方案、镜像定制和现场服务。专用设备版则强调精简、断电保护、开机自启、多串口/USB、多屏和触控。[专用设备操作系统 V20](https://www.uniontech.com/m/news-info/1040.html)

服务器 V20 也不是单一上游路线。官方资料曾区分 A 版（龙蜥/openAnolis 技术栈）、D 版（Debian 技术栈）和 E 版（openEuler 技术栈），包管理分别涉及 RPM/DNF/YUM 或 DEB/APT。采购服务器版时要写明具体分支和版本，不能笼统写“基于 Debian”。[服务器 ADE 版本说明](https://faq.uniontech.com/solution/umountain/3984/2e19)

### 2. 授权

桌面专业版采用商业许可。2026 年 4 月更新的最终用户许可协议规定：许可为非独占、不可转让、可撤销，一份副本每次限一台计算机；授权期限和售后期限由其他协议或授权文件确定；第三方软件的许可责任由用户另行承担。[桌面专业版 EULA](https://uniontech.com/agreement/license-professional-cn)

服务器 V20 安装资料列出“商业使用授权”和“免费使用授权”两种模式。免费授权适合开发、体验或不需要原厂服务的场景；商业生产仍应核实补丁、SLA、迁移、驻场、定制和衍生方案是否包含在合同中。[服务器 V20（1070）安装手册](https://www.uniontech.com/uploads/files/2024/0605/G7NSesgXBp9zWS3a7IByqDLmyh9GrHYRglzswdxD.pdf)

## 四、技术架构

### 1. 内核、桌面与服务器技术栈

UOS V20 桌面长期提供 Linux 4.19 和 5.10 LTS 双内核，便于在旧硬件稳定性和新硬件驱动之间选择。V25 桌面迁到 Linux 6.6 LTS；DDE 继续承担窗口管理、控制中心、文件管理器和系统交互。[V20 双内核说明](https://uniontech.com/news-info/2019.html) [V25 发布说明](https://www.uniontech.com/news-info/2877.html)

服务器版围绕多 CPU、容器、云计算、高可用、数据库和中间件展开。它与桌面共享“多架构、国产生态和安全服务”方向，但上游社区、包管理、内核模块、数据库认证和生命周期都要按具体服务器 SKU 核验。

### 2. 如意玲珑：跨发行版应用包

如意玲珑（Linyaps）是统信发起、后进入开放原子开源基金会孵化的独立包管理工具集。它试图解决传统 DEB/RPM 依赖交叉、不同发行版运行环境不一致和应用权限过宽的问题。

核心设计包括：

- 应用、基础环境和 Runtime 分层，共享可复用文件；
- 默认无 root 运行，使用 Linux Namespace 隔离进程、文件系统和网络；
- 通过沙箱限制权限，减少应用直接修改宿主系统的范围；
- 使用 OSTree 提供增量更新与版本回滚；
- 支持 x86、ARM64、LoongArch，并适配 deepin、UOS、openEuler、Ubuntu、Debian、openKylin、Anolis 等发行版。

这些能力来自项目自身的架构说明，性能数字仍需在目标应用和硬件上复测。[Linyaps 开源仓库](https://github.com/OpenAtom-Linyaps/linyaps) [开放原子项目说明](https://www.openatom.org/project/projectyGrVXZpSF8wG)

玲珑没有取代所有 DEB 包。V25 仍会遇到传统 DEB、玲珑 layer/UAB、自研应用和兼容应用并存的局面。企业应用商店需要同时处理包来源、签名、权限、灰度、依赖和回退。

### 3. Windows 兼容引擎与迁移产品

Deepin-Wine 基于 Wine，把 Windows API 调用转换为 Linux 环境可执行的调用。它不是一台完整 Windows 虚拟机。统信围绕不同遗留问题形成了多条产品路线：

| 遗留问题 | 统信路线 | 适用边界 |
|---|---|---|
| Windows C/S 应用 | Deepin-Wine、统信有应 | 适合经过验证的应用；内核驱动、复杂 COM、加密狗和许可证服务可能失败 |
| IE/ActiveX | 有来、有往、UBX 或插件兼容 | 适合限期过渡，长期应改造成标准 Web |
| 无 Linux 驱动外设 | 有墨、原生驱动适配、云打印 | 必须验证准确型号、接口、固件和 CPU 架构 |
| 完整 Windows 环境 | 有乔/彩虹、本地虚拟化 | 保留兼容性，也保留 Windows 授权、补丁、资源和数据交换治理 |
| 多应用集中交付 | 应用虚拟化、远程应用 | 受网络、并发、图形、音视频和外设重定向影响 |

官方解决方案自己把 C/S、IE/ActiveX、外设驱动、本地虚拟化和应用虚拟化分成多条路径，这也证明“兼容 Windows”不是单一开关。[应用外设迁移解决方案](https://www.uniontech.com/case-applicationPeripheral.html)

V25 发布时，统信称 Windows 兼容引擎商店提供 4000 余款应用。这个数字表示引擎侧应用条目或适配成果，不代表任何 EXE 都能运行，也不保证每款软件的插件、自动更新、外设调用和商业许可完整有效。

### 4. 安卓兼容

UOS V20 白皮书介绍过 UEngine：基于 Anbox 路线独立维护，借助容器运行 Android 应用，并通过文件共享和硬件加速桥接改善桌面体验。[UOS V20 白皮书](https://www.uniontech.com/uploads/files/2024/0415/mNpg6AjcW1labtNXUH35zmAuDhy62vS57T2PSgf0.pdf)

家庭版官网把原生 UOS 生态放在主线，Windows 和安卓列为过渡性兼容。[统信 UOS 家庭版](https://home.uniontech.com/mobile) 这一定义很实用：安卓容器适合补齐轻应用，关键业务仍要逐个测试登录、推送、摄像头、定位、文件、UKey 和性能。公开资料没有提供统一、可核验的安卓兼容应用数量；V20 的能力也不能直接外推到 V25 的所有版本和 CPU 架构。

### 5. 磐石系统、USEC 与安全认证

V25 的磐石系统 2.0 主要处理系统可靠性：

- 核心系统不可变，降低关键目录被应用、用户误操作或恶意程序修改的概率；
- 系统与应用分离；
- 差分更新减少下载量；
- 快照、原子更新和回滚降低升级失败后的恢复成本。

USEC 2.0 承担更完整的安全防护，包括独立访问控制模块、D-Bus 权限和沙箱加固、企业磁盘加密、玲珑沙箱与软硬件协同防护。统信披露的“部分场景相对 SELinux 开销下降 80%”“部分国密算法性能提升 3—10 倍”来自厂商测试，应按目标硬件和策略复测。[V25 技术说明](https://www.uniontech.com/news-info/2877.html)

认证方面，V20 桌面公开披露通过 GB/T 20272-2019 第四级相关检测，密码模块达到 GM/T 0028 第二级要求；V25 在 2026 年通过安全可靠测评，公告列明“统信桌面操作系统 V25（Linux Kernel 6.6）”为 I 级，有效期三年。[中国信息安全测评中心 2026 年第 1 号公告](https://www.itsec.gov.cn/aqkkcp/cpgg/202601/t20260116_249958.html)

认证必须核对产品全名、版本、架构、证书编号和有效期。旧版证书无法自动覆盖 V25 的任意小版本，也不能代替单位自身的等保、密码应用和供应链风险评估。

### 6. AI 能力

UOS AI 从 2023 年的对话和系统操作能力，逐步扩展到云端模型、端侧模型、私有模型接入和系统级 API。V25 的 UOS AI 3.0 进一步加入全局场景感知、运行沙箱、记忆与个性化、任务拆解、多智能体协同、MCP/Skills 扩展和 AI SDK V2。

V25 还提供写作和数据分析智能体，并支持企业私有化模型。官方所称“可接入 9000+ MCP、12000+ Skills”描述的是潜在外部生态，并非系统预装或由统信逐个认证的能力。[UOS AI 3.0 发布说明](https://www.uniontech.com/news-info/2877.html)

敏感网或关键业务部署要先回答四个问题：模型运行在本地、内网还是云端；文档和提示词会发往哪里；智能体能调用哪些系统权限和应用；操作日志、审批和撤销如何实现。没有明确数据边界时，默认关闭云模型和跨应用自动执行更稳妥。

### 1. 国产 CPU 与 x86

| CPU/平台 | 常见架构 | UOS 公开支持情况 | 迁移注意点 |
|---|---|---|---|
| 飞腾 | ARM64 | FT-2000、D2000、D3000、服务器 S5000C 等已有公开适配 | x86 软件、插件和驱动需 ARM64 原生包或迁移方案 |
| 鲲鹏 | ARM64 | 鲲鹏 920/920B 等在桌面、服务器和云方案中出现 | 重点验证 GPU/NPU、网卡、存储与上层中间件 |
| 龙芯 | MIPS64、LoongArch64 | 3A3000/4000 等旧型号与 3A5000/6000、3D5000 等新型号分属不同架构 | MIPS 与 LoongArch 包不通用，不能只写“龙芯版” |
| 海光 | AMD64/x86-64 | 桌面与服务器均有广泛适配，适合需要保留 x86 生态的信创路线 | 仍要核对整机 BIOS、GPU、板卡和安全软件 |

| 申威 | SW64 | V20 有专门架构支持 | 可用应用和驱动集合通常更窄 |
| Intel / AMD | AMD64/x86-64 | V20/V25 支持，V20 HWE 面向新硬件和利旧设备 | NVIDIA/AMD GPU、Wi-Fi、指纹和电源管理需按机型测试 |

V25 官方故障文档明确指出：飞腾、鲲鹏使用 ARM64 包；海光、兆芯、Intel、AMD 使用 AMD64 包；龙芯 3A3000/4000 使用 MIPS64EL，3A5000/6000 使用 LoongArch64。`.exe` 也不能直接转换成 `.deb`。[V25 软件架构不匹配说明](https://faq.uniontech.com/desktopv25/e27f/1261)

### 2. 外设

统信维护了打印机、扫描仪等驱动目录、推荐驱动和安装文档，并建立 UHQL 硬件兼容认证体系。[统信产品支持专区](https://ecology.chinauos.com/facility/) 这能显著降低常见办公设备的查找成本，但不能把“某品牌兼容”理解为该品牌所有年代、接口和固件都能即插即用。

真实项目最容易卡住的设备包括：

- 老旧或专用打印机、扫描仪、高拍仪；
- UKey、CA 介质、电子签章、指纹仪、身份证读卡器；
- 串口设备、采集卡、加密狗、银行柜面外设；
- 独立显卡、高分屏、投影、中控、会议摄像头与音频设备；

统信公开的某部委迁移案例涉及 1 万余台打印机和扫描仪、多芯片与多整机组合，最终依靠定制驱动、云打印和 UBX 等方案完成。这类材料来自供应商，仍能说明外设利旧具有明确工程量。[某部委应用外设迁移案例](https://www.uniontech.com/case-applicationPeripheral.html)

## 七、优势、短板与真实落地痛点

### 1. 优势

- **桌面产品积累长。** deepin、DDE、自研应用和用户社区给 UOS 提供了比临时拼装发行版更连续的桌面基础。
- **多架构覆盖完整。** 国产 ARM、LoongArch、MIPS、SW64 与 x86 路线都能进入同一厂商的产品和服务体系。
- **Windows 迁移工具链细。** Wine、IE 插件、Web 插件、驱动迁移、本地虚拟化、应用虚拟化和数据迁移分别处理不同遗留问题。
- **政企管理闭环较全。** 集中域管、私有更新、企业应用商店、云盘和现场服务适合大规模终端交付。
- **新架构方向清楚。** Linux 6.6、不可变核心、原子更新、玲珑沙箱和 AI 平台都对准了桌面 Linux 的长期问题。
- **行业案例覆盖广。** 政务、金融、教育、能源、运营商和专用终端都有公开采购或交付记录。

### 2. 短板与痛点

1. **跨 CPU 架构扩大适配矩阵。** 一个 AMD64 可用的 DEB、Wine 包或驱动，并不自动支持 ARM64 和 LoongArch。多 CPU 采购会增加镜像、仓库、测试和工单复杂度。
2. **Windows 专有技术仍是硬阻断。** .NET 特定版本、COM/OLE、DirectX、VBA、IE/ActiveX、内核服务、加密狗和闭源驱动无法靠一个兼容引擎全部解决。
3. **文档“能打开”不等于版式正确。** 字体、分页、公式、批注修订、嵌入对象、宏、OFD/PDF 转换、电子签章和打印结果都要用真实文件验收。
4. **外设长尾很长。** 官方目录和迁移工具降低了风险，老旧设备、专用协议、离线环境和厂商停产设备仍可能没有可用驱动。
5. **适配认证会过期。** 应用、UOS 小版本、内核、驱动或固件升级后都可能产生回归。互认证证书只能作为测试入场条件。
6. **过渡方案带来双栈成本。** Windows 虚拟化或远程应用保住业务连续性，也带回 Windows 许可、镜像补丁、病毒防护、服务器资源和数据跨域治理。
7. **终端管控需要重建。** 现有 AD/GPO、EDR、DLP、VPN、零信任、CA、补丁、资产和日志平台未必能按原方式运行。
8. **服务台和用户习惯会形成隐性成本。** 快捷键、文件路径、安装权限、打印流程、软件名称和故障排查都发生变化。先培训服务台，再培训终端用户，通常更有效。

## 八、主流行业怎么落地

### 1. 政务

常见场景是电子公文、OFD/PDF、CA/UKey、签章、政务外网/内网、浏览器业务、打印扫描和集中终端管理。中国政府采购网的 CA 下载页已提供统信 UOS 专业版 ARM64 驱动与控件，说明中央政府采购交易客户端存在实际适配。[中国政府采购网 CA 驱动页](https://pub.ccgp.gov.cn/loginx/ca_drv.htm)

### 2. 国企与能源

国企通常采用“终端操作系统 + 域管 + 私有应用商店 + 更新平台 + 迁移服务”。公开报道显示，中国邮政 30 万套桌面操作系统集采中统信为主选供应商；这一数字来自媒体报道，缺少可直接检索的采购方原始中标全文，应按报道口径理解。[北京日报客户端报道](https://wap.bjd.com.cn/news/2023/09/04/10552297.shtml)

### 3. 教育

教育版覆盖办公教学、电子教室、网络同传还原、考试、机房和数据中心。燕山大学 2023 年面向全校提供统信 UOS 授权，2024 年启动信创运营中心和适配迁移验证中心，并配套 WPS、中望 CAD、福昕 PDF、MWorks 等授权。[燕山大学授权通知](https://notice.ysu.edu.cn/index/tzgg/jfjg/xxjszx/21.htm) [燕山大学适配中心启动](https://www.ysu.edu.cn/news/info/5503/24331.htm)

统信后续披露该校 304 间多媒体教室、约 700 台办公教学电脑完成替换，适配 137 款教学应用，并处理老显卡、投影和中控问题。数字来自供应商案例，适合与校方材料交叉阅读。[燕山大学案例](https://www.uniontech.com/m/news-info/2617.html)

### 4. 金融

金融桌面和柜面会集中遇到高拍仪、存折打印机、密码键盘、指纹仪、双目摄像头、电子验印、柜外清和安全认证。统信已公开与多家柜面应用和外设厂商合作的解决方案。[银行柜面系统方案](https://www.uniontech.com/case-bankCounterSystem.html)

中国农业银行 2024 年采购 4200 套统信云桌面许可，同时采购 519 人天现场开发服务，总价 588.66 万元。这个采购结构很能说明问题：许可证并非主要工作量的全部，现场开发和适配要单独预算。[中国农业银行采购结果](https://www.abchina.com/cn/aboutabc/cg/Purchase/202407/t20240701_2426894.htm)

桂林银行 2024 年采购统信桌面、服务器和集中域管平台授权，体现了金融项目常见的成套交付形态。[桂林银行中标公告](https://www.guilinbank.com.cn/api-portal/page-home/article/10123639)

厂商曾宣称金融桌面市占率 85% 以上，但公开资料没有给出第三方原始样本、分母和计算方法。这个比例不适合作为选型结论。

## 九、与银河麒麟的关键对比

UOS V25 和银河麒麟 V11 已经高度同构：两者均采用 Linux 6.6，均引入不可变核心系统、应用与系统隔离、原子更新/回退、新应用包格式、AI 子系统和多架构支持。[银河麒麟 V11 产品页](https://www.kylinos.cn/productPc/desktop/desktopMainV11/)

| 维度 | 统信 UOS | 银河麒麟 | 选型提示 |
|---|---|---|---|
| 当前桌面主线 | V25，2026-04-15 发布，Linux 6.6 | V11，2025-08-26 发布，Linux 6.6 | 存量环境仍以 V20/V10 居多，新旧代际应并行 PoC |
| 社区与桌面 | deepin、DDE | openKylin、UKUI/新显示体系 | UOS 的桌面社区和 DDE 路线更连续；已有麒麟栈的组织延续成本更低 |

## 十、从 Windows 迁移的风险清单

| 风险 | 典型阻断点 | 验收动作 |
|---|---|---|
| CPU 架构变化 | x86 EXE、DLL、驱动迁到 ARM/LoongArch | 把 OS 迁移和 CPU 迁移拆开测试；为阻断应用保留 x86 或远程应用路线 |
| C/S 专有软件 | .NET、COM/OLE、DirectX、服务、许可证守护 | 按“原生—Web—兼容层—虚拟化—保留 Windows”分级 |
| IE/ActiveX | OA、网银、税务、社保、签章控件 | 兼容浏览器只作过渡，给去 ActiveX 改造设退出日期 |
| 文档兼容 | VBA、字体、分页、公式、嵌入对象、批注修订 | 建立真实文档回归库，逐页比对屏显、导出和打印 |
| 外设与介质 | UKey、打印扫描、高拍仪、读卡器、串口、加密狗 | 按 VID/PID、固件、驱动和 CPU 建白名单，测试热插拔与休眠唤醒 |
| 身份与安全 | AD/GPO、LDAP、CA、VPN、EDR、DLP、零信任 | 验证入域、单点登录、密码策略、证书续期、策略下发和日志回传 |
| 数据迁移 | NTFS ACL、EFS/BitLocker、长路径、大小写、邮件档案 | 先解密与备份，再做数量、哈希和业务抽样核验 |
| 性能稳定 | Wine、高分屏、GPU/CAD、会议、批量补丁 | 按岗位建立基线，覆盖峰值、断网、升级和回退 |
| 授权合规 | Windows 应用、字体、插件、虚拟机另行许可 | 要求 ISV 书面确认 Linux 兼容运行权和支持责任 |
| AI 数据治理 | 云模型上传文档，Agent 跨应用执行 | 明确模型位置、数据分级、权限、审批、日志和撤销 |
| 人员流程 | 使用习惯、服务台知识、安装权限变化 | 先培训服务台和关键用户，再推广到普通岗位 |

## 十一、实施与选型建议

### 1. 先做四张清单

- **人员与岗位清单：** 谁使用什么业务，停机能承受多久，是否需要外勤、会议、设计或柜面设备。
- **应用清单：** 应用名称、版本、厂商、技术栈、插件、数据库、许可证、业务等级和替代路线。
- **整机与外设清单：** CPU、BIOS/固件、GPU、网卡、打印扫描、UKey、VID/PID 和驱动版本。
- **数据与文档清单：** 数据规模、加密状态、权限、邮件档案、字体、模板、宏、签章和打印样本。

### 2. 应用分级与路线

| 级别 | 定义 | 放行原则 |
|---|---|---|
| P0 | 停用会中断核心业务 | 任一关键路径失败即暂停该场景全量迁移 |
| P1 | 重要，可短时回退 | 必须有明确回退和人工替代流程 |
| P2 | 通用办公 | 用真实文档、会议和打印任务验收 |
| P3 | 可替代或淘汰 | 优先换成原生或标准 Web 应用 |

迁移路线按以下顺序选择：原生应用 → 标准 Web 应用 → 兼容层 → 应用虚拟化或远程 Windows → 双系统/保留 Windows 例外。每个过渡方案都要写退出条件和期限。

### 3. 建立组合矩阵

每条测试记录至少锁定：

`OS 产品与小版本 + 内核 + CPU 架构 + 整机型号 + BIOS/固件 + 应用版本 + 外设型号 + 驱动/安全软件版本`

互认证证书只能让组合进入测试。真实业务验收决定能否放行。

### 4. PoC 与推广

1. 在实验室验证功能、性能、安全、断网、升级回退、备份恢复、外设热插拔和高负载连续运行。
2. 选择领导、综合办公、财务、档案、设计、柜面、运维和外勤等代表岗位试点。
3. 试点跨过至少一个完整业务周期，不能停留在开机、浏览器和 WPS 演示。
4. 保留可恢复的 Windows 环境；数据迁移完成数量、哈希和抽样核验后，再切换默认入口。
5. 按部门、区域或设备批次推广；P0 故障、文档错误、认证失败、关键外设不可用或工单异常上升时暂停扩面。

### 5. 推荐评分模型

| 维度 | 权重 |
|---|---:|
| 关键应用与业务兼容 | 40% |
| 整机、外设与 CPU 架构兼容 | 20% |
| 安全、域管和现有基础设施集成 | 15% |
| 稳定性与性能 | 10% |
| 生命周期、服务与迁移支持 | 10% |
| 用户体验和培训成本 | 5% |

P0 应用、身份认证、安全客户端和关键外设应设置为否决项，不能由其他维度高分抵消。

### 6. 不同场景的选型倾向

- **通用桌面、Windows 应用过渡较多：** 优先把 UOS 纳入 PoC，重点测试 Deepin-Wine、打印、UKey 和集中管控。
- **已有银河麒麟存量与管理体系：** 优先评估延续银河麒麟，减少镜像、补丁、培训和服务台的异构成本。
- **新硬件、原子更新和 AI 有明确需求：** 测试 UOS V25 与银河麒麟 V11；同时保留 V20/V10 成熟代作为对照。
- **数据库、中间件、容器、GPU/NPU 或高可用：** 单独做服务器选型，依据 ISV 认证和压测结果决策。
- **大型组织需要双供应商：** 按业务域或设备批次划分，不在同一标准桌面中随机混装。

合同应固化产品版本、CPU 架构、兼容清单、驻场人天、问题响应、漏洞修复、补丁频率、离线更新、升级权、授权迁移、停服日期、回退责任和过渡方案的 Windows 许可。

## 十二、外部研判

统信 UOS 已经跨过“有没有产品”的阶段，竞争焦点转向三个更难量化的指标：关键岗位真用率、升级后的持续兼容率、单位内部每百台终端的运维成本。

UOS V25 的不可变系统、玲珑和 AI 平台有清晰方向，但新架构也会改变旧 DEB 包、管理脚本、安全代理和运维习惯。成熟单位适合让 V20 与 V25 双轨一段时间，用业务矩阵决定升级，而非只按发布时间切换。

Windows 兼容引擎、安卓容器和虚拟化的价值在于降低切换中断。它们承担过渡角色时很有效；如果五年后核心业务仍全部依赖 Windows 兼容层，迁移只完成了终端表面替换，应用和运维债务仍然存在。

银河麒麟与统信的产品方向越来越接近。未来的差异更可能出现在具体机型驱动、ISV 响应、补丁质量、驻场团队、合同承诺和存量体系，而不是功能列表。对采购方最有利的方式，是把双方放进同一套可复现测试矩阵，用故障记录和总拥有成本说话。

## 十三、未能验证

- 2026 年 7 月公告提出的股权回转是否已经完成工商变更，公开材料截至 9 月 7 日没有给出最终结果；当前完整持股比例、表决权安排和统信最终实际控制人也无法从公开文件完整还原。
- 统信“千万级适配”的去重产品数、活跃使用数和各 CPU 架构的功能完整率没有公开原始数据。
- 金融桌面“85% 市占率”等比例缺少可复核的第三方样本、分母和方法。
- 安卓兼容应用没有统一、可核验的当前数量；V25 各 SKU、各 CPU 的 UEngine 支持范围也未见完整公开表。
- V25 桌面应用商店、玲珑和 Windows 兼容引擎的数量均为厂商口径，缺少统一第三方可用性基准。
- 统信与银河麒麟之间没有公开的同机构、同硬件、同应用集、同版本横向性能和兼容率测试。
- 多个行业案例由供应商披露，缺少采购方验收报告；文章已优先采用采购公告、政府文件和校方材料交叉验证。
- V25 与银河麒麟 V11 的具体安全证书、架构覆盖和有效期仍需在采购阶段索取原件。
