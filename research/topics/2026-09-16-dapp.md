## 一、先给结论

**DApp（decentralized application）能被独立核验的部分，是部署在共享账本上、按事先写明的规则改状态的那段代码。** 用户看见的网站、RPC、索引器和应用商店，默认仍由公司运营。2026 年能量到公开规模的品类，集中在兑换、借贷、质押、稳定币和永续合约。

![常见入门图把 DApp 画成四步：打开应用、连接钱包、调用智能合约、由多个节点共同记账](/research/dapp/what-is-dapp.jpg)

*常见教学图：用户路径是「打开应用 → 连接钱包 → 调用合约 → 链上记账」。能核验的是后两步的状态变更；前两步的网站和默认 RPC 仍常由公司提供。*

可核验的要点：

1. **定义至少有三套口径。** 2014 年 Gavin Wood 把 ĐApp 写成四件套里的统一界面；ethereum.org 现行开发者文档写成「去中心化网络上的智能合约 + 前端」；市场统计则把凡是连钱包的网页都算进去。三套口径对不上，用户数和「去中心化程度」就会被吹大。
2. **发展路径已经被公开事故标过几次。** 2016 年 The DAO 被盗后硬分叉；2017 年 CryptoKitties 堵死以太坊；2020 年流动性挖矿把锁仓做大；2022 年 Terra / 跨链桥 / 游戏经济连续出事。扩容把手续费打下来了，没有自动把非金融应用做成日用软件。
3. **2026-09-16 快照：链上 TVL 约 860 亿美元，以太坊约 490 亿美元。** 协议锁仓前排是 Lido（约 233 亿美元）、Aave（约 175 亿美元）、Morpho Blue（约 98 亿美元）。现货 DEX 24 小时成交里 Uniswap V3+V4 合计约 33.0 亿美元；Hyperliquid 公共 API 当天原生永续名义成交约 99.8 亿美元。锁仓排名和成交排名不是同一张表。
4. **头部项目多数仍有公司、基金会、多签或升级入口。** 用户用钱包签名，不等于协议没有人能改规则。前端挂了，懂合约的人仍可用地址交互；普通用户会觉得「应用没了」。
5. **对大陆读者：** 拆合约权限、看依赖和核对公开数据，可以跟进。用 DEX、借贷、永续、打新和任何面向境内的虚拟货币服务，按《银发〔2026〕42 号》观望。

## 二、事实层

### 1. 这个词在不同文本里指什么

| 口径 | 文本 | 它把 DApp 定义成什么 | 今天还成立的部分 |
|---|---|---|---|
| 应用层界面 | Gavin Wood，[ÐApps: What Web 3.0 Looks Like](https://gavwood.com/dappsweb3.html)，2014-04-17 | 浏览器把静态发布、加密消息、共识交易收成 ĐApp；URI 经共识解析成前端哈希 | 钱包 + 网页还在；名字解析和前端托管大多没上共识引擎 |
| 平台意图 | [Ethereum 白皮书](https://ethereum.org/whitepaper/) | 用图灵完备链让人写任意所有权规则、交易格式和状态转移；点名 Namecoin、金融合约、DAO | 通用合约平台成立；「两行代码复刻 Namecoin」是示例，不是产品清单 |
| 现行官方（开发） | [ethereum.org Technical introduction to dapps](https://ethereum.org/developers/docs/dapps/) | 后端跑在去中心化点对点网络，前端可用任意语言，也可以放到 IPFS | 合约在链上；前端「可以」去中心化，文档没说「默认已经如此」 |
| 现行官方（消费） | [ethereum.org Ethereum applications](https://ethereum.org/what-are-apps/) | 逻辑在以太坊上，所以叫 dapp；对照表写控制者是 Nobody、不可被审查 | 宣传句。同站开发者文档另列维护难、性能差、拥堵、体验差、**重新中心化**五条代价 |
| 资产接口 | [EIP-20](https://eips.ethereum.org/EIPS/eip-20)，2015-11-19 | 代币标准 API，方便钱包和去中心化交易所复用 | ERC-20 成为多数金融 DApp 的共同零件 |

ethereum.org 开发者页写得很具体：DApp 的后端是智能合约；合约一旦部署就很难改；恶意者难以针对单个应用做传统停服。同一页也写：为了好用，密钥、前端和业务逻辑可能回到中心化服务器，**中心化会消掉区块链相对传统模型的许多（若非全部）优点**。

消费页上的「Nobody / 关不掉」和开发者页上的这条警告，要对照着读。口号层的讨论见站内 [Web3 到底指什么](/articles/research/topics/what-is-web3)。

### 3. 用户实际碰到的是一条链路，不是一个程序

```text
界面层    网站 / App / 钱包内嵌浏览器（多在 Cloudflare、Vercel、应用商店）
钱包层    私钥或助记词在用户设备；默认 RPC 仍常指向 Infura / Alchemy 等
访问层    JSON-RPC、索引器、区块浏览器
合约层    兑换池、借贷池、金库、治理、代理升级
资产层    ERC-20 / 等价代币、LP 凭证、质押凭证、仓位 NFT
依赖层    预言机、跨链桥、稳定币发行人、排序器 / 出块者
法律层    基金会、开发公司、所在地法、应用商店与支付通道
```

最小可运行的「链上应用」只要合约地址和能发交易的密钥。最小**好用**的产品还要：托管前端、公开 RPC、价格源、区块浏览器，以及一份能讲清管理员权限的文档。

Moxie Marlinspike 2022 年的实验把这件事做了一次可复现演示：他写的 dapp 是普通 React 站点；钱包读余额走 Infura，返回 JSON 没有节点签名。详见 [My first impressions of web3](https://moxie.org/2022/01/07/web3-first-impressions.html)。2025-10-20 AWS `us-east-1` 故障时，Infura 多条网络端点受影响，MetaMask 出现余额显示为 0，链本身仍在出块。访问层单点故障的材料，见 [Web3 到底指什么](/articles/research/topics/what-is-web3)。

Aave V4 在 2026-03-30 上线以太坊，DefiLlama 子项 `Aave V4` 锁仓当日约 4.0 亿美元量级，远小于 V3。新版本上线不等于资金已经搬家。

### 6. 两类「头部」不要并成一句

Uniswap、Aave、Lido 是**合约协议**：状态在既有公链上，前端可替换。Hyperliquid 是**应用链**：撮合、撤单、清算跑在为自己吞吐量设计的 L1 上，用户资产往往先过桥。Pump.fun / PumpSwap 是**发射与成交绑定的终端**：合约在 Solana 上，产品形态接近发行工厂。

三类都能连钱包，安全模型和退出路径不同。桥、排序器和发射台管理员，经常比 AMM 公式本身更能决定用户能不能把钱转走。

## 三、结构分析

### 1. 为什么规模落在金融

链给应用的稀缺能力是：**多方都能验证的余额，以及按公开规则自动清算。** 兑换、借贷、质押、永续都直接消耗这一种能力。游戏要帧率、匹配和内容更新；社交要推送、审核和搜索；内容站要 SEO 和评论。这些需求与「每个节点都执行同一笔交易」冲突。ethereum.org 开发者文档把性能开销和拥堵写成缺点，不是旁注。

结果就是：融资叙事可以轮换 GameFi、SocialFi、DePIN，公开能复核的锁仓和费用，仍主要来自资金状态机。

### 2. 商业模式

| 角色 | 常见收入 | 常见风险转嫁给谁 |
|---|---|---|
| AMM / DEX | 交易手续费，部分归 LP，部分归协议 | 无常损失、MEV、假代币、授权钓鱼 |
| 借贷 | 利差、清算罚金 | 预言机、坏账、治理风险参数 |
| 流动质押 | 质押奖励抽成（Lido 文档长期写 10%） | 验证者惩罚、提款排队、凭证脱锚 |
| 永续 CLOB | 交易费、清算 | 高杠杆、桥、保险基金 |
| 发射台 | 发行费、自营做市 | 合约后门、流动性撤出、机器人抢跑 |
| 前端运营方 | 接口费、默认路由返佣、代币 | 域名劫持、RPC 审查、地区开关 |

代币激励能把锁仓暂时堆高。Compound 2020 年之后的模仿盘证明：奖励一停，地址和 TVL 可以一起掉。看协议要看**停发代币之后还有没有人付费使用**。

### 3. 可组合性和管理员权限是同一枚硬币的两面

ERC-20 让 Uniswap 不必为每个新币改协议，Aave 也不必自建钱包。这是白皮书里「应用互相调用」真正落地的部分。代价是：授权一次，恶意合约可以反复 `transferFrom`；升级代理可以在用户不知情时改逻辑；暂停开关可以在「去中心化」产品里停兑。

外部能确认的是：头部协议通常公布多签、时间锁或治理票。暂未看到公开、统一的审计口径证明「头部 DApp 已经普遍销毁管理员密钥」。

### 4. 和中心化交易所如何分工

CEX 卖法币通道、客服、法币计价的订单簿和托管。DApp 卖可转移的仓位和可核验的清算。用户常常把资产从交易所提到钱包，再进 Uniswap / Aave / Hyperliquid。两条系统互相喂单，也互相承接对方的故障：交易所停提时人往链上走；桥或合约出事时人往托管走。

## 四、外部研判

外部能确认的是：2026 年的 DApp 市场，已经从「什么都能上链」收成少数几种资金协议，外加一条高吞吐的永续应用链和若干发行工厂。消费宣传仍在用 2014 年的浏览器图景。

一种可能的外部解读是：对开发者，先问状态要不要多方共享、要不要抗单点撤销。只需要账号、推送和内容分发时，加一个 Connect Wallet 不会自动变成新应用品类。对读者，有用的动作是看合约权限、看前端域名、看默认 RPC，以及分清 TVL、成交量和费用各在量什么。

跟进判断：

| 读者位置 | 判断 | 下一步 |
|---|---|---|
| 想理解应用层和头部格局 | **跟进** | 用 DefiLlama 分功能看锁仓 / 成交 / 费用，用区块浏览器核对管理员和代理 |
| 开发者在测试网学习合约与钱包接入 | **跟进** | 停在 Sepolia 等测试网；主网当阅读对象 |
| 把 DappRadar 用户数、融资估值当日活 | **不跟进** | 这些口径无法在同一套审计下复核 |
| 大陆居民使用 DEX、借贷、永续、发射台 | **观望** | 按 42 号文把相关业务当禁止项 |
| 给内容站或工具站「改成 DApp」 | **不跟进**（默认） | 内容核验用哈希和时间戳即可；整站上链的取舍见 [2aran.com 能不能上链](/articles/research/topics/2aran-onchain-content-site) |

反证：若后续公开数据里，非金融类协议的独立费用和可核验日活稳定超过头部 DEX / 借贷，或主流钱包默认改为可验证轻客户端且前端普遍内容寻址，则「规模化的仍是金融状态机 / 访问层默认中心化」这两条要改写。暂未看到这样的截面。

## 五、未能验证

- 全球 DApp 独立日活、月活。DappRadar 等商业榜单的去重规则、是否计入机器人、是否把钱包打开算一次使用，公开材料不够用来当统计定义。
- Polymarket 2026 年 9 月的链上结算量、链下撮合占比和独立地址数。2025–2026 上半年有多家研报给出月成交，口径并不统一，当日未用同一接口复核。
- NFT 市场 2026 年真实成交里，有多少是洗盘、同一控制人互转。
- 游戏与社交应用的留存。Axie、CryptoKitties、各类链上社交都有过峰值截图，缺少可连续审计的队列。
- Lido、Aave、Uniswap 的最终控制人与基金会、开发公司、DAO 金库之间的完整权益穿透。
- Hyperliquid HIP-3 / HIP-4 额外市场的成交是否已计入上方 `universe` 合计；本次只加总官方 `metaAndAssetCtxs` 返回的 234 个原生市场。
- 「8265 个协议」里有多少是已死亡合约、测试分叉或同一产品的多链副本。
