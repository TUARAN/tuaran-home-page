> **范围说明：**以下整理针对中国大陆企业向手机用户下发短信、5G 消息和相近通道，依据截至 2026 年 9 月 16 日可以查到的部门规章、编号计划和主流云厂商公开文档。不构成法律意见或通道采购建议。海外 Twilio 等路径见[CPaaS 行业演进](/articles/research/topics/cpaas-industry-evolution)。

## 一、先给结论

**企业要给用户发验证码、通知或营销短信，合法入口是端口类短信：先有发送主体，再有码号、签名和模板，最后才是 API。** IP 消息走互联网，不自动等于这条短信通道。

可以直接核对的六点：

1. **短信是公用通信网上的电信服务。** 工信部 74 号令把通信短信息服务定义为：利用公用通信网络向固话、手机等终端传输有限长度信息，**不含互联网信息服务**。
2. **码号在短信场景里主要是 106 开头的短消息类服务接入代码。** 它由国家所有、审批使用。用户手机上显示的发送方，通常是这段码号再加扩展位。
3. **营销和通知不能混用同一端口码号。** 商业短信要事先取得接收方同意或请求的材料，并提供拒收方式；业务管理和服务短信走另一类端口。
4. **大多数企业不会自己去申请 106 码号。** 它们把资质、签名、模板交给阿里云、腾讯云、华为云或梦网这类平台，由持证服务商对接三大运营商。
5. **“IP 消息”至少有三层含义，不能混用：** 技术上的 IP 承载（5G 消息 / RCS 就属于这一类）、74 号令第四十一条所说的“具有短信特征的互联网递送”、以及产业里常说的绕开 106 端口、难以溯源的灰色通道。
6. **5G 消息没有替代短信。** 它是运营商可控的富媒体通道，企业通过 Chatbot / MaaP 接入，终端不支持时可以回落成普通短信。

## 二、事实层

### 1. 用户手机上同时存在几类“消息”

| 名称 | 走哪条路 | 用户怎么看到 | 谁管通道 | 典型用途 |
|---|---|---|---|---|
| 点对点短信 | 手机号 ↔ 短信中心（SMSC） | 普通手机号发来 | 基础电信企业 | 人与人互发 |
| 端口类短信 | 企业 → SP / 云平台 → 运营商网关 → SMSC | 106 开头号码 +【签名】 | 工信部 / 通信管理局 + 基础电信企业 | 验证码、物流、账单、营销 |
| 5G 消息（RCS） | 运营商 RCS / MaaP 平台，IP 承载 | 原生短信窗口里的卡片、按钮、富媒体 | 三大运营商，基于 GSMA RCS Universal Profile | 行业 Chatbot、通知升级、交互服务 |
| 厂商系统推送 | 互联网 + 手机厂商推送通道 | App 通知栏，通常不进短信收件箱 | 华为、小米、OPPO、vivo 等 | App 唤醒、订单状态、运营推送 |
| 即时通信 | 微信、企微、钉钉、飞书等 | App 会话 | 互联网平台 | 日常沟通、服务号、工作流 |

74 号令第四十条把短信限定在公用通信网；第四十一条又把“利用互联网向通信终端提供具有通信短信息特征的信息递送”**参照短信规定执行**。官方文本没有单独定义“IP 消息”四个字。产业讨论里的 IP 消息，多半落在第四十一条和厂商推送这两块，详见[IP 消息监管与 5G 消息合作僵局](/articles/research/topics/ip-messaging-rcs-standoff)。

### 2. 码号是国家资源，106 是短信专用号段

《电信网码号资源管理办法》规定：码号资源由数字、符号组成，用于实现电信功能的用户编号和网络编号；**码号资源属于国家所有**；未经工信部或省级通信管理局批准，任何单位或个人不得擅自启用。短信相关的审批事项明确包括“短消息类服务接入代码”。

《电信网编号计划（2017 年版）》把 106 规划为短消息类服务接入代码，采用不等位长编码。服务主体拿到一个接入代码后可以扩展，扩展后的总位长取决于基础运营商网络能否支撑。用户看到的长串 106 号码，通常是**批准码号 + 子端口 / 扩展位**。

| 号段 | 用途（2017 年版编号计划） | 谁分配 | 经营许可 |
|---|---|---|---|
| 1062 | 省内经营性短消息类服务 | 省通信管理局，各省可重用 | 须有增值电信业务经营许可 |
| 10630–10634 | 省内非经营性接入平台 | 省通信管理局 | 平台经营者须有许可 |
| 10635–10638 | 省内非经营性短消息类服务 | 省通信管理局 | 内容提供主体可不办许可 |
| 10639 | 省内公益性 | 省通信管理局 | 公益单位使用 |
| 1064 | 机器通信（非语音），使用位长 13 位 | 工信部 | 机器通信专用，不是普通企业短信端口 |
| 1065 | 基础运营商自营短消息类服务 | 工信部 | 运营商自营 |
| 1066 | 跨省 / 全国经营性 | 工信部 | 须有许可 |
| 1068 | 跨省 / 全国非经营性接入平台 | 工信部 | 平台经营者须有许可 |
| 10690–10694 | 跨省 / 全国非经营性接入平台 | 工信部 | 可扩展标识后面的内容提供主体 |
| 10695、10697 | 备用 | — | — |
| 10696、10698 | 跨省 / 全国非经营性短消息类服务 | 10696 委托各省；10698 由工信部 | 内容提供主体可不办许可 |
| 10699 | 跨省 / 全国公益性 | 工信部 | 公益单位使用 |
| 1060、1061、1067 | 备用 | — | — |

编号计划对“经营性”的口径很窄：**除通信费外，还允许向用户收通信信息费**。点播短信、订购类业务走这条线。银行验证码、快递通知、会员营销对用户通常只走通信通道、不另收信息费，对应的是**非经营性**号段。所以日常看到的验证码，大量落在 1068 / 1069 开头。

这和 74 号令按**内容用途**分的三类不是同一把尺子：

| 74 号令分类 | 法定含义 | 额外硬约束 |
|---|---|---|
| 商业性通信短信息 | 介绍、推销商品、服务或商业投资机会 | 发送方须提供接收方同意或请求的材料；须告知拒收方式；发现未同意或已拒收后不得再传；须管理时段和频次 |
| 业务管理和服务性通信短信息 | 操作验证、系统登录、业务提醒、民生服务等 | 不得与商业短信混用端口码号 |
| 公益性通信短信息 | 政府部门等发送的非盈利公共信息 | 常规发送需提前向电信管理机构报备；应急可先发后补 |

把“经营性码号”和“商业性短信”当成一件事，会看错通道。1069 非经营性端口照样可以发营销内容，只要内容被认定为商业短信，同意材料、签名、拒收和端口隔离一样要满足。

### 3. 提供短信服务的两张证

74 号令第四条：提供通信短信息服务，应当依法取得**电信业务经营许可**和**电信网码号资源使用许可**。基础电信企业不得为未取得这两项许可的组织、个人提供端口类接入。

行业里说的 SP 证，对应《电信业务分类目录（2015 年版）》第二类增值电信业务里的 **B25 信息服务业务（不含互联网信息服务）**。跨省经营向工信部申请，省内经营向省通信管理局申请。码号申请入口是工信部政务服务里的“电信网码号资源使用和调整审批”。江西省通信管理局公开指南写明：1062 省内经营性申请人须持有含“信息服务业务（不含固定网电信信息服务和互联网信息服务）”的增值电信业务经营许可证，且许可证剩余有效期不少于一年。

普通电商、银行、物流公司要发短信，多数并不是自己去办这两张证。它们是 74 号令里的**发送方**；持证公司是**传输方 / 通信短信息服务提供者**。

### 4. 企业实际怎么下发

公开可核对的路径只有三条。

**路径 A：自己当 SP。** 办增值电信业务经营许可，申请 106 码号，再与中国移动、中国联通、中国电信分别对接网关。移动侧公开企业规范是 CMPP（China Mobile Peer to Peer，现行公开文本可见 3.0）；联通侧行业通行接口是 SGIP；电信侧行业通行接口是 SMGP。企业系统提交下行（MT），接收上行（MO）和状态报告（DLR）。适合日均量极大、要自己控路由和子端口的银行、互联网平台和云通信厂商。

**路径 B：买云通信 / CPaaS。** 这是当前中小企业和大多数互联网业务的默认做法。阿里云、腾讯云公开流程一致：开通服务 → 提交签名归属方资质 → 申请签名 → 申请模板 → 等审核和运营商实名报备 → 控制台或 API 发送。用户收到的号码仍是 106 开头，由平台侧通道分配，阿里云、华为云都写明国内号码通常不支持企业指定固定号码。

**路径 C：5G 消息 Chatbot。** 企业向运营商或中移互联网等平台签约，注册 Chatbot，审核模板后，经 MaaP 接口下发卡片、菜单、媒体。中国电信与中国联通《5G 消息业务平台行业客户接入接口技术规范》写明：可预设是否转短信、是否离线存储；终端不是 5G 消息终端时，允许回落的消息会变成普通短信。中国移动“新消息”公开页面把行业接入写成：联系客户经理签约 → 登录平台注册 Chatbot → 群发或交互。

路径 B 的产品分类，云厂商已经产品化，和 74 号令三类大体对应：

| 云厂商产品名 | 对应 74 号令 | 公开规则（以厂商文档为准） |
|---|---|---|
| 验证码 | 业务管理和服务性 | 须含“验证码”等关键词；阿里云限制同签名同号码 1 条/分、5 条/小时、10 条/天 |
| 通知 / 短信通知 | 业务管理和服务性 | 禁止夹带营销；节日关怀、促销要改走推广类 |
| 推广 / 营销 | 商业性 | 腾讯云：仅企业认证可用；须以“拒收请回复 R”结尾；发送时段 8:00–22:00；禁止给非会员发营销。华为云写的推广时段是 8:00–21:00 |

74 号令第二十四条只要求服务提供者规范管理商业短信的**时段和频次**，没有写死全国统一钟点。8:00–22:00 或 8:00–21:00 是平台和运营商执行层规则，采购时以签约通道为准。

一条完整的端口类短信，用户看到的通常是：

```text
【公司简称】您的验证码是 123456，5 分钟内有效。
发送方显示：1069xxxxxxxxxx
```

签名规则由 74 号令第十九条托底：须用发送方全称、简称或依法取得的注册商标等，真实、清晰标识身份。2026 年发布的推荐性国家标准 GB/T 47533-2026《通信短信息服务内容提供者签名要求》进一步规定端口类签名管理、审核和投诉处理。腾讯云公开要求国内签名 2–12 个字，显示形态为【签名内容】。

## 三、结构分析

### 1. 钱和责任怎么分

```text
监管：工信部 / 省通信管理局
        │ 许可、码号、检查、申诉
        ▼
基础电信企业：移动 / 联通 / 电信
        │ 网关接入、实名核验、防侵扰、通道关停
        ▼
短信服务提供者（传输方）
  SP / 梦网 / 阿里云 / 腾讯云 / 华为云 / 容联 等
        │ 子端口、签名库、模板审核、路由、回执
        ▼
发送方：银行、电商、政务、SaaS
        │ 用户名单、同意材料、业务内容
        ▼
接收方：手机用户
```

发送方对内容负责（74 号令第六条：用户对使用短信服务发送的内容及其后果负责）。传输方负责许可、码号使用、签名传输、同意材料的形式审查、留存和拒收。基础电信企业负责接入管理和定期核验。新华社 2026 年对 74 号令的报道写明：传输方对发送方承诺材料做**形式审查**，不对其真实性做实质审查；发送方对材料真实性负责。

这解释了为什么云厂商死卡资质、签名、模板：它们把监管义务产品化了。企业买到的是已经接入三网、已经承担传输方义务的通道。单价只是账单上的一行。

### 2. 子端口才是日常运营单位

工信部批的是码号结构、位长、用途、范围和期限。服务商再给每个发送方分配**子端口码号和用途**，并留存到服务终止后不少于 6 个月。商业短信和服务短信不得混用端口，所以同一家银行通常至少有两套号：一套走验证码 / 动账，一套走理财推销。

用户投诉时，监管和运营商按发送端码号回溯。假码号、缺码号、冒用码号属于 74 号令第十二条明确禁止的传输行为。这也是灰色 IP 通道被盯上的原因：它把“看起来像短信”的内容递到手机上，却没有可审批、可留存、可关停的发送端码号。

### 3. 生态分层，价格战发生在中间层

| 层 | 角色 | 卖什么 | 约束 |
|---|---|---|---|
| 网络层 | 三大运营商 | 短信中心、网关、码号落地、5G 消息平台 | 反诈考核、投诉量、接入资格 |
| 持证通道层 | 全网 / 省内 SP、云通信上市公司 | 106 端口、三网路由、签名报备 | 许可年报、码号年报、通道被关风险 |
| 云封装层 | 阿里云、腾讯云、华为云 | 控制台、API、套餐、与云产品打包 | 上游通道成本、审核时效 |
| 行业集成层 | 营销云、CRM、验证码服务、5G 阅信 | 人群、频控、回落、效果报表 | 必须继续遵守同意和模板规则 |
| 终端层 | 手机厂商 | 短信 App、RCS 适配、系统推送 | 进网许可、与运营商的商业签约 |

梦网这类老牌云通信公司同时做传统行业短信和 5G 阅信，位置在持证通道层和行业集成层之间，详见[梦网云通信公司调研](/articles/research/companies/montnets)。互联网云厂商用开发者账号把路径 B 做成自助开通。运营商自己做 5G 消息和政企短信，既是上游，也是竞品。

个人主体在国内很难把营销短信做成稳定业务。腾讯云公开写：个人认证不支持国内营销短信；个人签名难以完成运营商实名报备。验证码、通知也要企业资质或授权委托。站内此前对个人 Agent 接短信的判断，仍然成立，见[WorkBuddy 短信通道调研](/articles/research/topics/workbuddy-sms-rcs-channel)。

### 4. IP 消息为什么会和码号绑在一起吵

技术上，5G 消息本身就是 IP 承载的融合消息，YD/T 2424-2012 等行业标准从 2010 年代就在写“基于 IP 的融合消息”。运营商接受这条 IP 通道，因为它可实名、可审核、可结算、可回落成 106 短信。

产业冲突里的 IP 消息，指的是另一头：内容经过互联网到达手机，显示形态接近短信或强提醒，却不经过端口类短信的码号、签名、模板和同意材料。74 号令第四十一条把这类“具有通信短信息特征的信息递送”参照短信管，并要求依法需审核的先送审。这是监管给灰色通道准备的抓手。

手机厂商的系统推送是第三条线。它通常不进短信收件箱，却同样能锁屏弹出。统一推送标准（UPS）当年要解决的是后台保活和通道碎片，不是 106 码号。运营商若把第四十一条解释得过宽，厂商会认为推送生态被挤压，进而在 5G 消息商业签约上留手。这是 2026 年 5 月那篇僵局调研的结构，不是新事实。

## 四、外部研判

观察，不是已证实的经营结论。

1. **普通企业的理性选择仍是路径 B。** 自己办 SP 证和 106 码号，要许可证、技术方案、码号年报、三网协议和投诉处置。只有发送量、多部门分端口或强合规审计能覆盖这套成本时，路径 A 才划算。
2. **营销短信会继续变贵、变慢、变窄。** 同意材料、会员关系、退订、分端口、报备时效，都会把“买号码群发”挤出正规通道。价格最低的通道往往伴随更高的拦截和关停风险。
3. **通知类短信仍难被微信和 App 推送完全替换。** 验证码、动账、物流在无 App、弱网络、锁屏必达这三项上仍有优势。5G 消息适合要按钮和卡片的服务，尚未成为默认通知通道。
4. **跟进合规端口短信，观望 5G 消息替代短信。** 企业如果现在就要发通知或经同意的会员营销，应走资质—签名—模板—分端口。若产品假设是“短信窗口里的小程序”，需要单独验证目标用户的 5G 消息开通率和回落成本，不能拿白皮书当覆盖率。
5. **第四十一条会决定 IP 消息的生死，而不是 RCS 标准本身。** 标准已经在。真正会改变生态的是：类短信互联网递送要不要许可、要不要码号、要不要签名，以及厂商推送算不算“具有通信短信息特征”。
