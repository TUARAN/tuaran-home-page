> **风险与合规提示：** 资料整理用于理解协议、产品和基础设施结构，不构成投资、开户、代币发行或法律建议。加密资产价格波动大，私钥丢失、钓鱼授权、合约漏洞和平台停服都可能导致全部本金损失。中国大陆现行规则把虚拟货币相关业务活动定性为非法金融活动；境外单位和个人不得以任何形式非法向境内主体提供交易、兑换、中介、定价等服务。违背公序良俗的相关民事法律行为无效，损失自行承担。

## 一、先给结论

一个产品自称 Web3，用户多到的权利只有三项可以当场检验：**谁控制签名密钥、关键状态能否不经单一公司核验、发行方停服后还有没有退出路径。** 三项里缺任何一项，商标可以继续叫 Web3，用户拿到的仍是平台许可。

可核验的要点：

1. **这个词至少有两套来源。** 2001 年 Tim Berners-Lee 等人写的是机器可理解的语义网；2014 年 4 月 17 日 Gavin Wood 把 Web 3.0 写成「后斯诺登网络」。两套方案解决的问题不同，不宜混成同一个产品品类。
2. **Wood 原定义是四件套：** 用哈希寻址发布静态内容、用伪匿名身份做加密消息、用共识引擎执行无信任交易、用浏览器把三者收成 ĐApp。今天消费市场几乎只卖了「交易 + 钱包界面」。
3. **链上规则、客户端看见的东西、代币激励、法律身份是四层，互相不能替代。** ERC-721 只保证 `ownerOf(tokenId)` 指向某个地址；图片和名字默认是一条 URI，规范写明 URI **可以改变**。
4. **2026 年用户的实际路径仍是：钱包 → RPC 公司 → 区块浏览器 / 店铺 API → 托管前端。** MetaMask 官方帮助中心写明默认用 Infura 进出链；用户可以改 RPC，默认不改。2025 年 10 月 20 日 AWS `us-east-1` 故障时，Infura 多条网络端点受影响，MetaMask 出现余额显示为 0，链本身仍在出块。
5. **对大陆读者：** 拆协议、看管理员权限、核对 RPC 依赖，可以跟进。参与代币融资、兑换、开户和任何面向境内的虚拟货币服务，按《银发〔2026〕42 号》观望。

## 二、事实层

### 1. 两套「Web 3」不要并成一句

| 名称 | 提出时间 | 提出者 / 文本 | 要解决的问题 | 主要技术 |
|---|---|---|---|---|
| Semantic Web | 2001 年 5 月 | Berners-Lee、Hendler、Lassila，《Scientific American》封面文 [The Semantic Web](https://www.scientificamerican.com/article/the-semantic-web/) | 让网页对机器可理解，便于自动推理和代理 | RDF、本体、链接数据 |
| Web 2.0 | 约 2004 | 常追溯到 Tim O'Reilly 对用户生成内容平台的概括 | 读写网、社交与广告变现 | 中心化账号、服务器、推荐与广告 |
| Web 3.0 / Web3（加密语境） | 2014-04-17 | Gavin Wood，[ÐApps: What Web 3.0 Looks Like](https://gavwood.com/dappsweb3.html) | 少把信息交给「无法被合理信任」的组织，用数学强制原先的假设 | 内容寻址发布、伪匿名消息、共识账本、ĐApp 浏览器 |

ethereum.org 现行介绍页把口号收成 **Read-Write-Own**，并指向 2020 年一条推文；站点源码把链接写成 [@himgajria 2020-05-28](https://twitter.com/himgajria/status/1266415636789334016)。该页同时承认 Web3 已变成涵盖性术语，并列出四条原则：去中心化、无需许可、原生支付、少依赖被信任的第三方。[What is Web3](https://ethereum.org/web3/) 开发者对照页最后更新于 2026-02-23。

Wood 自己的日期比 ethereum.org 那句「以太坊上线后不久」更早。以太坊主网 2015 年 7 月 30 日启动；Wood 的博文写于主网上线前一年，当时 Ethereum 还是正在写黄皮书的项目。2018 年 9 月 12 日他在 [Why We Need Web 3.0](https://gavofyork.medium.com/why-we-need-web-3-0-5da4f2bf95ab) 里重申：希望做一套点对点网络，让人完成现在能做的事，但「没有服务器、也没有当局管理信息流动」。

### 2. Wood 2014 年的四组件

原文把「后斯诺登网络」拆成四块，对应今天常被省略的分工：

| 组件 | Wood 当时的说法 | 他点名的先例 | 今天常见落点 |
|---|---|---|---|
| 静态内容发布 | 地址内在于内容（哈希），下载后可核验对错 | BitTorrent / magnet | IPFS、Arweave、仍大量使用的 HTTPS |
| 动态消息 | 伪匿名身份、加密信道、不把 IP 当端点 | 他设想的低层消息系统 | 多数产品退回 HTTPS + 推送服务 |
| 无信任交易 | 共识引擎按事先写明的规则改状态 | Bitcoin；他把 Ethereum 当作「第一个可工作的通用例子」 | 公链、L2、智能合约 |
| 统一界面 | 看起来仍像浏览器，URI 经共识解析成前端哈希 | Namecoin 式名字 | 钱包插件 + 托管在 Cloudflare / Vercel 上的网页 |

四件套里，**只有第三件在消费市场被规模化交付**。第一件有内容寻址网络，但 NFT 与 dApp 前端仍大量指向普通 URL。第二件没有成为日常通信层。第四件的外观还在，解析和托管大多没上共识引擎。

### 4. 2022 年那次实验，规范本身就允许

Moxie 做了两件事，现在仍能回到原文核对。

第一，他写的 dApp 是普通 React 网站。所谓分布式，指**状态和改状态的权限**放在链上。手机和浏览器当不了对等节点，读状态只能问远程节点。他观察到当时几乎所有 dApp 走 Infura 或 Alchemy；连上 MetaMask 之后，钱包自己也向 Infura 发 `eth_getBalance`。返回的 JSON **没有签名**，客户端无从证明节点在撒谎。

第二，他按当时的 NFT 惯例把图像放在 URL 上，而规范不要求对 URL 内容做哈希承诺。他让同一枚代币在 OpenSea、Rarible 和钱包里显示成不同图。OpenSea 下架后，钱包里也不见了——钱包列出 NFT 时请求的是 OpenSea API，得到 `304 No Content`。代币所有权记录仍在链上。

这一点和 ERC-721 文本一致。元数据扩展是**可选**的；`tokenURI` 返回 RFC 3986 URI，可以指向一份 JSON。规范写明：**URI MAY be mutable**（允许随时间改变），举例是「代表一栋房子的 NFT，房屋照片和居住者本来就会变」。见 [EIP-721](https://eips.ethereum.org/EIPS/eip-721)。链上保证的是 tokenId 和地址的对应；图像、名字、描述默认在链外。

### 5. 2026 年仍能核对的访问路径

MetaMask 帮助中心现行页面 [What is Infura, and why does MetaMask use it?](https://support.metamask.io/more-web3/learn/what-is-infura-and-why-does-metamask-use-it/) 写了三件事实：

- Infura 是 MetaMask 用来「把信息送进、送出区块链」的服务商；
- 更近一段时间，Infura 和 MetaMask **同属 Consensys Software**；
- 用户**不必**使用 Infura，可以把 RPC 改成自己的节点或其他端点。

ethereum.org 对 JSON-RPC 的说明同样直白：应用要读链或发交易，必须连上一个以太坊节点。[JSON-RPC API](https://ethereum.org/developers/docs/apis/json-rpc/)

默认路径因此是工程选择，不是协议强制。协议允许自跑节点；产品为了让几千万人打开钱包就能看到余额，把节点外包给少数 API 公司。2025-10-20 的故障把这条依赖变成一次公众可见的事故：链还在，**解释链的那一层**停了。

Infura、Alchemy、QuickNode 各自宣传过千亿级月请求。这些数字来自厂商或转述，缺少统一的第三方审计口径，不能当成市场份额。能确认的是：头部钱包把其中一家设为默认，故障时用户界面会像整条链消失。

## 三、结构分析

按状态从产生到被用户看见拆层。每一层都可以单独中心化，也可以单独做到可核验；把任何一层的公司商标写成「Web3」，都会把检验做空。

```text
口号层      去中心化 / 用户所有 / Web3 登录
密钥层      谁持有能签署状态变更的私钥或门限份额
账本层      谁出块、谁验证、数据是否公开可同步
合约层      增发、冻结、升级、暂停写在谁控制的函数里
存储层      元数据与文件：链上字节 / 内容哈希 / 可变 HTTP
访问层      全节点 / RPC / 索引器 / 区块浏览器
界面层      钱包、dApp 前端、托管网站、应用商店
资产层      代币支付拥堵、代表权利，或只为融资和盘面存在
治理层      管理员、多签、时间锁、投票代币
法律层      公司、基金会、牌照、用户所在司法辖区
```

### 表 A：各层谁说了算

| 层 | 口号通常怎么说 | 2026 年用户默认碰到什么 | 发行公司消失后还能否用 |
|---|---|---|---|
| 密钥 | 你的钥匙，你的币 | 助记词或设备密钥；交易所账户是另一套托管 | 密钥还在就能在别的钱包恢复；交给平台的资产随平台 |
| 账本 | 全球计算机 / 无人可关 | 公链节点仍在；用户很少自己跑 | 公链本身通常还在；许可链随运营方 |
| 合约 | 代码即法律 | 大量合约保留 `owner` / `upgrade` / `pause` | 无升级、无管理员的合约仍可被第三方调用 |
| 存储 | 永久上链 | `tokenURI`、前端、文档多在 HTTPS 或可变网关 | 只有内容寻址且有人继续提供副本时才读得到 |
| 访问 | 连上区块链 | Infura / Alchemy / 自建 RPC | 换端点或自跑节点后可读；只认一家 API 则空白 |
| 界面 | ĐApp / Web3 App | React 站点 + 钱包注入，部署在云上 | 域名和网页可没；懂的人仍可用合约地址交互 |
| 资产 | 社区所有 | 交易所订单簿、稳定币、平台积分混在一起 | 能转走的链上余额可转；锁在盘里的不能 |
| 治理 | DAO | 多签 + 投票代币 + 基金会实体并行 | 看管理员密钥是否销毁或交给不可逆时间锁 |
| 法律 | 无需许可 | 用户仍受所在地法约束；入口受应用商店和支付通道约束 | 牌照和公司注销不自动删除链上状态 |

### 表 B：四类方案都在用同一个词

| 方案 | 最小承诺 | 典型形态 | 容易把检验做空的方式 |
|---|---|---|---|
| 协议最大派 | 单一公司关不掉关键路径 | 自运行节点、不可升级合约、内容寻址 | 把难用写成纯度，普通用户永远到不了 |
| 链上金融派 | 资产可转移、可清算、规则公开 | DEX、借贷、稳定币、永续 | 把投机成交量写成协议用途 |
| 产品包装派 | 钱包登录 + 链上回执 | NFT 会员、积分上链、Connect Wallet | 把登录方式写成所有权 |
| 许可链 / 联盟链 | 可审计、可追责、参与方许可 | 数字藏品、供应链存证、跨境结算试点 | 把「写进某条链」写成 Web3 |

四类方案可以共用一条公链，用户权利仍可能完全不同。OKX Wallet 这类产品把自托管多链入口和交易所流量绑在一起，要拆的是**密钥在谁设备上**和**兑换、桥、跟单是否构成境内虚拟货币服务**，见站内 [OKX Web3 钱包观察](/articles/research/topics/okx-web3-wallet)。中心化交易所则是另一套：用户接触加密资产的主入口仍是 Web2 平台，见 [加密货币交易所观察](/articles/research/topics/cryptocurrency-exchanges)。

### 表 C：五条检验，用来替代「真正」

「真正的 Web3」是口号竞赛。能写进产品清单的是这五条：

| 检验 | 通过时长什么样 | 失败时长什么样 |
|---|---|---|
| 退出 | 用户能把资产或数据转到自己控制的地址，无需平台审批 | 提现、导出、桥接被风控或管理员拦住 |
| 独立核验 | 换一个 RPC，或自跑节点，关键状态仍一致 | 关掉 Infura / OpenSea，钱包空白或 NFT 消失 |
| 管理员密钥 | 无升级，或多签 + 公开时间锁，权限可在浏览器核对 | 单钥匙可增发、冻结、改 URI、暂停合约 |
| 公司死亡 | 前端挂了，合约、哈希和副本仍可被第三方读取 | 代码、元数据、域名都在公司服务器 |
| 代币必要性 | 代币支付验证、存储或拥堵，或对应可执行权利 | 去掉代币系统照常跑，代币只为融资和盘面存在 |

**钱包登录只证明你能对某次请求签名。** 所有权取决于状态能否被独立核验，以及管理员能否单方面撤销。两项同时成立，Connect Wallet 才从登录按钮变成权利凭证。

站内已有两篇把这套检验用在具体对象上：

- [2aran.com 能不能上链](/articles/research/topics/2aran-onchain-content-site) 把内容站拆成五档深度。链上时间戳（深度 1）已经买到独立核验和版本顺序；整站 dApp（深度 4）会丢掉搜索、评论、登录和 SEO，还要读者装钱包。内容站要买的是可核验历史，通常不是把 Cloudflare 换成链。
- [如何上链发币](/articles/research/topics/how-to-launch-token-onchain) 说明部署 ERC-20 只完成资产登记。决定风险的是管理员权限、能否增发、初始分配、流动性会不会被撤走。对境内主体，技术验证应停在测试网或获批的封闭场景。

比特币满足货币状态的共享和退出，不提供通用 Web 应用层。多数 NFT 商店满足界面和局部所有权显示，在存储层和访问层经常失败。以太坊提供可编程共享状态；默认客户端仍把核验外包。

## 四、外部研判

外部能确认的是：加密语境里的 Web3，起点是 Wood 2014 年那篇四组件设计；2026 年公众产品多半停在「密钥在用户设备上 + 状态在某条公链登记」。访问层、存储层和界面层重新集中到少数公司和云区域，已经有公开事故，不再只是 2022 年一篇博客的印象。

一种可能的外部解读是：对开发者，先问三件事——状态要不要多方共享、要不要抗单点撤销、用户会不会自己核验。只需要账号和支付时，钱包登录不会自动变成新的所有权模型。对读者，有用的动作是看管理员权限、看 `tokenURI` 指向哪里、看钱包默认 RPC 是谁；把「去中心化」当形容词用，检验会失效。

跟进判断：

| 读者位置 | 判断 | 下一步 |
|---|---|---|
| 想理解协议和产品结构 | **跟进** | 用表 C 核对具体产品；优先读合约权限、RPC 和元数据，不读融资故事 |
| 想给自己的网站加可核验发布 | **跟进** | 按内容账本路径做哈希和可选 L2 时间戳，首版不发币、不要求读者连钱包 |
| 大陆居民参与代币、打新、杠杆、境内兑换 | **观望** | 按 42 号文把相关业务当禁止项，损失风险自担 |
| 把 Web3 当新流量入口去做钱包登录页 | **不跟进** | 登录方式改变不产生可核验权利，还叠一层私钥和授权风险 |

反证：若 2026 年后再观察时，主流钱包默认连用户自选或可验证的轻客户端、NFT 元数据普遍带内容哈希、关键协议取消单钥匙升级，则「访问层和存储层已经重新中心化」这条判断要改写。暂未看到公开、可审计的数据证明这三件事已经成为默认。

## 五、未能验证

- Infura、Alchemy、QuickNode 在 2026 年的实际请求份额。厂商自报月请求量和博客里的 40% / 35% 估算，对不上同一口径。
- 仍使用可变 HTTP 元数据、未做内容哈希承诺的 NFT 比例。
- 自己运行全节点或可验证轻客户端的用户数量，以及 MetaMask 用户改过默认 RPC 的比例。
- 「Web3」搜索热度与链上活跃地址之间的关系；两者量的不是同一群人。
- 中国联盟链、数字藏品平台的真实活跃地址和重复使用率。公开材料多为项目宣发。
- Moxie 2022 年抓到的 Infura 项目 ID、OpenSea `v1/assets` 路径，不能直接当成 2026 年钱包的现行请求；现行默认依赖以 MetaMask 帮助中心和 2025-10-20 故障报道为准。
