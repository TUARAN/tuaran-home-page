> **风险与合规提示：** 貔貅盘涉及加密资产诈骗、智能合约权限、流动性和市场操纵风险。链上记录公开不等于交易安全，检测工具也可能误报、漏报或只反映查询时的状态。资料用于安全教育和机制分析，不构成投资、交易、追损或法律建议；遭遇实际损失时，应保存证据并向所在地执法机关、相关钱包或交易平台咨询。

## 一、先给结论

“貔貅盘”是中文加密社区对一类 **只容易买进、很难或无法卖出** 的代币陷阱的称呼。钱包里会出现余额，行情页也可能连续上涨，但代币合约掌握着转账规则。普通买家提交卖单时，合约可以让交易回滚、扣掉接近全部资产，或只允许项目方控制的地址卖出。

先抓住六个判断：

1. **余额不等于可兑现资产。** 钱包显示的数量通常来自代币合约的 `balanceOf`；同一份合约也决定这些代币能否转给 DEX 资金池。
2. **K 线可以在几乎没有正常卖盘时上涨。** 浅流动性池里，连续小额买入会抬高边际价格；无法退出的买家又不会形成真实卖压。
3. **“代码已验证”只说明公开代码与链上字节码能够对应。** 它不证明业务逻辑安全，也不排除代理升级、外部控制器和管理员权限。
4. **黑名单、暂停和可调税率本身不自动等于诈骗。** 合规稳定币也可能用这些能力冻结被制裁地址。关键要看权限由谁控制、规则是否披露、是否针对普通买家形成不对称退出。
5. **一次小额卖出成功仍不能排除陷阱。** 合约可以设置白名单、延时、最大卖出量、按地址或区块变化的条件，也可以在检测完成后改规则。
6. **“再买一些就能解锁”是继续收割。** 正常 DEX 不会要求用户持续加仓，才能取回已经买到的代币。

识别貔貅盘的核心问题只有一个：**一个没有特权的普通地址，能否在当前规则下，把代币换回池中的主流资产并实际到账。**

## 二、钱包有余额，为什么仍然卖不掉

ERC-20 是一套接口约定。它规定代币通常应提供 `balanceOf`、`transfer`、`transferFrom`、`approve` 等方法，方便钱包和 DEX 共同调用。标准接口没有保证“任何持有人在任何时候都能自由转出”。[EIP-20](https://eips.ethereum.org/EIPS/eip-20)甚至明确要求调用者处理返回 `false` 的情况，不能假设转账永远成功。

在常见的 AMM 交易里，买入和卖出是两条方向相反的转账：

```text
买入：资金池把目标代币转给用户
卖出：用户把目标代币转回资金池，资金池再付出 USDT、USDC、WETH 或 WBNB
```

恶意合约只要在第二条路径上增加判断，就能保留“可以买”的外观，同时卡住退出。例如：

```solidity
if (to == pair && !allowedSeller[from]) revert();
```

这段示意代码的意思是：代币转向交易池时，发送者必须在许可名单里。项目方地址可以卖，普通买家不能卖。真实陷阱通常会把逻辑拆散、改名或藏进外部合约，未必像示例这样直白。

[Ethereum.org 的骗局代币说明](https://ethereum.org/guides/how-to-id-scam-tokens/)还提醒了两个容易误判的地方：ERC-20 余额由代币合约自己的存储决定，开发者可以按自己的逻辑返回；`Transfer` 事件同样由合约触发，看到转账事件和持有人数量不代表背后一定存在独立、正常的用户交易。

## 三、常见的“只进不出”机关

### 3.1 黑名单与白名单

合约可以记录一组地址，在转账前检查发送者或接收者。买家成交后被加入黑名单，卖出会直接失败；另一种做法是只允许白名单地址向资金池转账，项目方可以制造卖出记录，普通地址没有同样权限。

黑名单能力也有合法用途。稳定币发行人可能因制裁、盗币或法院命令冻结地址。区分点在于治理和披露：谁能加人、是否经过多签或延时、操作是否可追溯、普通用户是否在买入前已经知道规则。一个匿名管理员可以随时把买家拉黑，风险结构完全不同。

### 3.2 100% 卖出税与可变税率

交易可能不会回滚，却把卖出所得几乎全部作为“税”扣走。界面上显示交易成功，用户收到的主流资产接近零，经济结果仍然等于无法退出。

[GoPlus Token Security API 文档](https://docs.gopluslabs.io/reference/response-details)把 `sell_tax = 1` 解释为 100% 卖出税或无法卖出，也单独标记 `slippage_modifiable`：管理员能修改买卖税时，今天可卖的代币明天可能被调成无法交易。

### 3.3 卖出数量、时间和地址条件

限制可以做得很细：

- 只允许低于某个数量的卖出，阻止大额退出；
- 要求持仓超过动态门槛，用户永远差一点；
- 每个地址只允许卖一次，或每次只能卖极小比例；
- 买入后进入冷却期，而冷却期又能被管理员修改；
- 根据 `tx.origin`、调用路由、区块号或地址历史给出不同结果；
- 检测钱包可以卖，普通新钱包不能卖。

这解释了为什么“我朋友刚才卖成功了”和“检测网站显示可卖”都只能算一个时点、一个地址、一个数量下的证据。

### 3.4 修改余额或可转让余额

更激进的合约允许管理员直接改持仓，或者把“界面显示余额”和“实际允许转出的余额”分开记录。用户看到 10 万枚代币，转账逻辑却只承认很小一部分。

GoPlus 的风险字段把 `owner_change_balance` 单独列出；[Ethereum.org 的代币集成检查清单](https://ethereum.org/developers/tutorials/token-integration-checklist/)也要求关注管理员增发、暂停、黑名单和可升级能力，因为这些权限可能困住依赖该代币的合约和用户。

### 3.5 外部控制器与代理升级

代币表面代码可能很短，真正的判断交给另一个控制器；也可能使用代理合约，把执行逻辑放在可替换的实现合约中。今天通过检查的规则，管理员升级后可以改变。

因此，核验不能只停在代币首页。还要继续追：

- 当前实现合约地址；
- Proxy Admin、Owner、AccessControl 各角色；
- 税率、路由、交易对和控制器是否可修改；
- 多签的签名门槛与成员；
- 是否存在时间锁，以及时间锁能否被绕过。

[OpenZeppelin 的访问控制文档](https://docs.openzeppelin.com/contracts/5.x/access-control)说明，Owner 或角色可以管理铸币、冻结转账等关键能力。权限设计是正常智能合约的一部分，审查重点是权限边界和实际控制人。

## 四、为什么价格会一直涨

貔貅盘的价格通常来自 DEX 流动性池，不一定是假数字。问题出在这个价格只能描述 **下一小份代币的边际报价**，不能证明全部持仓可以按该价格卖出。

假设一个小池子里有 10 枚 WBNB 和 1000 万枚新代币。有人用 WBNB 买币后：

- 池中的 WBNB 增加；
- 新代币减少；
- AMM 按储备比例提高后续买家的价格。

如果普通买家无法把币卖回池子，价格缺少正常卖盘约束。骗子还可以用多个关联钱包互相交易，制造成交量、持有人数和“社区正在进场”的画面。把少量代币转给知名地址，也不能证明地址所有者主动购买或背书。

这类盘面最有迷惑性的三组数字是：

| 页面显示 | 它真正能说明的事 | 它不能证明的事 |
|---|---|---|
| 钱包余额 100 万枚 | 合约向该地址报告了这个余额 | 能转出、能卖出、能换回多少钱 |
| 最新价上涨 500% | 最近的池内边际报价上升 | 所有持仓能按该价格退出 |
| 持有人 3000 个 | 3000 个地址出现了余额或转账记录 | 3000 个独立的人主动买入 |
| 流动性 20 万美元 | 某个时点池中两侧资产的估值 | LP 不会被撤、代币一定可卖 |

理解池深、边际价格和可变现金额的差异，可继续看[《AMM 与流动性池：没有买卖挂单，链上交易怎样自动定价》](/articles/research/topics/amm-liquidity-pool)。

## 五、怎样检查一枚陌生代币

### 第一步：确认链、合约地址和交易对

代币名称和 Logo 可以重名，合约地址才是链上对象的标识。核对时至少同时确认：

- 它位于哪条链；
- 完整合约地址；
- 官方渠道公布的地址是否一致；
- 主要交易对和资金池地址；
- 钱包或行情页有没有把同名代币混在一起。

陌生人私聊给出的地址、搜索广告、群公告截图和 KOL 钱包收到的空投，都不能单独作为来源。

### 第二步：看真实卖出，不只看绿色 K 线

在区块浏览器中打开交易对，找多个无关联地址完成的卖出交易。确认三件事：

1. 交易状态成功；
2. 代币确实进入池子；
3. 卖家确实收到 WETH、WBNB、USDT、USDC 等对手资产。

项目方地址之间的循环交易、路由器测试、极小金额卖出都可能是布景。买入记录很多、正常卖出记录极少，是强烈警报。

### 第三步：查权限与可变项

优先寻找这些能力：

- 黑名单、白名单；
- 暂停转账或暂停交易；
- 修改买卖税；
- 修改最大交易量、最大钱包量、冷却期；
- 修改余额、铸币或销毁他人代币；
- 更换路由、交易对或外部控制器；
- 代理升级；
- 特权地址绕过限制。

“Owner 已放弃”也要继续查。权限可能留在另一个角色、代理管理员、外部合约或隐藏地址中。

### 第四步：用检测工具交叉检查

GoPlus、Honeypot.is 等工具会结合代码特征与买卖模拟，给出 `is_honeypot`、卖出税、能否卖完、暂停和黑名单等结果。这些结果适合筛掉明显风险，不适合充当安全证明。

工具可能受以下条件影响：

- 合约未开源，静态分析看不到完整逻辑；
- 代理实现或外部控制器没有被正确追踪；
- 交易冷却、反机器人规则造成误报；
- 恶意合约识别检测地址，给模拟器放行；
- 管理员在检测后修改参数或升级实现；
- 工具尚未支持该链、DEX 或新型机制。

至少比较两类方法：代码与权限检查、真实链上卖出记录、交易模拟。三者相互印证，比看一个红绿标签可靠。

### 第五步：检查流动性和 LP 控制权

即使代币可以卖，仍要确认池中有多少主流资产、LP 份额由谁控制、锁定何时到期。管理员可以自由撤走流动性时，风险从“卖不出”变成“能提交卖单，但池里已经没有可换走的资产”。

“LP 已锁”只能降低短期撤池风险，不能消除代币合约里的黑名单、税率和升级权限。

## 六、哪些信号最容易制造安全错觉

| 信号 | 正确理解 |
|---|---|
| 代码已验证 | 可以阅读对应源码；恶意逻辑也可以完整开源 |
| 通过某次审计 | 先看审计范围、版本、日期和未解决项；后续升级可能不在范围内 |
| Owner 已放弃 | 继续查角色、代理管理员、外部控制器和预设特权地址 |
| 有真实流动性 | 说明池中暂时有资产；还要查退出权限和 LP 控制权 |
| 检测工具显示安全 | 只代表该工具在该时点、该参数下未命中风险 |
| 有人卖出成功 | 查卖家是否特权地址、金额是否被特殊限制、实际到账多少 |
| 知名地址持币 | 可能是任何人主动转入，不能推出地址所有者背书 |
| 连续上涨、没有回撤 | 可能正是正常持有人不能卖出的结果 |

风险信号需要组合判断。单独存在黑名单不一定是诈骗；匿名团队、可升级代理、可调税率、普通地址缺少真实卖出，再叠加私聊催促加仓，已经足以放弃交易。

## 七、已经买入后，先做什么

发现卖不出时，先停止追加资金。不要为了满足“最低持仓”“解冻税”“保证金”“验证费”继续买入或转账，也不要相信声称能收费追回资产的陌生人。

按风险从近到远处理：

1. **保存证据。** 记录链、代币与交易对合约地址、钱包地址、交易哈希、时间、金额、失败报错、聊天记录和对方账号。
2. **检查授权。** 如果曾连接陌生网站，查看是否给未知合约授予代币或 NFT 权限。撤销可疑授权只能阻止后续扣款，不能让貔貅币恢复可卖。
3. **判断密钥是否暴露。** 只做过普通 DEX 授权与 Swap，不等于助记词泄露；若曾输入助记词、私钥或签署来源不明的高危交易，应把未受影响资产转移到全新钱包，并停用旧地址。
4. **向入口平台报告。** 联系钱包、DEX 前端、行情平台、群组平台和中心化交易所，提交合约地址与交易证据，争取风险标记或冻结尚未转出的中心化账户资金。
5. **按所在地要求报案。** 链上交易通常不可逆，及时提供完整证据比寻找“黑客追回”更实际。

不要向“追回团队”支付前置费，也不要把钱包控制权交给自称白帽的人。二次诈骗常利用受害者急于挽回损失的心理。

## 八、术语边界：币圈貔貅盘与安全论文里的 honeypot

“Honeypot”在智能合约研究里还有一个更早、更窄的含义：攻击者部署一个看似存在漏洞的合约，引诱别人尝试盗取其中资产；隐藏条件会让尝试者反而损失自己的钱。

2019 年 USENIX Security 论文 [《The Art of The Scam: Demystifying Honeypots in Ethereum Smart Contracts》](https://www.usenix.org/conference/usenixsecurity19/presentation/ferreira)对这类“假漏洞诱捕”做过系统分类，并在超过 200 万份合约中用工具识别样本。这里的受害者往往以为自己发现了可获利漏洞。

中文社区所说的“貔貅盘”更多是 **代币交易陷阱**：普通用户被价格、宣传或私聊诱导买入，随后无法正常卖出。两者都利用“看起来有利可图”的诱饵，也都把真正限制藏在合约逻辑里；受害行为、检测特征和资金流并不相同。
