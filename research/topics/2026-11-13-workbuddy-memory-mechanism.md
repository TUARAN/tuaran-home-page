## 一、先给结论

到 **2026-11-13（北京）**，目前能看清的是：WorkBuddy 是腾讯出品的全场景 AI 办公工作台，公开口号是「AI Agent 办公新范式」。官网 workbuddy.cn、国际站 workbuddy.ai，以及腾讯云上的 WorkBuddy Enterprise 记忆说明，同属这一条产品线。下面只写这条产品线当前对外公开的记忆机制。

目前能站住的要点：

1. **对外设置里，记忆至少有两条可分别处理的轨道。** 国际站《系统设置》在「记忆与进化」下列出「本地记忆」和「生成对话记忆」：前者写明把日常工作记忆写入本地文件，后者允许从对话中提取上下文。「生成对话记忆」在《记忆》页写明默认开启。用户可查看、用对话编辑、删除或清空、导入、一键关闭；系统设置还列出不可恢复的「重置记忆」。
2. **已经落地的对话记忆，是每晚重做摘要，并允许更正、删除现行条目。** 官方《记忆》页写：每晚整理当天会话，记忆摘要每晚重新生成；后续把相关记忆当作背景；使用方式是注入系统提示词，并支持检索会话历史。关闭后停止提取新记忆；关闭或删除后，相应数据停止用于后续对话，已生成输出不会追溯撤回。已打开的官方文档没有出现「原地」这个词。
3. **本地一侧，官方承认写文件，也承认摘要可以缓存在本地。** 更新日志写过：工作空间初始化会自动创建 MEMORY.md；Working Memory 改为按 workspace 独立存储。国际站 5.9.4 更新说明写「可按会话关闭工作区本地记忆；记忆摘要缓存在本地作为兜底」。客户端还有「长期记忆」编辑页的修复记录。
4. **底层实现没有被写成完整架构图。** 官方没有把对话记忆的存储实现披露为向量数据库、某种服务器表，或某种文件格式。隐私政策写过：若开启 Memory，服务会用既往输入提供更个性化的输出；输入与输出在服务器上最长保留 14 天，桌面端也在本地保存。这条 14 天口径没有单独对上「记忆数据」的留存期限。

## 二、事实层

资料核对窗口：约 **2026-11-13（北京）**。以已经打开的官方文档、官网、更新日志和隐私政策原文为准。

### 2.1 这是哪一个 WorkBuddy

官网首页写：「WorkBuddy 是腾讯出品的全场景 AI 办公工作台。」口号是「AI Agent 办公新范式」。简介页写：用户用自然语言描述需求，由 WorkBuddy 自主规划和执行任务，并交付文档、表格、PPT 等成果。国际站首页的对应表述是 “an all-in-one AI workspace from Tencent”。文档静态资源同时出现在 `download.codebuddy.cn` 与 `download.codebuddy.ai`。

workbuddy.cn 与 workbuddy.ai 是同一条产品线的国内站与国际站。两边的记忆、设置文档路径并不完全镜像：国内《记忆》页在 `/docs/workbuddy/.../Memory`，国际《系统设置》在 `/docs/zh/workbuddy/.../System-Settings`；把路径对调后，本次打开得到 404。内容也不完全同一版，后面按各页原文分开写。

腾讯云文档《WorkBuddy Enterprise 记忆》最近更新时间写为 2026-07-20 19:49:30，正文与官网《记忆》页高度同构，包括默认开启、每晚整理、注入系统提示词、检索会话历史、关闭后不追溯撤回等。企业产品概述把 WorkBuddy Enterprise 写成腾讯云的一站式 AI 智能体平台总品牌，下面并列 CodeBuddy、WorkBuddy、WorkBuddy Managed Agents。CodeBuddy 是编码工具，同一文档站点上另有 CodeBuddy CLI 的记忆说明；那一套不并进下面的机制描述。

国际站《Tencent WorkBuddy Privacy Policy》（Last Updated: August 2026）把服务主体按地区写为 Tencent Korea Yuhan Hoesa，以及新加坡注册的 Tencent Cloud International Pte. Ltd.；并写明该政策不适用于 enterprise version，须另见企业隐私政策。联系邮箱为 `workbuddy_ai@tencent.com`。国内常见问题页的咨询邮箱是 `workbuddy@tencent.com`。`workbuddy.cn/privacy/` 打开后是《腾讯云代码助手隐私保护声明》，生效时间 2025-09-26，声明适用主体是腾讯云计算（北京）有限责任公司、适用于腾讯云代码助手官网，不宜直接当作 WorkBuddy 个人版自己的隐私正文。产品文档多处提到「WorkBuddy 隐私保护指引（PC 端）」，本次没有打开这份中文指引的独立页面。

公开检索里还能碰到同名但无关的产品，例如新加坡联合办公平台 work-buddy.com，以及面向现场作业排班的 WorkBuddy 软件、换班应用 WorkBuddy Shift Swap。它们与腾讯这条产品线不是同一主体，下文不再展开。

### 2.2 对外和对内设置现在怎么写

入口在官方文档里有几种写法，需要并存，不宜合成一个菜单路径。

《记忆》页（国内文档，页面时间 2026-07-08 10:45，北京）写：可从头像处进入「设置 - 记忆」中查看、编辑、删除或一键关闭。同页「使用建议」写成「设置 → 记忆」。腾讯云企业文档写成「设置 > 记忆」。移动端《设置》把这一块叫「记忆库」，入口是左上角菜单打开侧边栏，再点用户名称旁的齿轮；页面时间 2026-09-17 17:45，北京。桌面端国内《系统设置》（页面时间 2026-11-10 11:49，北京）把「记忆与进化」同时放在头像菜单和设置导航的「功能」分组，说明是「记忆的管理与清除，详见记忆」，并链到《记忆》页。更新日志 5.4.5（2026-08-30）写：个人面板新增「记忆与进化」快捷入口，可直接进入个性化记忆设置。

国际站《系统设置》（页面时间 2026-11-02 15:49，北京）把入口写成「头像 > 设置 > 系统设置」，并在「记忆与进化」下给出一张表。这是目前已经打开的官方文本里，对设置项列得最完整的一处：

| 设置项 | 官方说明 |
| --- | --- |
| 本地记忆 | 将日常工作记忆写入本地文件，跨会话保留上下文 |
| 生成对话记忆 | 允许从对话中提取并记住相关上下文，让后续回应更连贯 |
| 管理记忆 | 查看已保存的记忆内容，也可提交修改建议 |
| 导入 | 支持从 ChatGPT、Claude 等其他 AI 导入记忆 |
| 重置记忆 | 清空当前全部记忆，该操作不可恢复 |

同页警告：重置会清空全部记忆且不可恢复。如果「生成对话记忆」仍处于开启状态，后续对话仍会产生新记忆；如需彻底停用，请同时关闭该功能。

同一页在「技能与智能体」下还有「本地技能与记忆沉淀」：自动记录本地记忆、工作日志，并自动沉淀和优化技能；数据本地存储，仅在设备和工作区中保留。官方没有写明这一项与「本地记忆」开关是不是同一份存储。

《记忆》页把「生成对话记忆」写为默认开启。管理方式三条是：

- 查看：记忆摘要每晚重新生成，打开已生成的记忆，可查看记忆内容
- 编辑：点击右上角编辑图标，唤起对话框，通过对话告诉 WorkBuddy 要记住或忘记什么
- 删除：点击右上角删除图标，可以清空当前记忆

用户控制还写了：支持新增、删除、更正记忆条目；可随时关闭；亦支持从其他 AI 导入。导入步骤是：复制示例提示词到其他 AI 的对话中，再把结果粘贴回来，点击添加到记忆。移动端「记忆库」写：「我的记忆每晚重新生成，点击可查看、编辑记忆内容。通过对话的方式告诉 WorkBuddy 要记住或忘记什么。」

国内《系统设置》总览页没有再展开「本地记忆」「生成对话记忆」「重置记忆」这几个开关的逐项说明，而是指向《记忆》页。《记忆》页本身在 2026-07-08 之后未见同步改写，因此 7 月以后的客户端用词，要以更新日志和国际站设置页补看，不能当成《记忆》页已经写过。

### 2.3 已经在用的写入、调用和更新方式

对话记忆这一侧，官方概述是：从会话历史中提取具有参考价值的个人信息（事实信息、偏好习惯、人物关系、近期跟进事项等），形成「记忆数据」并定期更新。后续对话或任务执行时，会将与当前请求相关的记忆作为背景信息一并参考。提取频率：每晚整理当天会话，仅本人可见。

调用方式写了两条：一是注入系统提示词作为上下文；二是支持对会话历史的检索，例子是「上周做过什么」「之前聊过的 XX」。

积分与共享：记忆提取由 WorkBuddy 自费完成，不额外消耗 token / 积分；记忆数据仅用于产品内部为本人提供个性化服务，不涉及第三方共享。隐私提醒要求记忆内容遵循 WorkBuddy 隐私政策，仅本人可见；会话若涉及他人个人信息，提交前需确认已获授权。使用建议还写：记忆由模型自动抽取，可能存在概括偏差或时效性问题，重要判断前建议先核验。

关闭和删除的效力，官方写得很明确：关闭后将停止提取新的记忆；关闭或删除记忆条目后，相应数据将停止用于后续对话，但已生成的输出不会因此追溯撤回。这里没有写关闭开关会不会立刻清空已经存下的记忆。更新日志 4.22.12 修过「关闭再打开记忆开关导致记忆丢失」；5.9.1（2026-10-22）修过「记忆开关加载前误显示为开启」。这两条说明开关状态和存储之间曾经出现过失步，但不能单独用来推断关闭后的应然存储策略。

更新日志还提供了对话记忆之外、已经落地的本地和云端线索：

- 4.6.2（2026-03-20）：Working Memory 改为按 workspace 独立存储
- 4.7.0（2026-03-25）：初始化工作空间自动创建 MEMORY.md
- 4.8.0（2026-03-31）：修复记忆系统全局开关竞态条件和文件队列卡死
- 4.8.1（2026-04-03）：优化专家场景系统提示词，不再注入 IDENTITY.md 内容，确保专家人设不被覆盖
- 5.3.3（2026-07-21）：新增个性化页本地长期记忆展示与编辑
- 5.3.7、5.3.14：长期记忆编辑页和长期记忆加载相关修复
- 5.8.1（2026-10-11）：修复记忆删除后重新导入不显示
- 5.9.1（2026-10-22）：优化云端记忆，可记住项目相关内容
- 国际站更新日志 5.9.4：可按会话关闭工作区本地记忆；记忆摘要缓存在本地作为兜底。国内站已打开的更新日志写到 5.11.0（2026-11-03，灰度中），没有出现这一条 5.9.4 原文。

已打开的官方页面全文检索，「原地」出现次数为零。产品用来描述更新的词是「定期更新」「每晚重新生成」「更正记忆条目」「清空当前记忆」「重置」。

### 2.4 官方已经披露的底层，和尚未披露的部分

本地轨道：国际站设置页写「将日常工作记忆写入本地文件」；「本地技能与记忆沉淀」写数据本地存储，仅在设备和工作区保留。更新日志把 MEMORY.md、按工作空间存储的 Working Memory，以及曾经注入系统提示词的 IDENTITY.md 写进了正式发布说明。国际站 5.9.4 还把记忆摘要的本地缓存写成「兜底」。常见问题里，桌面端登录目录出现在 `~/Library/Application Support/CodeBuddyExtension/`（macOS）和 `%APPDATA%\CodeBuddyExtension`（Windows），工作空间目录示例为 Windows 的 `C:\Users\<用户名>\workbuddy`、Mac 的 `/Users/用户名/WorkBuddy`。这些是客户端数据位置，页面没有说记忆文件一定落在其中某一处。

对话记忆轨道：官方把它写成模型从会话中抽取、形成记忆数据、再注入系统提示词，并支持检索会话历史。存储引擎、是否向量库、是否独立数据库表，已打开的《记忆》页、系统设置和隐私政策都没有写。常见问题在「VPC 专享版安全架构」里提到「后台服务、数据库、向量数据库等所有组件部署在独立 VPC 内」，这是专享版整体部署的表述，没有写这就是个人版或企业版对话记忆的存储实现。

国际隐私政策与记忆直接相关的句子是：If the Memory feature is enabled, the Service will use your previous Inputs to provide more personalized Outputs。输入与输出在服务器上最长保留 14 天，并写明桌面端也会在本地保存，直到用户在本地删除；桌面端的配置信息存储在本地、不在服务器处理。政策没有为 Memory 单独列出一条留存期限。常见问题还写：使用端内默认模型时，输入与输出会上传云端处理；使用自定义模型时，内容仅透传给自定义模型侧，服务端不留存数据。体验优化计划开关控制数据是否用于模型训练，与记忆开关不是同一项。

5.2.6 更新日志有一句「专享版禁用 Memory 个性化功能」。客户端也多次提到本地数据库（如 WAL 预检与修复），那是桌面端一般性的本地库，官方没有把它指认为记忆专用库。

### 2.5 第三方文章里更细的文件层，不能当作官方规格

已经打开的非官方材料，会把本地记忆写成一套可直接打开的 Markdown 文件。腾讯云开发者社区专栏《信息该放哪：七个存放位置与一条晋升阶梯》（作者「当月光落下」，文中标明基于一台机器的实测，修改于 2026-09-28）把用户级记忆写成目录下的 SOUL.md、IDENTITY.md、USER.md、MEMORY.md，把项目级记忆写成工作空间 `.workbuddy/memory/MEMORY.md`，另有按日日志；并区分「云端记忆档案」与本地文件。觉醒 AI 知识库的《WorkBuddy 记忆系统拆解》（更新 2026-08-16）写成三层存储，给出 `~/.workbuddy/MEMORY.md`、项目级 `.workbuddy/memory/MEMORY.md`，以及约 4000 字符、30 天日志蒸馏等治理数字，并称参考智见 AI 蓝皮书。社区书 The WorkBuddy Book 的 Memory 章，则主要转述官方《记忆》页，同时把记忆与项目指令、self-improvement 技能作对照；文中「记忆绑定账号、企业与个人隔离」等判断，页面没有标出对应的官方原文。

这些材料可以说明：部分构建或使用方式里，确实存在本地 Markdown 记忆文件。这与官方已经写出的「写入本地文件」「自动创建 MEMORY.md」「不再注入 IDENTITY.md」能够对上一部分。它们不能单独证明 SOUL.md、USER.md 的路径和职责，也不能把 4000 字符、30 天蒸馏、检索窗口天数等数字写成产品规格。本次尝试打开 CSDN 上一篇常被检索到的记忆拆解，没有得到可核对的正文，文中也不引用。

## 三、结构分析

记忆已经在产品里落地。真正卡住判断的，是公开文本同时写了两条轨道，又没有把它们收成同一份仓库。

第一层是文档不同步。国内《记忆》页停在 2026-07-08，腾讯云企业记忆说明停在 2026-07-20，写的都是对话抽取、每晚摘要、设置里的查看编辑删除。国际站《系统设置》在 11 月初仍单独列出「本地记忆」和「生成对话记忆」。国内《系统设置》在 11 月 10 日已经改成新的导航结构，记忆细节却仍指向那篇 7 月的《记忆》页。国际站 5.9.4 写出「按会话关闭工作区本地记忆」和「摘要本地缓存兜底」，国内已打开的更新日志没有对应条目。要把「当前产品里的设置长什么样」写成一张无差别清单，材料还对不齐。

第二层是更新语义。每晚重新生成摘要，加上「更正记忆条目」和「清空当前记忆」，说明现行摘要和条目可以被改写或清掉。公开文本没有把它写成只能在末尾追加、永不改原条的日志。官方也没有把这种改写叫作「原地」，也没有给出原条与摘要之间的数据结构：是一条条目被覆盖，还是每晚生成一份新摘要替换旧摘要，公开文本写不清。关闭开关「停止提取、停止用于后续对话、不撤回旧输出」，与「重置不可恢复地清空全部记忆」被写成两种操作，关闭本身会不会保留旧条目，官方没有一句写死。

第三层是存储实现。本地轨道已经写到「文件」；对话记忆只写到「记忆数据」和系统提示词、会话检索。向量库、服务端数据库、文件格式，都还没有被官方指认到这一功能上。隐私政策里输入输出 14 天的服务器留存，和「记忆数据定期更新、供后续对话使用」如何衔接，也还对不上。不把未披露的实现补进去，判断才能停在已经打开的原文上。

## 四、判断与跟进

当前能对外讲清楚的是：检索到腾讯这条 WorkBuddy 时，公开文档把记忆写成可分别管理的两条轨道。面向用户的对话记忆默认开启，按晚抽取并重做摘要，进入后续对话的系统提示词，也可以用来检索会话历史；用户可以看、改、删、导入和关闭，关掉以后不再抽新的，也不会把已经给出的回答追回去。与此并行，官方还承认一条写入本地文件、并按工作空间保存工作记忆的轨道。更新日志里的 MEMORY.md、IDENTITY.md 和「云端记忆」用词，说明本地文件层和云端对话记忆，在更新日志里都是已经发布的机制。

就「会不会改原条」而言：对话记忆的公开行为，已经包含对现行摘要的重新生成，以及对条目的更正和清空。这已经构成对当前记忆内容的改写，只是产品文档不用「原地」来命名它。本地文件若由用户或产品直接编辑，改写原文件更是题中之义；具体文件树仍以官方已写出的 MEMORY.md 等为限，不以第三方实测篇为准。

跟进上，先不必把博客里的分层文件和字数上限当成规格。值得继续核对的，是国内与国际文档能否对齐、中文《隐私保护指引（PC 端）》会不会单独写记忆留存，以及官方会不会补一口径，说明对话记忆的存储实现，还有关闭开关后旧记忆是否仍保存在库中。这些会改变对「存在哪、留多久」的判断，不改变「两条轨道已经对外提供、对话记忆按晚更新并注入提示词」这一层已经能站住的事实。当前判断是：可以按现有公开文档理解产品行为，对未披露的存储实现保持观望。
