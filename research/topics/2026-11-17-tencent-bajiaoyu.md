## 一、先给结论

到 **2026-11-17（北京）**：「腾讯八爪鱼」在官方站点、协议和文档里，对不上腾讯自有、并以「八爪鱼」为正式名称的单一产品。检索里最先出现的，是几组同名或近名对象。它们和腾讯有分发、对接或对标关系，官方主体并不写成腾讯。

能站住的要点：

1. **未找到腾讯把「八爪鱼」写成自有产品正式名称的官方产品页或公告。** [WorkBuddy 简介](https://www.workbuddy.cn/docs/workbuddy/Overview) 的原文是「WorkBuddy 是腾讯出品的全场景 AI 工作台」。公开检索里，腾讯这条 Agent 线还常和 QClaw、QBotClaw 以及「龙虾」这一称呼一起出现。这些名称与「八爪鱼」接近，官方用词并不相同。
2. **中文互联网上最常见的「八爪鱼」，是深圳数阔信息技术有限公司运营的采集器和同品牌 RPA。** [《深圳数阔用户服务协议》](https://www.bazhuayu.com/ServiceTerms) 写：「八爪鱼为深圳数阔研发、运营，并统一管理。」官网是 [bazhuayu.com](https://www.bazhuayu.com/)，页脚备案号为粤ICP备14092314号。腾讯[应用宝详情页](https://sj.qq.com/appdetail/com.tencent.pcgame.shebazhaoyucaijiqi) 把这款软件的开发者、运营者写成深圳数阔；应用宝本身的开发者才是深圳市腾讯计算机系统有限公司。
3. **另有「八爪鱼智能体 OpenOcta」，和数阔八爪鱼不是同一产品。** 官网是 [openocta.com](https://openocta.com/)。官网前端页脚把公司写成「杭州乘云数字技术有限公司」，备案号为浙ICP备2023046722号-2。页面会拿 WorkBuddy 企业版做选型对比，这会加重「腾讯八爪鱼」的误读；对比文案不能当成腾讯出品声明。
4. **数阔文档写了它和腾讯 Agent 的对接，两边口径还没有完全对齐。** [八爪鱼 MCP 文档](https://www.bazhuayu.com/docs/zh/mcp) 写：采集能力可接入 WorkBuddy、QClaw（小龙虾）等智能体；WorkBuddy 用户可在连接器市场搜索「八爪鱼」，用 OAuth 授权。腾讯云 [WorkBuddy 连接器文档](https://cloud.tencent.com/document/product/1831/134525)（页内标注最近更新 2026-11-03）点名的已支持连接器是 QQ 邮箱、腾讯文档、腾讯乐享、腾讯会议、TAPD、腾讯网盘，并支持自定义连接器，正文没有出现「八爪鱼」。这一条只能并陈，不能写成已经由腾讯官方确认的内置产品。
5. **「ego-lite 浏览器」不是同一产品。** [ego(lite) 中文产品页](https://lite.ego.app/zh-cn) 把它写成面向 AI Agent 的 Chromium 浏览器，公开仓库在 [github.com/citrolabs/ego-lite](https://github.com/citrolabs/ego-lite)。页里没有把它写成腾讯产品，也没有使用「八爪鱼」作为正式名称。两者同属智能体操作网页的大范围，官方材料不能支持合写。

## 二、事实层

资料核对窗口：约 **2026-11-17（北京）**。产品名称、主体、能力和标价，以官网、协议、文档和腾讯云文档原文为准。应用商店详情、二手新闻和社区文章只用来对照入口与叫法，不当作产品规格。

### 2.1 这句话为什么容易对错

「腾讯八爪鱼」不是某一家公司已经写在产品主标题上的官方全称。按这个词去检索，结果会被几件事叠在一起：

- 数阔的「八爪鱼采集器」长期出现在腾讯应用宝、腾讯软件中心等分发渠道里，页面域名和「腾讯下载」标记容易让人把渠道当成出品方。
- 数阔后来把采集能力做成 MCP，文档直接写对接 WorkBuddy、QClaw。
- OpenOcta 把自己定名为「八爪鱼智能体」，官网关键词和问答里又对标 WorkBuddy 企业版、WorkBuddy 本地版。
- 腾讯 2026 年的 Agent 产品线里，外界常用「龙虾」来称呼 QClaw、QQ 浏览器 QBotClaw 等，海生动物的昵称接近，正式名称并不叫「八爪鱼」。

这四条会把不同主体、不同产品，推进同一个搜索词下。下面按官方材料分开写。

### 2.2 数阔「八爪鱼」：名称、主体和产品

[八爪鱼采集器官网](https://www.bazhuayu.com/) 的页面标题是「八爪鱼采集器 - 免费网络爬虫软件_网页大数据抓取工具」。主文案写成：「八爪鱼采集器，百万用户的选择」「无需编写代码就能采集网站数据」。公司简介页 [skieer.com/PR](https://www.skieer.com/PR) 写：深圳数阔信息技术有限公司（原视界信息）2012 年创立；2014 年「八爪鱼大数据采集平台」上线；2022 年品牌升级为「数阔」，旗下产品更名为数阔八爪鱼采集器、数阔云听 CEM、数阔八爪鱼 RPA、数阔八爪鱼数据服务。2023 年「数阔 VOC」上线。国际站点 [octoparse.com](https://www.octoparse.com/) 仍在运营；数阔 MCP 文档把 `https://mcp.octoparse.com` 写成国际环境入口，与国内 `https://mcp.bazhuayu.com` 并列。

服务协议把「八爪鱼」的范围写为：八爪鱼采集器官方网站（www.bazhuayu.com）、八爪鱼 RPA 官方网站（https://rpa.bazhuayu.com）及其客户端。协议更新日期是 2022 年 11 月 2 日。官网页脚和 [数阔官网](https://www.skieer.com/) 页脚都写深圳数阔信息技术有限公司，备案号粤ICP备14092314号。联系地址在官网页脚写为深圳市南山区西丽街道深圳国际创新谷 1 栋 A 座 2001（或「20 楼」）。

[官方下载页](https://www.bazhuayu.com/download) 当前标出的 Windows 客户端是 V10.2.1，更新日期 2026 年 9 月 15 日；系统要求为 Win10/Win11（64 位），Win7/Win8/Win8.1 需改下 V8.7.7。更新说明写：本地采集支持断点续采；新增 AI 助手，可用自然语言修正 XPath、增删字段、格式化数据及配置正则。10.1.0（2026-06-30）还写到「本地浏览器无缝对接，可以直接复用本地登录会话与 Cookies」，并支持识别 shadow 和多层 iframe。应用宝详情页同一版本号为 10.2.1，更新时间写成 2026.10.20，与官网下载页的 9 月 15 日并不相同，宜按两个页面原文并存。

能力口径以官网和文档为准：可视化配置采集流程，使用预置模板或自定义规则，采集公开网页中的文本、图片和文件，并提供云采集、导出和 API。MCP 文档把面向智能体的能力写成：搜索预置模板、触发云采集、查询任务状态、导出数据、检索数据中心存量内容，以及按需采集部分电商数据。文档同时写明若干不支持项，包括仅能在本地运行的任务、创建或编辑任务配置、上传自定义模板、访问账户设置或账单，以及「无预置模板时自动生成任意网页采集规则」。这些是数阔官方对自身产品的说明，不是腾讯产品规格。

### 2.3 它和腾讯的交叉处

数阔八爪鱼和腾讯的关系可以分成三层，不宜并成「腾讯产品」一句：

第一层是分发渠道。腾讯应用宝详情页明确列出开发者、运营者为深圳数阔信息技术有限公司，并单独列出应用宝的开发者、运营者为深圳市腾讯计算机系统有限公司。页面上的「腾讯下载」「已通过腾讯下载数据审核」，说的是分发与安全审核，不能改写成出品关系。

第二层是智能体对接。数阔 [MCP 概述](https://www.bazhuayu.com/docs/zh/mcp) 和 [WorkBuddy 对接文档](https://www.bazhuayu.com/docs/zh/mcp/integrations/workbuddy) 写：WorkBuddy 已经上架八爪鱼连接器，用户在连接器市场搜索「八爪鱼」，完成 OAuth 后，在对话里打开开关即可调用采集能力；也可手动添加通用 HTTP MCP，地址为 `https://mcp.bazhuayu.com`，使用 `Authorization: Bearer <API Key>`。文档还写：免费版也可连接；免费 / 基础版用户每周可通过 MCP 获得 2,000 条免费采集额度；「截至 2026 年 8 月 28 日，八爪鱼采集器 MCP 主入口实测公开 12 个工具」。QClaw 的对接说明出现在数阔自己的文档里，官方入口被写成 qclaw.qq.com。这些都是数阔文档的口径。

第三层是腾讯侧官方文档。腾讯云《连接器》页把连接器定义为「将 WorkBuddy 与外部服务对接」，并写：「当前已支持 QQ 邮箱、腾讯文档、腾讯乐享、腾讯会议、TAPD、腾讯网盘等连接器，同时支持自定义连接器。」同一页提醒「非官方连接器可能存在安全隐患，请优先使用官方推荐连接器」，自定义连接器「按照引导配置自定义的 MCP 连接器」。该页没有点名「八爪鱼」。因此，数阔文档中的「已上架八爪鱼连接器」，还不能直接改写成腾讯云文档里的官方内置连接器清单。结论只能停在「对接关系可见，官方清单未对齐」。

公司简介列出的投资方为拓尔思、协同创新基金、中信资本、红点创投、奇绩创坛、华义创投、景毅投资。官方简介和服务协议里，没有把腾讯写成股东、收购方或产品运营方。完整工商登记和最新年报尚未在正文里核对，股权穿透仍有缺口；就产品协议和站点备案而言，运营主体写的是深圳数阔。

### 2.4 OpenOcta「八爪鱼智能体」

[OpenOcta 官网](https://openocta.com/) 使用的中文名是「八爪鱼智能体」「八爪鱼运维智能体」。首页把产品线分成个人版 Edge 与企业版 AIOps：前者装在 Windows / Mac 电脑上，宣传 SSH / SFTP 纳管、告警分析、故障排查、巡检和脚本执行；后者部署在 Linux 服务器，面向团队告警收敛、工作流和统一管控。页面还写：业务和办公智能体已经独立为 BizzAI，「OpenOcta 只做运维智能体」。

官网前端资源里的页脚字段把公司写成「杭州乘云数字技术有限公司」，版权年份写作「©2017-」加当前年份，备案链接文字为「浙ICP备2023046722号-2」。工信部备案查询页尚未交叉核验，以上是官网自身页脚口径。`/about`、`/legal` 回到站点壳页面或显示「未找到您所要浏览的页面」，没有完整的公司介绍或服务条款正文。官网提到 GitHub，地址常见写法是 github.com/openocta/openocta；该仓库页未提供完整 README 和星标数据，开源仓库的完整核验仍待补。

定价页也需要并陈。人可读的 [定价页](https://openocta.com/pricing) 列出标准版 STD、旗舰版 Ultra 和一体机 ONE，页上没有直接给出人民币标价，旗舰版写「具体方案请联系原厂小助手」。同一站点提供的机器可读摘要 [pricing.md](https://openocta.com/pricing.md) 则写成：社区版（Free）¥0 / 永久免费；专业版（Pro）¥49,800 / 套 / 年；旗舰版（Ultra）联系销售定制。两份官方材料的版本名称并不一致，「标准版 / 专业版」没有在同一页完成对应。价格和授权范围以当时购买沟通和协议为准，不宜把其中一份摘要单独写成确定售价。

OpenOcta 官网的问答和元数据会讨论「搜 WorkBuddy 本地版该看什么」「和 WorkBuddy 企业版怎么选」，并把自身定位为可私有化的对照选项。这只能说明它在争夺同一类搜索和选型，不能说明它是腾讯产品，也不能说明它和数阔八爪鱼属于同一条产品线。

### 2.5 其他容易混进来的名字

检索里还能碰到「飞智八爪鱼」游戏手柄。公开报道写过飞智与腾讯心悦、腾讯先锋云游戏等合作或联名，产品主体是外设品牌飞智，不是腾讯以「八爪鱼」命名的软件。应用宝上也有「八爪鱼进化」一类小游戏，和采集器、智能体这类生产力工具不是同一对象。这些名字只需划开，不再展开。

腾讯「龙虾」线要单独记一笔。它容易和「八爪鱼」一起出现，因为都是海生动物昵称，又都落在 2026 年的 Agent 讨论里。WorkBuddy 官方简介只用「WorkBuddy」「腾讯出品」，不用「八爪鱼」。QClaw、QBotClaw 的详细发布词、是否仍在服务、迁移说明，主要出现在新闻、腾讯云社区文章和数阔对接文档里；没有一篇腾讯产品主文档把正式名称写成「八爪鱼」。若这句话其实指的是 WorkBuddy、QClaw 或 QQ 浏览器里的 Agent，应改用这些产品自己的官方名称，再另做核对。

### 2.6 账号、计费和限制

数阔八爪鱼需要注册账号后登录客户端或云端使用。[套餐页](https://www.bazhuayu.com/plan) 明确标出：免费版 ¥0；个人版 ¥79 / 月；团队版 ¥359 / 月。附加项包括：本地加速任务数 ¥69 / 个 / 月（个人及以上版本可购买）；云节点 ¥189 / 2 个 / 月（团队及以上版本可购买）。企业版页内写定制云节点、多账号多设备、监控预警和专属服务，并出现「赠 2999 元企业专属培训」。对比表里还能看到 ¥599、¥2999 等数字，这些数字对应的年付或企业档标签，套餐页对比表没有完整给出，不宜自行配对。免费版可见的限制包括任务数 100、手动导出、数据导出量 5 万条 / 月等；更高版本的节点数、并发和自动导出以套餐页当时展示为准。

OpenOcta 个人版在官网以免费下载安装包的方式提供；企业版售价见上一节两份定价材料的差异。两端价格都可能调整，购买前以当时页面和销售确认到的协议为准。

## 三、结构分析

真正卡住判断的，是「腾讯」和「八爪鱼」被写在同一个词里。某一项采集功能或智能体能力列得全不全，还在其次。拆开以后，这句话至少对应三种不同的理解，后续跟不跟进也不一样。

第一种，把分发渠道或连接器当成出品方。数阔八爪鱼出现在应用宝，又在自己的文档里写对接 WorkBuddy，检索结果会看起来很「腾讯」。协议、备案和应用宝开发者栏，却把运营主体写在深圳数阔。按这个理解，对象是一家独立的数据采集 / RPA 公司的成熟产品，和腾讯的关系是渠道与接口。

第二种，把腾讯 2026 年的 Agent 线记成了「八爪鱼」。WorkBuddy 的官方简介很清楚，产品名是 WorkBuddy。外界常用的「龙虾」也指向 QClaw、QBotClaw 等，并不等于「八爪鱼」。OpenOcta 又主动用八爪鱼这个中文名，去对标 WorkBuddy 的选型搜索，会让第二种误读更难解开。

第三种，另有尚未见到的腾讯官方材料：新发布、内测名称、活动页或海报把某款产品叫成了「八爪鱼」。官方站点、协议和文档里，还没有出现这样一份原文。检索未命中，不等于日后不会出现这个名字。结论只能停在：公开官方材料还撑不起「腾讯自有产品名叫八爪鱼」这一句。

和 ego-lite 的关系也落在同一层结构里。ego-lite 要解决的是：人与 Agent 共用一个已登录的浏览器，Agent 在隔离 Space 里操作页面。数阔八爪鱼要解决的是模板化、云端或本地的网页数据采集。OpenOcta 要解决的是本机或私有化环境里的运维智能体。WorkBuddy 是腾讯出品的 AI 工作台。它们会在「让智能体操作真实网页或本地环境」这个大范围里相遇，产品主体、正式名称和官方定义并不重合。

## 四、外部研判

外部判断是：**观望**。在所指对象被确认之前，不按「腾讯自有产品：八爪鱼」去跟进试用、采购或写成既定产品线。

如果指向的是数阔八爪鱼采集器或 RPA，可以把它当作独立第三方工具继续看：官网套餐、客户端版本、MCP 对 WorkBuddy 的实际连接效果，以及采集合规边界。判断依据应回到 bazhuayu.com 的协议和购买页，不要写成腾讯产品更新。

如果指向的是 OpenOcta，需要先补公司主体的工商核验、开源仓库和两份定价材料之间的版本对应，再决定是否试用个人版或接触企业版。它和腾讯的关系，只见于官网自己的对标表述。
