# 直接对接真实 5G 网关——WorkBuddy MCP 安装指引

> 配套连接器：`5g-msg-channel`（版本 1.0.0）
> 难度：★☆☆☆☆（按步骤复制粘贴即可，不需要懂代码）
> 耗时：约 5 分钟
> 适用场景：已拿到平台账号，需要真实收发 5G 消息（会产生费用）

---

## 0. 先看一眼：装好后能做什么？

装好后你**在 WorkBuddy 对话里直接打字**就能调用，比如：

```
帮我用 send_5g 给 13800138000 发消息，内容：你好
```

或检查链路状态：

```
用 bridge_status 工具查一下链路状态
```

---

## 1. 先找平台/负责人要 2 样东西（必须先拿到）

对接真实网关前必须拿到以下两项：

| 需要什么 | 填到哪个变量 | 长什么样（示例） |
|---|---|---|
| ① 网关 WebSocket 地址 | `MAAP_WS_URL` | `wss://5gvas01.cmicmaap.com/gtw-ai/openclaw/ws/msg` |
| ② API 钥匙 | `MAAP_API_KEY` | `ak_xxxxxxxx` |

> 💡 顺便确认：
> 1. 你的业务手机号（机器人号）已经开通 5G 消息服务；
> 2. 你知道自己的手机号（用于发测试消息）；
> 3. 问清楚机器人号允许哪些上行号码触发（用于填白名单）。

## 2. 准备工作（四步必做）

### ✅ ① 确认并记下「项目根目录」路径

先确认你把 `5g-msg-channel` 文件夹放在哪个位置，下面统一叫 `<你的项目根目录>`，例如：

| 你把文件夹放在哪 | `<你的项目根目录>` 就是 |
|---|---|
| `D:\apps\5g-msg-channel\` | `D:\apps\5g-msg-channel` |
| `E:\公司项目\5g-msg-channel\` | `E:\公司项目\5g-msg-channel` |

检查这个路径下 **必须存在** `<你的项目根目录>\connector\src\index.cjs`。找不到先找负责人要完整项目文件夹。

### ✅ ② node 命令怎么写（三选一，优先最简单的）

先在终端里输入：

```bash
node -v
```

然后按下面规则选择：

| 情况 | `"command"` 写什么 | 说明 |
|---|---|---|
| `node -v` **能显示版本号**（比如 `v22.22.2`） | 就写：`node` | ✅ **推荐！最简单，不用管路径** |
| `node -v` 报错但你**自己装了 node** | 写安装路径，例如：`C:\Program Files\nodejs\node.exe` | 装在其它盘就写对应路径，比如 `D:\\dev\\nodejs\\node.exe` |
| `node -v` 报错、也没自己装 → **用 WorkBuddy 自带的 node** | 参考下面例子拼路径 | WorkBuddy 自带的在 `.workbuddy\binaries\node\versions\` 下 |

**怎么拿到 WorkBuddy 自带 node 的完整路径：**

用记事本打开这个文件（里面只有一行版本号）：

```
C:\Users\<你的用户名>\.workbuddy\binaries\node\versions\current
```

假设看到的是 `22.22.2-2`，那么 node 完整路径就是：

```
C:\Users\<你的用户名>\.workbuddy\binaries\node\versions\22.22.2-2\node.exe
```

**真实示例（用户名叫 `jx`，版本是 `22.22.2-2`）**：

```
C:\Users\jx\.workbuddy\binaries\node\versions\22.22.2-2\node.exe
```

> 💡 每台电脑用户名 / 版本号可能不同，**请用你自己记事本里看到的那一行替换**。

### ✅ ③ 安装依赖（只要一次，以后不用再装）

打开终端执行（把 `<你的项目根目录>` 换成①的路径）：

```bash
cd <你的项目根目录>
npm run install:all
```

或手动进入子目录：

```bash
cd <你的项目根目录>\connector
npm install
```

## 3. 在 WorkBuddy 界面添加（推荐新手用）

### 3.1 打开 MCP 管理页

1. 打开 WorkBuddy → 左侧边栏找 **「连接器 / MCP」** → 点进去
2. 点 **「添加 MCP 服务器」** 或右上角 **「+」**

### 3.2 按下表填写

| 填写项 | 填什么 |
|---|---|
| 服务器名称 | `5g-msg-channel`（随便起，建议这个） |
| 命令 / Command | **推荐**写：`node`（走系统 PATH）<br>不行就写绝对路径，参考第 2 步②（WorkBuddy 自带 node 示例：`C:\Users\jx\.workbuddy\binaries\node\versions\22.22.2-2\node.exe`） |
| 参数 / Args | **只填入口文件路径，不要加 `--mock`**<br>`<你的项目根目录>\connector\src\index.cjs` |
| 环境变量 / Env | 见下表 |

**环境变量（直连真实网关必填）**：

| 变量名 | 值 | 必填？ | 说明 |
|---|---|---|---|
| `MAAP_WS_URL` | 平台给的网关地址（第 1 节的①） | ✅ | 真实平台 WS 地址 |
| `MAAP_API_KEY` | 平台给的钥匙（第 1 节的②） | ✅ | 真实认证凭证 |
| `ACP_CWD` | `C:\Users\<你>\WorkBuddy\<项目文件夹>` | ✅ | 告诉 AI 在哪个目录干活 |
| `ALLOWED_SENDERS` | `13800138000,13900139000` | ⚠️ 强烈建议 | **只允许这些手机号触发 AI** |
| `ENFORCE_WHITELIST` | `true` | ⚠️ 强烈建议 | 开启白名单强制校验 |
| `ACP_SESSION_ID` | （可选）你的会话 ID | ❌ | 想指定 AI 用哪个会话再填 |
| `BRIDGE_MAX_QUEUE` | 默认 500 | ❌ | 队列上限，超限自动拒发 |
| `TASK_TIMEOUT_MS` | 默认 120000 | ❌ | 单条 AI 任务超时（毫秒） |
| `LOG_LEVEL` | `info` / `debug` / `warn` / `error` | ❌ | 日志级别 |

> 🛡️ **白名单为什么强烈建议填**：
> 真实网关下，**任何能发 5G 消息到机器人号的人**都能触发 AI 干活、产生费用。
> 填上 `ALLOWED_SENDERS` + `ENFORCE_WHITELIST=true`，只有白名单号码能触发。

### 3.3 保存 + 信任（最容易漏！）

点 **保存** → 在列表里找到刚添加的 `5g-msg-channel` → 点 **「信任 / Trust」** 按钮

> ⚠️ 不点信任 = 不生效。新手 90% 卡在这里。

## 4. 或直接改配置文件（老鸟推荐，界面找不到时用）

打开 `C:\Users\<你的用户名>\.workbuddy\mcp.json`，**整个替换**为以下内容，把 `<...>` 换成你自己的值：

```json
{
  "mcpServers": {
    "5g-msg-channel": {
      "command": "node",
      "args": [
        "<你的项目根目录，反斜杠两个>\\connector\\src\\index.cjs"
      ],
      "env": {
        "MAAP_WS_URL": "wss://5gvas01.cmicmaap.com/gtw-ai/openclaw/ws/msg",
        "MAAP_API_KEY": "ak_<平台给你的钥匙>",
        "ALLOWED_SENDERS": "13800138000",
        "ENFORCE_WHITELIST": "true",
        "ACP_CWD": "C:\\Users\\<你的用户名>\\WorkBuddy\\<你的项目文件夹>",
        "ACP_SESSION_ID": "<可选：你的会话ID>"
      },
      "disabled": false
    }
  }
}
```

保存后：**重启 WorkBuddy** → 打开 MCP 管理页 → 点 **「信任」**

> 💡 **`"command"` 怎么写（按推荐顺序三选一）：**
>
> ① 终端里 `node -v` 能显示版本号 → **写 `"node"`（推荐，最简单）**
>
> ② 自己装了 node，知道安装路径 → 例如：
> ```
> "C:\\Program Files\\nodejs\\node.exe"
> ```
>
> ③ 用 WorkBuddy 自带的 node（参考第 2 步②里的 `current` 文件）→ 示例：
> ```
> "C:\\Users\\jx\\.workbuddy\\binaries\\node\\versions\\22.22.2-2\\node.exe"
> ```
> （把 `jx` 换成你的用户名、`22.22.2-2` 换成 `current` 文件里那行版本号）
>
> ⚠️ JSON 格式坑：路径里的单个 `\` **必须**写成 `\\`（两个反斜杠）。
> 例如你的项目在 `D:\apps\5g-msg-channel`，`args` 里必须写成 `D:\\apps\\5g-msg-channel\\connector\\src\\index.cjs`。

## 5. 进阶：指定 AI 用哪个会话？（可选）

有两种方式指定 `ACP_SESSION_ID`，**任选一种即可**：

### 方式 A：写在 mcp.json 的 env 里（推荐）

在第 4 节 mcp.json 的 `"env"` 中加一行：

```json
"ACP_SESSION_ID": "d0bac45c-b979-47d2-a4d9-76f8f3ca2485"
```

### 方式 B：写在连接器的 .env 文件里

在 `<你的项目根目录>\connector\` 目录下新建 `.env` 文件，内容：

```
ACP_SESSION_ID=d0bac45c-b979-47d2-a4d9-76f8f3ca2485
```

### 行为规则

```
填了 sessionId → 启动时优先用这个会话
   ├─ 能用 ✅ → 就用它
   └─ 失效/报错 ❌ → 自动新建会话并记住（下次自动用新的）

没填 → 自动新建会话并记住，重启自动复用
```

> 💡 想强制从头开始？删掉 `<你的项目根目录>\connector\.session.json` 再重启。

## 6. 验证是否成功（必须做！）

### 6.1 WorkBuddy 对话里发一条测试

打开一个新对话，输入：

```
用 send_5g 工具给 13800138000 发一条消息，内容写：你好，这是真实5G消息测试
```

### 6.2 判断结果

| 现象 | 说明 |
|---|---|
| AI 回复 `sent ...` 或成功字样 + **手机收到消息** | ✅ **大功告成！** |
| AI 说「没有这个工具 / 找不到 send_5g」 | ❌ 没注册成功 → 检查配置 + 是否点了「信任」 |
| AI 说「5G WS 未连接」 | ❌ 网关地址或 API_KEY 填错 → 回第 1 节核对 |
| AI 说「auth_failed」 | ❌ `MAAP_API_KEY` 不对 → 问平台要正确值 |
| 手机没收到但 AI 说成功 | ⚠️ 检查号码是否真开通了 5G 消息；或机器人号白名单 |

### 6.3 查链路状态（排障用）

在对话里输入：

```
用 bridge_status 工具查一下链路状态
```

看到返回里有 `"wsConnected": true` 说明网关链路 OK。

## 7. 常见问题（小白问答）

**Q1：找不到「连接器 / MCP」入口在哪？**<br>
A：左侧边栏找图标（插头/拼图/齿轮），可能叫「连接器」或「MCP」。真找不到就用第 4 节方式 B（直接改 mcp.json 文件）最稳。

**Q2：「信任」按钮在哪？**<br>
A：添加后列表那一行右侧，可能是开关样式或「信任 / Trust」文字。

**Q3：改了配置但没反应？**<br>
A：按顺序来 → ① 重启 WorkBuddy；② 打开 MCP 管理页确认「信任」是开的。新手最容易漏这两步。

**Q4：node 路径怎么验证对不对？**<br>
A：复制 node.exe 的完整路径到文件资源管理器地址栏按回车，**能看到 node.exe 本体**就是对的。

**Q5：报错 `auth_failed` / `WS 未连接`？**<br>
A：
- 先核对 `MAAP_WS_URL` 和 `MAAP_API_KEY` 是否是平台给的原始值（有没有多一个空格、少复制字符）。
- 白名单如果开了，检查 `ALLOWED_SENDERS` 里的号码是不是**带国家码格式**，有时平台要求是 `8613800138000`。

**Q6：真实网关下别人发短信过来，AI 没反应？**<br>
A：按顺序排：
1. 你的机器人号是不是真的收到了那条短信（先在平台后台/接口日志确认）；
2. `ENFORCE_WHITELIST=true` 时，那个号码**必须**在 `ALLOWED_SENDERS` 里；
3. 让对方再发一条，看 `bridge_status` 里 `queueLength` / `processed` / `failed` 数字有没有变化；
4. 都不行就把 `LOG_LEVEL=debug` 加上重跑，去 `connector/logs/` 看当天日志。

**Q7：我想临时禁用它怎么办？**<br>
A：MCP 管理页找到 `5g-msg-channel`，点禁用 / 删除即可；或在 mcp.json 里 `"disabled": true`。

**Q8：日志文件在哪看？**<br>
A：默认 `<你的项目根目录>\connector\logs\channel-YYYY-MM-DD.log`，每天一个新文件。
