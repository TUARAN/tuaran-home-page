# 设计说明

## 已确认的页面结构

- 待办列表：`.todo-table .ivu-table-tbody > tr.ivu-table-row`
- 标题：每行内 `.title.oneLine`
- 详情动作：`button[label="一键提交"][event="onekeySubmit"]`
- 一键提交弹窗：标题包含“一键提交”
- 最终动作：弹窗内 `.onekey-submit-button`，可见文案为“提交”

截图中的类名、属性和用户提供的 DOM 相互印证。列表列宽、动态生成的 `ivu-table-column-*` 类、水印和人员姓名不参与定位。

## 状态机

```text
待办列表
  -> 打开一条标题
等待详情
  -> 点击一键提交
等待提交弹窗
  -> 点击弹窗内最终提交
等待返回列表
  -> 记录完成并处理下一条
```

状态只有在预期元素可见且可操作时才向前推进。每一阶段有超时，超时后停止整个批次并显示当前标题和失败阶段。

## 关键取舍

- 使用 `activeTab` 临时授权，不申请 `<all_urls>`，减少对其他网页的访问范围。
- 采用 Shadow DOM 面板，避免 OA 自身 CSS 污染控制面板，也避免扩展样式影响 OA。
- 行指纹由标题、文种、提交人、接收时间等单元格文本组合而成，降低列表刷新后重复处理的风险。
- 连续模式默认上限 20 条；另有“单步一条”用于上线前验收。
- 页面进入后台时暂停点击与延时。
- 不自动刷新、不关闭页面、不处理确认文案不明确的额外弹窗。

## 已知边界

普通模式假定详情与两级弹窗处于同一标签页的同一顶层文档中。Canvas 模式通过一次真实闭环校准相对坐标和按钮灰度模板，每一步重新截图并在预期位置附近做归一化相关匹配；点击使用 Chrome Debugger Protocol。宽高比变化超过 8%、置信度不足、新窗口或跨域标签页都会停止，不会越过未知步骤。
