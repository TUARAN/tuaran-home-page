# WorkBuddy 申请材料草稿

**申请类别：常规第三方应用（待平台确认入口）。** 附图“硬件接入”表单会核实真实硬件产品；软件桌宠不具备这一前提。未获得平台确认之前不提交“硬件类型”或把本机模拟器描述为实物硬件。

| 字段 | 建议填写 |
| --- | --- |
| 应用名称（≤32 字） | 鹿鹿精灵 |
| 应用图标 | 使用本目录 `icon.png`（鹿鹿头像，1:1 PNG，1254×1254，≤2 MB） |
| 应用介绍（≤200 字） | 鹿鹿精灵是一只陪伴用户工作的长颈鹿桌宠。用户可点击鹿鹿互动，并在输入文字、点击发送后，让已授权的 WorkBuddy 本地助理处理请求。鹿鹿显示连接状态与回复；离线时提供明确标记的本地演示，不读取通讯录或自动执行任务。 |
| 产品链接 | 产品页发布后填写 `https://2aran.com/tools/workbuddy-desktop-pet`；发布前不能提交未上线链接 |
| 应用场景（≤500 字） | 用户在电脑工作时，桌宠显示于桌面边缘。用户主动输入工作问题或指令并点击发送；应用检测本地助理是否可用，将这条文字发给 WorkBuddy 本地助理，随后读取本次消息之后的回复并显示在桌宠会话区。用户可随时关闭桌宠，离线交互在本机完成。申请读取本地助理状态与消息历史仅用于连接状态和本次回复展示；申请发送消息仅用于用户明确点击发送后的任务执行。应用不需要手机号、头像、云端任务或积分权限。 |
| Scope | `user.localassistant.readable`、`user.localassistant.invokable` |
| OAuth 回调 | 在正式服务端 OAuth 方案确定后登记精确 HTTPS 地址；本机开发联调可以用 `http://localhost:8080/workbuddy/api`，须与桥接器配置逐字一致，且仅供本地测试 |
| 其他证明材料 | 产品截图、桌面运行视频、真实产品页、隐私说明；截图所示可选附件最多 3 个、单个 ≤10 MB |

**两项 Scope 的审核理由**

- `user.localassistant.readable`：只查询当前授权用户的本地助理在线状态，并在用户发送后读取相应消息的回复，向用户展示处理结果。
- `user.localassistant.invokable`：用户在桌宠输入框点击发送后，将该条文字发送给其 PC 上已授权的本地助理；不在后台自动发送。

**提交前核验**：确认平台是否向常规第三方应用开放上述 Scope；真实获批应用的 Client ID、服务端 Secret 与回调已配置；演示与材料描述一致；产品页已上线；图标和实际运行截图已上传。审核通过前不宣称已经获得官方权限。获批后再进行真账号 OAuth、在线状态、发送、历史读取的端到端验证。

依据：[第三方应用](https://open.workbuddy.cn/docs/third-party-app)、[Open API 接口](https://open.workbuddy.cn/docs/openapi)；字段尺寸、字数和附件限制取自用户提供的申请表截图。官方文档未给出桌宠软件在“硬件接入”栏的豁免规则。
