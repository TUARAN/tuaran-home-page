# X高频互动助手

站内入口：<https://2aran.com/resources/x-reply-clipboard-extension>。工具集的「推特工具」和下载中心都会链到这一页。

版本规则与发版记录格式见 [VERSIONING.md](VERSIONING.md)。本地测试版 v3.27.24；公开下载仍为 v3.12.1，要求联系站长获取密码后下载。

站长在 `/admin/community-actions?tab=extension` 的「X 高频互动助手」卡片生成新下载密码。新密码立即生效，旧密码失效；后台只保存校验值，明文仅在生成时显示一次。本次站点管理功能不改变扩展版本号。

本地 Chrome Manifest V3 扩展。面板顶部提供四个分组，新安装默认选择回复管理的首页互动：

- **回复管理**：分为「首页互动」和「通知互动」两个子页签。首页互动从上往下回复首页帖子；通知互动只处理最近 2 小时内别人对当前账号的回复，先点赞再回复。两项各有独立任务窗口，切换子页签不会启动任务。
- **点赞管理**：分为「首页帖子」和「帖子评论」两个子页签，可随「全流程启动」一起运行，也可各自手动启停，并保留独立处理历史。首页帖子只点赞刷到的帖子；帖子评论逐个打开首页帖子，只点赞评论，不重复点赞原帖。X 官方自动化规则不允许自动点赞。次数限制会暂停 1、2、6 小时后尝试继续，持续受限则停止；疑似自动化或账号限制会立即停止。
- **关注管理**：提供清理未回关和回关粉丝；关注候选暂时折叠并停用，不会随全流程启动。
- **定时发帖**：只从热点取材，先读取知乎热榜，再读今日头条；素材不足时才读取 2aran 舆情分析的近期热点。发推使用设置页的提示词，参考王长富直接表达观点的节奏，不抓取或改写他的帖子。不编现场情节；通常分成二至四个短段，每段一行、段间留空，极短的一句话可单行。用过的素材 ID 和已发主题保存在 Chrome 本地；待发列表和发布历史保留来源、原始链接及站内选题页。主题重复、语气过火或不合格的素材会跳过。旧版待发草稿不会继续发送。第一条立即发送，之后每条随机间隔 25～35 分钟。

任务会在 X 首页等待发帖框和 Post 按钮真正出现，再发送待发列表的第一条；页面尚在加载时会继续检查，不计为发送失败。

X 提示「You already said that」时，定时发帖会清空这条草稿，跳过当前待发内容并立即尝试下一条。

两个回复助手优先使用 DeepSeek 阅读当前帖子后生成回复。遇到服务繁忙、限流、网关错误或超时，先通过 2aran.com 的受限接口调用后台已启用的 NAS Ollama 模型；NAS 失败后，再使用设置中保存的 B.AI Key 调用 `gpt-6-luna`。B.AI Key 只保存在 Chrome 扩展本地，不打入源码或下载包。DeepSeek 密钥错误和内容错误不触发回退。NAS 回退记录会进入后台模型调用台账；扩展直连 DeepSeek 和 B.AI 的请求不会进入站点台账。三端都失败时，当前帖子按 3、8、20、30 秒逐步重试，不当作已回复。

标题栏右上角的四格图标打开「X 工具箱」。在单条推文详情页可将当前推文排版为 PDF，再在打印窗口选择保存；工具箱内可关闭或重新启用导出。原独立的互关清理插件功能已并入「关注管理」；X 长文自动发布保留为独立扩展，单独管理站点密钥和定时任务。

时间线每次先按当前频率挡位生成一份随机计划。轮次进度里可以从单行按钮选择慢、中、快、超快，默认是「中」：3～5 轮，每轮 25～35 条；每条成功后随机等待 5～15 秒，整次完成后随机休息 2～3 小时再生成下一份计划。通知回复使用同一套挡位决定每条间隔和扫描后的休息，并继续使用持久历史去重。已经开始的计划和正在进行的等待不会因为改挡位而改写。插件不对时间线和通知回复设置每日总量。页面暂时不可用时从 2 秒开始逐步重试，最长间隔 30 秒；网络恢复事件会立即唤醒重试。标题栏显示整个插件从任一任务启动后累计的稳定运行时长，各任务单独显示自己的运行时间；只有最后一个任务停止或对应任务页签关闭时，整体计时才结束。

## 安装

1. 打开 Chrome：`chrome://extensions/`
2. 开启「开发者模式」。
3. 点击「加载已解压的扩展程序」。
4. 选择本目录：

```text
tools/x-reply-clipboard-extension
```

已经装过旧版时，在扩展管理页点这个扩展的刷新按钮。

## 使用

1. 在 Chrome 里登录 X。
2. 面板默认浮在页面右下角。标题栏齿轮里可以打开「嵌入到页面」，再挂到右侧搜索框下方。顶部依次是回复管理、点赞管理、关注管理、定时发帖；点分组内的子页签会切到对应任务窗口。
3. 互关任务按提示打开 Following / Followers 列表；回复和点赞任务在各自窗口点击开始按钮。
4. 首次运行先填写 DeepSeek API Key；配置后主面板收起密钥栏，可在右上角设置修改。
5. 工作区的单行按钮选择慢、中、快或超快。每一挡的具体数字在「频率设置」里修改；提示词和 API Key 在「模型设置」里修改，改动自动保存。
6. 需要停止时，点「停止」。
7. 要在后台看到回执，打开 `/admin/community-actions`，把回执密钥贴到设置里的「社区回执」。不填则不上传。
8. 在右上角展开操作菜单，打开「每日报告」。可按账号查看本机已存记录的累计统计，也可在月历选日期查看当天五项数字；选定单个账号后点「上传当日报告」会发送到后台「社区动作 → 浏览器插件」。需先应用 `0112_x_extension_daily_reports.sql`。重复上传同一天会更新该天汇总；「一键清空状态」保留本机报告和限制观察日志。

## 长时间运行与锁屏排查（2026-10-18）

这台 Mac 的接电源配置经 `pmset -g custom` 核对为 `sleep 0`、`displaysleep 10`：接电时允许显示器约 10 分钟后关闭，系统不因空闲自动睡眠。锁屏设置没有改动。屏幕关闭或锁定本身不等于系统睡眠；合盖、手动睡眠、断电、Chrome 退出或任务标签页停用仍可能中断自动化。检查时 `pmset -g batt` 同时显示 `AC Power` 和电池「discharging」，因此还要核对电源适配器、连接及之后的电量变化，不能仅凭接电源配置认定机器能持续运行。

Chrome「Aran」配置文件已在 `chrome://settings/performance` 核对：省内存模式原本关闭；2026-10-18 关闭了节能模式，并将 `x.com` 加入「始终让以下网站保持活跃状态」。需要保持 Chrome、扩展和已登录的 X 任务标签页打开。Chrome 设置仅减少后台标签页被节能策略停用的机会，不能唤醒已睡眠的 Mac，也不能保证 X 页面和登录态始终可用。

复盘时先在插件中启动任务，锁屏观察一段时间，再打开后台「社区动作 → X 插件监控」（`/admin/community-actions/x-monitor`）比较最近心跳、任务状态、最近确认动作和最近异常。该页面上线后才可从线上访问；本地代码存在不代表线上已部署。「有心跳」只说明插件近期能连接后台，不能单独证明任务持续执行；若心跳仍在而确认动作长期不变，应结合任务的等待截止时间、X 登录态和异常回执排查。超过 5 分钟没有心跳，先检查 Mac 是否睡眠或电池耗尽、Chrome 是否仍在运行、扩展和 X 标签页是否打开、回执密钥及网络连接。

扩展的长等待由离屏计时器处理，后台心跳通过 Chrome alarm 定期触发；这些机制均不能唤醒已经睡眠的设备。参考：[Apple 的睡眠与锁屏说明](https://support.apple.com/en-ie/guide/mac-help/mchle41a6ccd/mac)、[Chrome 始终保持网站活跃](https://support.google.com/chrome/answer/12929150)、[Chrome alarms 限制](https://developer.chrome.com/docs/extensions/reference/api/alarms)。

「定时发帖」只发送纯文字。先取知乎热榜，再取今日头条；两者素材不足时才读 2aran 舆情分析。生成后放进待发列表，列表没发完不会重新抓取。正文排成短行，每行之间空一行；面板显示下一次发布倒计时，默认「中」是 25～35 分钟。发帖框已有其他内容时等待人工处理。

「关注候选」每次从 @crazypig9y、@jianlvup、@jianlvya、@kyotom08、@Chill_Alpha 里随机打开一个 Followers 页面。「清理未回关」「回关粉丝」和「关注候选」共用同一组额度：每 2 秒操作 1 个，三项合计每完成 15 个暂停 30 分钟，每日合计最多 400 个。今日数量、本批进度和暂停时间保存在 Chrome 扩展本地存储中，并按本地日期重置。

扩展只操作启动任务的 X 标签页。回复管理的两项、点赞管理的两项、定时发帖以及关注管理的三项各用一个任务窗口。点子页签会打开尚未创建的任务窗口，已打开则跳转；原窗口仍停在自己的页面，正在运行的任务继续跑。具体任务子页签的箭头表示跳转，悬停时旁边出现独立叉号，可关闭该任务窗口。不要把两个任务放进同一个窗口的不同页签，Chrome 会冻住被盖住的后台页签。也不要手动刷新正在执行任务的窗口。

面板中的每条间隔从发送成功后开始，按当前挡位随机抽取并计算，不包含 AI 生成、弹窗出现、编辑器写入和发送确认所需的时间。默认「中」是 5～15 秒。出现重试时，总耗时会继续增加；v3.2.0 已缩短单步超时并减少后台计时消息，避免 v3.1.6 在前台也被离屏轮询拖慢。
