# 小红书高频互动助手

本地 Chrome Manifest V3 扩展。推荐评论在小红书首页运行。笔记浇给在创作服务平台运行，用 DeepSeek 把今天的 AI 资讯写成图文笔记并发布。

## 版本与发布

`manifest.json` 是当前可安装代码的版本号。开发中的修改可以合并验证；准备交给人加载或测试时，先验证，再按影响升版并在这里记录。交付过的版本内容冻结，后续行为修改使用新版本号。只改文档不升版。公开 ZIP 和下载页仅列实际上传并验证可下载的版本；打包本身不升版。兼容修复升 PATCH，新增兼容功能升 MINOR，破坏已有设置或使用方式升 MAJOR，版本号使用三段数字。

当前本地测试版为 v0.7.0。此扩展尚无公开下载 ZIP；不得将本地测试版写成已发布版。真正上传 ZIP 后，才将对应记录标为“已发布”，补上发布日期、下载文件名、SHA-256 和对应提交，并核对 `manifest.version`、面板版本、ZIP 文件名与 ZIP 内版本一致。旧记录缺少的信息不追填猜测值。

## 高质帖管理

打开 `https://creator.xiaohongshu.com/new/note-manager` 后，右上角助手面板的「高质帖管理」只扫描当前已加载的卡片。面板可选最近 7 天、最近 1 个月、最近 3 个月或全部笔记，默认最近 1 个月；范围按页面显示的发布时间计算，边界当天的具体时刻也参与比较。点击「开始设置」后先处理当前范围内的候选，处理完才滚动加载下一批。若已加载卡片的发布时间全部可读且确认为倒序，越过范围后停止滚动；若排序不明则继续到列表末尾。日期无法读取的卡片在限定范围内跳过。评论数严格大于 10 的笔记设为「公开可见」，即使点赞不足 100；其余评论数不超过 10、点赞数严格低于 100 的笔记设为「仅自己可见」。恰好 10 条评论或恰好 100 赞不跨阈值；没有命中任一规则的笔记保持原权限。评论数无法识别时不会贸然设为私密；点赞数无法识别且评论数未超过 10 时也跳过。已符合目标权限的笔记不重复保存。每篇修改后重新打开同一笔记的权限弹窗核验；单篇在操作前指标变化、按钮结构不符或下拉框切换失败且弹窗已安全关闭时会跳过。若滚动后没有新笔记且无法确认到达末尾、弹窗无法关闭，或提交后的保存与核验出现异常，会停止并显示原因；可点「停止」中断后续笔记。

### 权限下拉框为什么难点开

**现场已验证的现象。**「权限设置」弹窗中的控件是由 `.perm-select-wrapper`、`.d-select-main`、`.d-select-suffix-indicator` 等 `div` 组成的自定义选择器，并非原生 `<select>`。五个权限选项在收起时已经存在于 `.d-options-wrapper`，但容器宽度为 0、不可见；因此仅凭 DOM 里能搜到「仅自己可见」，不能认为菜单已展开。用浏览器真实点击箭头能展开菜单；在同一个弹窗里，扩展调用 `arrow.click()`、自行派发指针按压事件、调用 `main.click()` 均未展开。v0.3.8 的实际报错进一步显示，点击位置有时被 `perm-loading-mask` 覆盖；这说明弹窗还可能处于加载阶段，即使选项节点已存在也不能立即点击。以上仍未定位到小红书组件内部具体哪条判断。

**浏览器机制与业内做法。** [`HTMLElement.click()`](https://developer.mozilla.org/en-US/docs/Web/API/HTMLElement/click) 只模拟一次 `click`，不会自动完成真实鼠标的移动、按下、抬起及焦点变化；它生成的 `click` 事件的 [`isTrusted` 为 `false`](https://developer.mozilla.org/en-US/docs/Web/API/Event/isTrusted)。自定义下拉框的展开条件由组件自己实现，[WAI-ARIA 的 combobox 指南](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)也明确允许不同的展开触发方式。因此不能推断所有网站的自定义下拉框都拒绝 `.click()`。常规浏览器自动化更接近用户输入：例如 [Playwright 的 `locator.click()`](https://playwright.dev/docs/input) 会等控件可见、稳定、未被遮挡，再发送鼠标操作，并将直接派发 `click` 作为另一种单独的方式。本扩展据此检查控件可见和命中位置，用 Chrome 的 [`debugger` API](https://developer.chrome.com/docs/extensions/reference/api/debugger) 发送 [CDP 鼠标移动、按下、抬起事件](https://chromedevtools.github.io/devtools-protocol/tot/Input/)，然后检查菜单、选中值和保存后的值。

**安全判断的边界。** 小红书可能依赖完整的指针事件顺序、焦点或事件来源，也可能有其他组件状态条件；目前没有证据确认它专门用 `isTrusted` 拦截自动化，不能把这次现象定性为反机器人或安全管控。Chrome 内容脚本运行在[隔离环境](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)，但仍与页面共享 DOM；单凭隔离环境也不能解释此次差异。`debugger` 是权限较大的浏览器 API，扩展代码将消息限制在创作平台笔记管理页，单次点击后立即解除附加；用户仍应留意 Chrome 的权限提示。真实账号上的 v0.4.0 结果须以重新加载扩展后的操作与保存复核为准。

## 推荐评论

在已登录的 `https://www.xiaohongshu.com/explore` 推荐频道里，从上往下打开别人的笔记。读标题、正文和已经出现的几条评论，交给 DeepSeek Flash 写 12～40 个字的评论，填进底部「说点什么...」，再点发送。

自己的笔记、没有文字的笔记、已经评论过的笔记会跳过。评论框里如果已经有手写内容，任务会停下来，不会覆盖。

频率默认是「中」：每轮 12～20 条，成功后等待 8～16 秒，一轮结束后休息 90～150 分钟。慢、快、超快可以在面板里滑。已经开始的等待不会因为改挡位而改写。

DeepSeek API Key 只保存在这个扩展自己的 Chrome 本地存储里，和 X 高频互动助手不共用。请求只带笔记文字，不带小红书登录 Cookie。

评论或笔记确认成功、跳过、失败或受限时，可以把回执发到站长后台的社区动作页。在设置里粘贴同一把回执密钥。不填则不上传。上传内容只有任务项、结果、笔记编号和错误码，不包含正文和登录 Cookie。网站页面不用一直开着。

## 安装

1. 打开 `chrome://extensions/`
2. 开启开发者模式
3. 加载已解压的扩展程序，选择：

```text
tools/xhs-interaction-extension
```

改完代码后，在扩展管理页刷新这个扩展，再刷新小红书标签页和创作服务平台标签页。

## 笔记浇给

发文页是 `https://creator.xiaohongshu.com/publish/publish?from=menu&target=image`。页面默认可能停在「上传视频」。任务会点「上传图文」，再点「文字配图」，把两张卡片交给小红书的配图模板，然后填写标题和正文，点「发布」。自动发布暂不填写话题；直接输入 `#话题` 会打开候选菜单，未选中候选项时可能阻止发布。

内容由 DeepSeek Flash 写成小红书笔记。素材优先取今天的 AI 资讯，来源是量子位和 Hacker News。今天没有新资讯时，用最近 48 小时里还没发过的条目，正文里不会把旧闻说成刚刚发生。同一条资讯发出去之后不会再写一次。

第一条会马上发。发出后按挡位等待：慢 50～70 分钟，中 25～35 分钟，快 12～18 分钟，超快 6～10 分钟。默认是「中」。没有确认发布成功时，1 分钟后用同一条内容重试。标题框里已经有别的内容时，任务停下，不会覆盖。

在推荐页点「开始发笔记」会打开创作服务平台。面板也可以直接在创作服务平台里启动。评论和发笔记不要放在同一个被挡住的后台标签页里。
